# GEO 项目文件治理

> **通用兼容**：适用于 Claude Code、Codex 和兼容 Agent Skills 的工具；建议完整安装同级 `geo-*` 技能，运行诊断请使用 `../geo-runtime/SKILL.md`。

> 本模块是 GEO 项目的"目录规范守护者"。确保所有模块产出的文件都放入标准位置，不再乱建文件夹。
> 对应的内容创作模块见 geo-content-production，审核模块见 geo-content-audit。

---

## 0. 输出归位硬规则

所有 GEO 技能在产出文件时，必须**直接写入标准目录**，不要先写到项目根目录再事后归位。

写文件前优先用共享路径工具解析目标位置：

```bash
node geo-content-archive/scripts/project_paths.js \
  --project-dir "项目_品牌GEO" \
  --artifact article \
  --filename "文章标题.md" \
  --json
```

如果从本技能目录内执行：

```bash
node scripts/project_paths.js --project-dir "项目_品牌GEO" --artifact article --filename "文章标题.md"
```

该脚本会创建标准 8 目录和常用子目录，并返回 `outputPath`。其他技能写文件时应使用这个路径。

## 1. check-structure — 目录结构校验

**用途**：扫描项目目录，对比标准结构，输出合规报告。

**参数**：

| 参数 | 说明 | 必填 | 默认值 |
|------|------|------|--------|
| `--dir` | 项目根目录路径 | 否 | 当前项目目录 |
| `--fix` | 自动修复模式（创建缺失目录、移动散落文件） | 否 | false |

### 标准目录结构（8 目录）

```
项目_{品牌名}GEO/
├── 00_项目概览/              ← 项目入口：概览、仪表盘、品牌定位、汇报
├── 01_项目资料/              ← 客户原始资料（只读参考）
├── 02_知识库/                ← 结构化事实知识库、优势证据库与补充清单
├── 03_规划方案/              ← 关键词方案、标题方案、映射表、跟踪表
├── 04_内容创作/              ← 文章/封面/配图/合规榜单/多平台分发
├── 05_质量审核/              ← 一致性/媒体/AI检测/覆盖度/缺口分析
├── 06_发布记录/              ← 发布任务记录/收录状态
└── 07_监测分析/              ← 收录监测/证据链/PDCA/平台画像/行业洞察
```

### 检查项

1. **标准目录完整性**：8 个标准目录是否全部存在
2. **非预期目录检测**：是否存在标准结构之外的顶层目录
3. **文件归位合规**：文件是否放在正确的标准目录中（依据文件归位规则表）
4. **根目录散落文件**：根目录下是否有不应存在的文件
5. **目录深度校验**：子文件夹深度是否超过 3 级

### 执行步骤

1. 扫描 `--dir` 指定的项目根目录
2. 逐项执行上述 5 个检查
3. 输出合规报告表格：

```
🔍 目录结构校验报告

项目：项目_品牌名GEO/

✅ 标准目录完整性 ............ 8/8 通过
❌ 非预期目录检测 ............ 发现 2 个：05_排名监测/、GEO知识库/
⚠️ 文件归位合规 .............. 3 个文件位置不对
✅ 根目录散落文件 ............ 无散落文件
✅ 目录深度校验 .............. 最大深度 3 级

--- 偏差详情 ---

[非预期目录]
  - 05_排名监测/ → 应迁移到 07_监测分析/收录监测/
  - GEO知识库/   → 应迁移到对应标准目录

[文件归位偏差]
  - 03_规划方案/壁挂炉推荐TOP10.md → 应移至 04_内容创作/
  - 仪表盘.md                  → 应移至 00_项目概览/

汇总：2 个问题需修复，1 个警告
```

4. 如果带 `--fix` 参数，自动修复所有可修复的偏差并输出修复报告

## 2. file-organize — 文件归位

**用途**：将散乱文件移动到标准位置，支持 dry-run 预览。

**参数**：

| 参数 | 说明 | 必填 | 默认值 |
|------|------|------|--------|
| `--dir` | 项目根目录路径 | 否 | 当前项目目录 |
| `--dry-run` | 预览模式，只显示归位方案不执行 | 否 | false |
| `--move` | 移动文件（默认为复制，保留原文件） | 否 | false |

### 文件归位规则表

| 文件类型 | 来源模块 | 标准位置 | 识别方式 |
|---------|---------|---------|---------|
| 品牌定位文档 | geo-brand | `00_项目概览/品牌定位/` | 文件名含"品牌定位" |
| 内容布局跟踪表 | geo-brand, geo-article | `03_规划方案/内容布局跟踪表.md` | 文件名含"跟踪表" |
| 关键词映射表 | geo-content-production | `03_规划方案/关键词映射表.md` | 文件名含"关键词映射" |
| 拓展词方案(MD) | geo-content-production | `03_规划方案/关键词方案/` | 文件名含"拓展词方案" |
| 拓展词方案(HTML) | geo-content-production | `03_规划方案/关键词方案/` | .html 后缀 |
| 意图树(MD) | geo-content-production | `03_规划方案/关键词方案/` | 文件名含"意图树" |
| 意图树(CSV) | geo-content-production | `03_规划方案/关键词方案/` | .csv 后缀 |
| 标题方案(MD) | geo-content-production | `03_规划方案/标题方案/` | 文件名含"标题" |
| 标题方案(其他) | geo-content-production | `03_规划方案/标题方案/` | 文件名含"标题" |
| 原创文章 | geo-brand, geo-content-production | `04_内容创作/{日期批次}/articles/` | .md 文件，非跟踪表/知识库 |
| 核心优势与可信证据库 | geo-knowledge | `02_知识库/证据库/` | `核心优势与可信证据库_*.md` |
| 待补强证据清单 | geo-knowledge | `02_知识库/证据库/` | 不与基础信息补充清单混放 |
| 信息补充清单 | geo-knowledge | `02_知识库/补充清单/` | 基础资料缺口，不是证据强度清单 |
| 覆盖度优化版 | geo-content-audit | `04_内容创作/{日期批次}/optimized/` | 文件名含"优化版" |
| 封面图片 | geo-content-production | `04_内容创作/{日期批次}/covers/` | cover_*.png |
| cover_mapping.json | geo-content-production | `04_内容创作/{日期批次}/covers/` | 文件名匹配 |
| 文中配图 | geo-content-production | `04_内容创作/{日期批次}/images/` | .png/.jpg，非封面 |
| 合规榜单文章 | geo-content-audit | `04_内容创作/合规榜单/` | 文件名含"推荐"/"榜单" |
| 一致性审核报告 | geo-content-audit | `05_质量审核/一致性审核/` | 文件名含"一致性" |
| 媒体投稿审核报告 | geo-content-audit | `05_质量审核/媒体投稿审核/` | 文件名含"媒体"/"投稿" |
| AI识别检测报告 | geo-content-audit | `05_质量审核/AI识别检测/` | 文件名含"AI" |
| 覆盖度报告 | geo-content-audit | `05_质量审核/覆盖度分析/` | 文件名含"覆盖度" |
| 缺口分析报告 | geo-content-audit | `05_质量审核/缺口分析/` | 文件名含"缺口" |
| 内容质量报告 | geo-article | `05_质量审核/内容质量报告/` | 文件名含"质量报告" |
| 发布任务记录 | geo-publish | `06_发布记录/` | 文件名含"发布" |
| 收录监测报告 | geo-indexing | `07_监测分析/收录监测/` | 文件名含"收录"/"监测" |
| 证据链分析报告 | geo-analysis | `07_监测分析/证据链分析/` | 文件名含"证据链" |
| PDCA对比报告 | geo-analysis | `07_监测分析/PDCA对比/` | 文件名含"PDCA"/"对比" |
| 平台画像文档 | geo-analysis | `07_监测分析/平台画像/` | 文件名为平台名 |
| 行业洞察文档 | geo-analysis | `07_监测分析/行业洞察/` | 按行业分类 |
| 项目仪表盘 | geo-analysis | `00_项目概览/仪表盘.md` | 文件名含"仪表盘" |
| 导出截图 | geo-analysis | `07_监测分析/导出截图/` | .png 文件 |

### 执行步骤

1. 扫描项目目录下所有文件
2. 对每个文件，按上表的"识别方式"匹配文件类型
3. 确定目标标准位置（{日期批次} 取文件修改日期或文件名中的日期）
4. 生成归位方案表格：

```
📋 文件归位方案（预览）

文件                          → 目标位置
──────────────────────────────────────────────────────
壁挂炉推荐TOP10.md           → 04_内容创作/2026-05-08/articles/
一致性审核报告_壁挂炉.md      → 05_质量审核/一致性审核/
cover_壁挂炉推荐TOP10.png    → 04_内容创作/2026-05-08/covers/
仪表盘.md                   → 00_项目概览/仪表盘.md

共 4 个文件需要归位
```

5. 如果 `--dry-run`，输出方案后结束
6. 否则等待用户确认，然后执行复制/移动操作
7. 输出归位完成报告

### 特殊处理

- **无法识别的文件**：归入 `00_项目概览/_待分类/` 并在报告中标记
- **文件名冲突**：目标位置已有同名文件时，保留两者（新文件追加编号后缀）
- **软链接**：不处理已有的软链接文件，避免循环

## 3. migrate — 项目迁移

**用途**：将旧版目录结构迁移到新结构，处理已有项目的结构升级。

**参数**：

| 参数 | 说明 | 必填 | 默认值 |
|------|------|------|--------|
| `--dir` | 项目根目录路径 | 否 | 当前项目目录 |
| `--dry-run` | 预览模式，只显示迁移方案不执行 | 否 | false |
| `--force` | 强制模式，覆盖目标位置已有文件 | 否 | false |

### 迁移映射表

| 旧路径 | 新路径 |
|-------|-------|
| `03_GEO方案/` | `03_规划方案/` |
| `04_标题方案/` | `03_规划方案/标题方案/` |
| `05_排名监测/` | `07_监测分析/收录监测/` |
| `05_质量报告/` | `05_质量审核/内容质量报告/` |
| `05_审核报告/` | `05_质量审核/`（按内容类型分配子文件夹） |
| `06_覆盖度报告/` | `05_质量审核/覆盖度分析/` |
| `04_内容创作/优化版本/` | `04_内容创作/{日期}/optimized/` |
| `GEO知识库/platforms/` | `07_监测分析/平台画像/` |
| `GEO知识库/industries/` | `07_监测分析/行业洞察/` |
| 根目录 `仪表盘.md` | `00_项目概览/仪表盘.md` |

### 执行步骤

1. 扫描项目目录，识别旧版结构特征（如 `03_GEO方案/`、`GEO知识库/` 等）
2. 对比迁移映射表，生成迁移方案
3. 如果 `--dry-run`，输出方案后结束
4. 创建新标准目录结构（8 个目录）
5. 按迁移映射表逐项迁移：
   - 复制文件到新位置
   - 迁移完成后在旧目录添加 `_deprecated` 后缀（不直接删除）
6. 输出迁移报告：

```
✅ 项目迁移完成！

📁 项目：项目_品牌名GEO/
📊 迁移统计：
  - 迁移目录：6 个
  - 迁移文件：23 个
  - 跳过（已存在）：2 个
  - 旧目录标记：6 个（已添加 _deprecated 后缀）

⚠️ 后续操作：
  - 检查 _deprecated 目录确认无遗漏后可手动删除
  - 运行 check-structure 验证新结构合规性
```

7. 提示用户运行 `check-structure` 验证迁移结果

## 工作流总览

```
create-kb (建立标准结构)
    │
    ├── 各模块产出 → check-structure (检查是否合规)
    │                   ├── 全部合规 → 正常运营
    │                   └── 发现偏差 → file-organize (纠正归位)
    │
    └── 旧项目迁移 → migrate (一键迁移到新结构)
```

### 使用示例

**校验当前项目结构：**
```
你：检查一下项目目录结构合不合规
```

**归位散乱文件（预览）：**
```
你：帮我整理一下项目里的散乱文件，先看看方案
```

**归位散乱文件（执行）：**
```
你：确认归位，执行吧
```

**迁移旧项目：**
```
你：把这个旧项目迁移到新目录结构
```

## 与其他技能的配合

1. **geo-knowledge > create-kb（创建项目）**：新建项目时自动建立 8 目录标准结构
2. **geo-content-production（内容创作）**：创作产出的文件按归位规则放入标准位置
3. **geo-content-audit（质量审核）**：审核报告按归位规则放入标准位置
4. **geo-analysis（监测分析）**：分析报告按归位规则放入标准位置
5. **geo-publish（发布管理）**：发布记录按归位规则放入标准位置
