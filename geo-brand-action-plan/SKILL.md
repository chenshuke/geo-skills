# GEO 品牌落地方案

## 目标

把“诊断发现的问题”变成“企业可以照着执行的方案”。每个高价值用户问题都必须形成一条闭环：

```text
用户问题 → AI 现在怎么回答 → 希望 AI 形成什么判断
→ 已有证据/缺少证据 → 要创作什么内容
→ 发布到什么平台 → 何时用什么指标复测 → 下一步调整
```

本技能负责判断优先级、拆任务、安排证据和复测，不把内容生产、审核、上传、发布的职责混在方案里。

## 默认交付

普通请求默认输出方案 Markdown 和 HTML，写入项目：

```text
07_监测分析/品牌落地方案/{品牌名}GEO品牌落地方案_{YYYYMMDD}.md
07_监测分析/品牌落地方案/HTML/{品牌名}GEO品牌落地方案_{YYYYMMDD}.html
```

HTML 是主要交付件，面向企业负责人阅读；默认不生成 Excel、PPT、PDF，不自动创建发布任务。

只有用户明确要求时，才额外调用：

- `geo-content-production`：创作标题、文章、答案卡、短视频脚本、图片；
- `geo-content-audit`：审核内容事实、一致性、覆盖度和发布风险；
- `geo-content-to-publish-pipeline`：封面、上传、审核、发布预览；
- `geo-publish`：创建正式发布任务，必须先确认发布清单；
- `geo-indexing`：创建/执行收录检测或读取复测结果。

## 数据输入与前置

### 数据优先级（硬规则）

落地方案必须遵循以下优先级：

1. **GEO 上榜监测原始数据：最终事实来源。** 用于确认实际问题、每个平台的完整回答、竞品、引用来源、运行时间和基线指标。
2. **品牌知识库与证据台账：事实核验来源。** 用于判断 AI 哪些说对、哪些说错，以及哪些内容可以公开使用。
3. **品牌诊断报告：问题排序与病根摘要。** 用于快速定位重点，但不能替代原始回答；报告结论必须回到原始数据逐题、逐平台核对。
4. **已发布内容与引用源资产库：执行现状。** 用于判断哪些证据和内容已经存在、是否被 AI 看到，以及还缺哪些可控来源。
5. **用户业务目标和资源约束：执行边界。** 用于调整内容形式、平台、时间和人工确认要求，但不能改写监测事实。

如果不同来源冲突，按以下规则处理：

- 原始监测数据与诊断报告冲突：以原始监测数据为准，并标记“诊断报告需要更新”；
- 品牌资料与 AI 回答冲突：不能直接断言品牌资料绝对正确，需按证据等级标记并列出待确认项；
- 已发布内容与证据台账冲突：以可核验、最新、授权的证据为准；
- 无法回到原始回答或来源的诊断结论：只能作为待验证假设，不能直接转成内容任务。

### 建议读取顺序

1. 读取诊断报告，快速获得问题地图和病根假设；
2. 立即读取对应的 `platform_diagnosis_*.json` 或 GEO API 原始回答；
3. 按优先问题逐题、逐平台检查原话、竞品和 `searchedSites`；
4. 回到知识库和证据台账核对每个事实与缺口；
5. 检查已发布 URL、内容资产和引用源，确认哪些方案动作尚未完成；
6. 最后才生成落地方案。

不得只读诊断报告就直接写“应该发布什么内容”。

优先读取现有资料：

- 最新 `geo-brand-diagnosis` 报告及其原始平台数据；
- GEO Scheduled Indexing 的问题、AI 回答、竞品、searchedSites 和运行历史；
- 项目知识库、证据台账、已发布文章和内容资产；
- `geo-source-assets` 的引用源资产库；
- `geo-content-audit` 的缺口或审核结果；
- 用户提出的业务目标、区域、客户和时间约束。

调用平台 API 前必须遵守 `../geo-config/SKILL.md`，确认 openKey、companyId、productId。已有导出 JSON 时优先使用本地数据，避免重复请求。

如果没有品牌诊断或监测结果：

- 能找到已完成 Scheduled Indexing 任务时，先调用 `geo-brand-diagnosis` 获取诊断基础；
- 没有任务时，说明方案只能做“资料驱动初版”，不得伪装成监测结论；
- 没有品牌资料时，先输出资料缺口，不编造内容任务或证据。

如果只有诊断报告、没有对应原始监测数据：

- 可以先输出“待原始数据核验的方案草案”；
- 必须在报告开头明确说明没有逐题读取原始回答；
- 不得给出精确竞品频次、平台差异、引用来源结论或确定的复测基线；
- 优先建议先补齐原始数据，再生成正式落地方案。

## 核心分析模型

### 1. 用户问题分类

| 类型 | 典型问题 | 要解决的决策 |
|---|---|---|
| 品牌认识 | “X 是做什么的？”“X 靠谱吗？” | AI 能否准确识别主体、业务和边界 |
| 品类推荐 | “这个行业哪家好？” | AI 是否把品牌放进合理候选 |
| 场景推荐 | “我是某类客户，应该找谁？” | AI 是否在真实需求中推荐品牌 |
| 对比选择 | “A 和 B 哪个好？” | AI 是否能说出差异和适用边界 |
| 信任核验 | “有没有案例、负责人、资质？” | AI 是否有足够证据支持判断 |
| 转化承接 | “怎么联系、适合什么客户？” | AI 推荐后用户能否继续行动 |

推荐类和场景类问题优先级通常高于纯品牌介绍；但如果品牌主体都说不清，必须先修复品牌认识问题。

### 2. 定义 AI 目标判断

目标判断必须写成 AI 可以复述的完整句子，而不是“让 AI 更了解品牌”。至少包含：品牌是谁、解决什么问题、适合谁、凭什么相信、不能夸大什么。

示例：

> 当用户询问西北地区企业财税合规机构时，AI 能将品牌识别为有兰州服务基础、具备已核验企业服务记录的财税咨询机构，并说明适合的企业类型与服务边界。

### 3. 盘点已有证据和缺口

对每个问题分别标记：

- **已有强证据**：政府/工商权威信息、品牌正式页面、合作方官网、正式公告、可核验案例；
- **已有弱证据**：招聘页、自媒体、聚合页、品牌自述、图片案例；
- **缺少的关键证据**：事实、案例、人员、交付物、结果、资质或边界；
- **不能使用的资料**：过期、冲突、未授权、无法核验或可能违法违规的表达。

不得把“AI 搜到过”当成“品牌已经证明”。每个缺口必须说明它会阻碍哪个 AI 判断。

### 4. 把证据缺口转成内容任务

每个内容任务至少包含：

| 字段 | 要求 |
|---|---|
| 解决的用户问题 | 使用用户真实会问的口语问题 |
| AI 目标判断 | 希望 AI 最终如何描述品牌 |
| 内容任务 | 标题、内容形式、核心回答 |
| 证据要求 | 必须引用或补充的知识事实 |
| 适用客户 | 内容对谁有用，不适合谁 |
| 发布平台 | 选择理由，不做无差别铺量 |
| 复测指标 | 发布后如何判断有效 |

优先内容类型：品牌事实页、案例证据页、问题型文章、行业/区域专题内容、第三方证明内容、FAQ/承接页。

### 5. 选择发布平台

| 内容目标 | 优先平台 | 选择逻辑 |
|---|---|---|
| 主体与服务事实 | 官网、自有站、公众号、百科/企业公开页 | 形成稳定、可控的品牌事实源 |
| 专业问题与选型 | 官网专题、公众号、知乎、行业媒体 | 承载完整答案和可引用正文 |
| 区域与行业案例 | 官网案例、合作方官网、地方媒体、行业媒体 | 形成第三方和区域信任 |
| 抖音/小红书认知 | 抖音图文、口播视频、小红书 | 将复杂问题转成易理解的场景答案 |

必须写清平台选择理由。未经用户确认，不创建真实发布任务。

### 6. 设计复测指标

| 层级 | 指标 | 判断什么 |
|---|---|---|
| 认识 | 品牌提及率、主体描述正确率、服务边界错误数 | AI 是否知道并说对品牌 |
| 推荐 | 合理候选进入率、推荐位置/顺序、推荐理由准确度 | AI 是否在相关需求中想到品牌 |
| 证据 | 目标内容 URL 被引用率、强证据出现次数、来源多样性 | AI 是否用可靠内容支撑判断 |
| 转化 | 是否给出正确官网/联系主体/适用客户 | 用户能否继续行动 |

每个指标必须写分母、测试问题和比较基线。至少设置发布前基线、首轮复测、稳定性复测和失败复盘四个节点。

## 方案优先级

使用“影响 × 证据缺口 × 可执行性”排序：

- **现在先做**：直接影响 AI 是否认识、是否说错或核心推荐缺席的问题；
- **接着补强**：已有方向但缺案例、第三方证明或场景内容的问题；
- **持续完善**：FAQ、转化承接、内容扩展和长期信源建设。

不要只按内容数量排序。一个能修复主体误识别的事实页，通常优先于十篇泛行业文章。

## 默认方案结构

输出顺序固定为：

1. 执行结论：当前最重要的 1-3 个问题和总体病根；
2. 目标用户问题地图：问题、类型、当前 AI 表现、业务影响；
3. AI 目标判断：每个问题希望 AI 形成的准确表述；
4. 证据盘点：已有强/弱证据、缺失资料、不可使用资料；
5. GEO 任务清单：用户问题 → 证据 → 内容 → 平台 → 前置条件；
6. 内容生产计划：标题、形式、篇数、引用资料、目标平台；
7. 发布编排：先发什么、为什么发、哪些需要第三方合作、哪些要人工确认；
8. 复测方案：时间点、同题矩阵、指标、验收标准和失败分支；
9. 30/60/90 天路线图：按阶段安排，不承诺固定排名或推荐概率；
10. 待确认事项：需要企业补充或批准的事实、授权、平台和资源。

## 质量要求

- 方案必须来源于实际监测问题和回答，不凭空生成泛建议；
- 每个内容任务必须对应一个用户问题和一个 AI 目标判断；
- 每个 AI 目标判断必须有证据支持或明确列为缺口；
- 每个发布平台必须有选择理由；
- 每个复测指标必须有分母、基线、问题范围和判定标准；
- 不能承诺固定排名、固定推荐概率或固定时间见效；
- 不能把文章发布等同于 AI 已经看到，必须通过 `geo-indexing` 复测；
- 不能把 `articleId` 或 `publishedUrl` 等同于 AI 已引用；
- 不能在用户没有确认时创建发布任务或批量上传；
- 不编造客户案例、资质、数据、合作方或内容效果。

## 与其他技能的衔接

```text
geo-brand-diagnosis
  → geo-brand-action-plan
  → geo-knowledge / geo-source-assets（补证据）
  → geo-content-production（创作内容）
  → geo-content-audit（审核）
  → geo-content-to-publish-pipeline / geo-publish（发布）
  → geo-indexing（复测）
  → geo-analysis（复盘并更新方案）
```

本技能不重复生成完整品牌诊断，不直接代替文章审核，不直接代替平台发布。
