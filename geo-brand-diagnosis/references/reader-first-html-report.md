# 老板阅读版品牌认知诊断报告

## 目录

1. 阅读对象与成功标准
2. 推荐结构
3. 大白话转换规则
4. 竞品分析规则
5. 视觉与 HTML 规则
6. 交付前删减

## 1. 阅读对象与成功标准

默认读者是企业负责人、品牌负责人和业务负责人，不假设其了解 GEO、API 或平台数据结构。

读者看完后必须能够复述：

- AI 现在是否认识我们；
- AI 把我们说成了什么；
- 哪些地方说对、说偏或说错；
- AI 有没有说出真实优势和可信证据；
- 是否存在错误、负面信息或适用边界混乱；
- AI 的认识主要来自哪些公开来源；
- 我们最先要纠正和补充什么。

## 2. 推荐结构

### 封面第一屏

必须生成独立、完整的头部封面，不得只放一条标题栏。封面至少包含：

- 品牌名或简洁文字标识；
- “GEO 品牌认知诊断报告”正式标题；
- 一句话核心诊断；
- 报告类型、测试范围和测试日期；
- 与正文明确区隔的深色或高对比视觉区域。

使用品牌名和报告名称作为标题。紧接着放一句结论，例如：

> AI 已经知道这个品牌，但对核心业务和优势的认识仍不完整，其中一项信息存在明显偏差。

接着展示三个结果：

- 5 个品牌问题中有多少回答基本准确；
- 5 个品牌问题中有多少回答存在重要遗漏；
- 5 个品牌问题中有多少回答存在错误或风险。

品牌问题本身已经包含品牌名，不计算品牌提及率，也不把出现品牌名写成主动推荐。数字下面必须写一句解释。

### 第一部分：AI 眼中的品牌

用三栏或三个短段说明：

- 已经说对的；
- 还说不清的；
- 明显说错或有风险的。

### 第二部分：最重要的问题

选择 3-5 个足以影响客户信任或推荐的问题。每个问题按以下格式写：

```text
问题标题
AI 是怎么说的：一两句短摘录或转述
实际情况：基于现有证据的核对
为什么重要：对客户判断或品牌信任的影响
```

不要展示 answerId、topicId。需要追溯时，将代表来源链接放在“实际情况”或报告末尾。

### 第三部分：真正的病根

这是报告区别于普通复盘的核心章节。必须明确：哪些是表面现象，哪些是共同底层原因。

使用以下结构：

| 现象 | 直接证据 | 病根判断 | 证据等级 | 影响 | 验证方法 |
|---|---|---|---|---|---|

证据等级只使用三种说法：已证实、高度可能、待验证。不要把合理推断写成确定事实。

优先寻找能解释多个现象的共同病根。例如：主体关系混乱、服务能力被扩写、推荐题缺席，可能共同来自“品牌事实、场景证据和第三方证明没有被组织成统一的公开信息”。

### 第四部分：为什么会说偏或说错

按重要性列 3-5 个原因。每个原因都写：

```text
原因 → 本次数据中的表现 → 应补的知识、内容或证据
```

禁止只写“品牌知名度不足”“内容不够多”。

### 第五部分：信息来源与外部参照

按用户场景组织：

| 用户在问什么 | AI 主要参考什么来源 | 其他品牌如何被描述 | 我方真正缺什么 |
|---|---|---|---|

正文只展示与品牌认知错误、优势判断或来源结构直接相关的代表信息。完整来源和竞品名单只有用户要求时才附加。

区分：

- 直接竞品：客户定位、服务范围和区域接近；
- 头部替代：规模和牌照不同，但抢占高价值需求；
- 区域替代：依靠本地化和区域信源进入推荐；
- 非同类干扰：同名企业或不相关品牌，不应作为竞品策略对象。

### 第六部分：最先做的三件事

使用序号 1-3。每件事写清：

- 要解决的诊断问题；
- 具体产物；
- 完成后如何用同题复测。

每项动作必须对应前面的一个病根，并写清复测时要观察的变化，例如“主体关系题不再出现相互矛盾”“区域推荐题开始出现品牌”。

### 报告末尾：测试说明

只保留普通读者需要的信息：测试日期、平台、问题数、回答数、事实核对边界、AI 结果会变化。任务和回答编号只在完整审计版出现。

## 3. 大白话转换规则

| 避免使用 | 改成 |
|---|---|
| 品牌命中 / brand indexed | AI 回答里有没有提到品牌 |
| 识别准确率 | AI 能不能把品牌说清楚 |
| 信息完整率 | AI 有没有把关键业务、客户和场景说完整 |
| 语义标签不稳定 | AI 对品牌的理解前后不一致 |
| 信源结构薄弱 | 能证明品牌能力的公开资料太少或太分散 |
| 外部信息占位 | AI 更容易从其他品牌或第三方内容形成判断 |
| 转化承接 | 用户看完推荐后，能不能方便地了解和咨询 |
| P0/P1/P2 | 现在先做 / 接着补强 / 持续完善 |

专业名词不可避免时，第一次出现后用括号解释。

## 4. 竞品分析规则

统计竞品时合并同一机构的中英文名、简称和集团名。不要把“本品牌”、同名无关企业、人物和泛称计入竞品。

优先展示：

1. 跨平台重复出现的竞品；
2. 在品牌核心场景出现的竞品；
3. 有明确推荐理由或来源支撑的竞品；
4. 与品牌规模、区域或服务类型真正可比较的竞品。

对四大、全国性集团等头部替代，不要简单建议“超过它们”。说明用户为什么会在复杂场景选择它们，以及品牌应该在哪个更具体的场景建立推荐理由。

## 5. 视觉与 HTML 规则

- 使用白色或浅灰页面、深色正文、单一主强调色和一种风险色；不要使用大面积渐变。
- 封面允许使用深色纯色背景，但不得使用大面积渐变；优先使用品牌色、文字标识和克制的几何结构。
- 封面在桌面端应形成约 450-600px 的独立首屏，在手机端允许信息自然换行，不出现文字重叠。
- 正文最大宽度约 1000-1120px，保证长文阅读舒适。
- 标题层级明显，正文不少于 16px，行高约 1.7。
- 卡片圆角不超过 8px；不要把每个段落都做成卡片。
- 表格只放比较信息，列数尽量不超过 4；移动端允许横向滚动，不压缩到不可读。
- 数字应同时带标签和解释，不依赖颜色传达含义。
- 来源链接使用可读标题，不直接堆长 URL。
- 报告末尾再放方法和限制，避免第一屏出现任务参数。
- HTML 使用连续阅读布局，适配 Safari 和手机浏览器。

## 6. 交付前删减

完成初稿后主动删除：

- 重复出现三次以上的同一结论；
- 不影响决策的来源统计和域名排行；
- 所有 API 字段和技术编号；
- 过长的 AI 原文；
- 全部竞品名单和全部来源列表；
- 无法对应诊断问题的泛化建议；
- 为显得专业而增加的术语。

删减后，正文仍必须保留足够证据，让每个重要判断都能被普通读者理解和相信。
