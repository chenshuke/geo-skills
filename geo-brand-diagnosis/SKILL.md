# GEO 品牌 AI 诊断技能

> **通用兼容**：适用于 Claude Code、Codex 和兼容 Agent Skills 的工具；建议完整安装同级 `geo-*` 技能，运行诊断请使用 `../geo-runtime/SKILL.md`。

本技能默认以 GEO 平台现有的 Scheduled Indexing 上榜检测任务为数据源，不再默认要求用户生成问题、逐个平台人工测试或粘贴 AI 回答。

支持四种模式：

1. **平台任务选择模式（默认）**：读取当前 companyId/productId 下的上榜检测计划，展示任务名称、问题数、平台、最近执行时间和完成状态，让用户选择。
2. **平台结果诊断模式（默认主流程）**：用户选择任务后，自动读取该任务的问题、AI 完整回答、AI 平台、竞品、引用来源标题、URL、来源域名和品牌文章命中状态，直接生成诊断。
3. **完整诊断交付模式**：基于选中任务的原始平台数据，交付 Markdown、HTML、完整证据 Excel，并按需生成演示 PPT。所有结论必须能追溯到任务、运行、问题、平台、回答编号和来源 URL。
4. **人工/问题生成兜底模式**：仅当 GEO 平台没有可用任务、用户没有平台权限，或用户明确要求创建新检测问题时，才使用原有 5/10 题、8 题矩阵或旧服务商审计问题池流程。

## 输出归位硬规则

品牌 AI 诊断报告必须直接写入项目标准目录：诊断 Markdown/HTML 优先放 `07_监测分析/品牌诊断报告/`、`07_监测分析/证据链分析/` 或 `05_质量审核/缺口分析/`；原始 JSON 放 `原始数据/`，证据 Excel 放 `附件/`，演示稿放 `PPT/`。写文件前可用 `geo-content-archive/scripts/project_paths.js --artifact evidence-report` 或 `--artifact audit-gap` 获取路径。

## 默认输入与配置

调用平台前必须遵守 `../geo-config/SKILL.md`：从用户级配置读取 openKey、companyId、productId；如果 defaults 为 0，先列出公司和产品让用户选择并写回配置。

默认不要求用户提供问题或 AI 回答。用户只需提出“做品牌诊断”，Agent 应主动查询平台任务列表。

### 平台任务列表

```bash
node geo-brand-diagnosis/scripts/platform_diagnosis_data.js \
  --action list \
  --limit 30 \
  --json-out 任务列表.json
```

向用户展示：`schedule_id`、任务名称、问题数、平台、最近运行时间、完成数量、是否可诊断。不要展示 openKey 或 Base URL。一次展示建议不超过 10-20 条，优先最近且已完成的任务。

用户选择 `schedule_id` 后自动导出：

```bash
node geo-brand-diagnosis/scripts/platform_diagnosis_data.js \
  --action export \
  --schedule-id 203 \
  --json-out 原始数据/platform_diagnosis_203.json
```

可用 `--run-id` 指定某次执行；未指定时选择最近一条已完成运行。

标准化数据包含：

```text
任务：schedule_id、name、company_id、product_id、selected_run_id
问题：topic_id、question
回答：answer_id、run_id、question、ai_platform、ai_answer、brand_indexed、competitors、screenshot_url
来源：source_id、answer_id、title、url、source_domain、article_indexed
```

`answers[].sources` 与顶层 `sources[]` 均保留来源标题和 URL，报告、Excel 和 PPT 必须通过 `answer_id` 关联。

## 核心原则

- 只基于用户提供的品牌资料和 AI 问答记录分析。
- 不编造品牌事实、案例、数据、资质、合作客户或引用来源。
- 信息不足时明确写「资料不足，需要补充」。
- 诊断必须转成可执行动作，不能只做泛泛点评。
- 重点识别：AI 不知道、AI 说错、AI 不推荐、AI 推荐竞品、缺少信任证据、缺少转化承接。
- “回答中出现品牌”不等于“准确识别品牌”；“知道品牌”也不等于“会主动推荐品牌”。三者必须分别统计。
- 不允许只写“存在问题”。每个重要结论必须附原始回答摘录、回答编号、核对依据和引用来源。
- 多平台诊断必须使用同一组问题，保留平台、模型/版本、执行时间和原始记录，避免把单次回答当成稳定结论。
- 正式对外交付时，先展示诊断问题和方法，再展示结论；不得暴露内部销售策略、合作分工、渠道计划或未经确认的时间承诺。

## 标准工作流

### 0. 先判断输入状态

- 默认先执行配置检查和平台任务列表，不要先要求用户提供问题或 AI 回答。
- 如果平台有已完成任务：展示任务列表并让用户选择，选择后进入**平台结果诊断模式**。
- 如果任务存在但尚未完成：展示完成进度，让用户选择其他已完成任务或等待；未经用户确认不要触发 `run-now`。
- 如果用户已给 `schedule_id`：直接导出该任务最近已完成运行的数据；如有多次运行且用户关心趋势，再展示 run 列表供选择。
- 如果平台没有可用任务或用户无权限：说明原因，再进入人工/问题生成兜底模式。
- 如果用户提到换服务商、旧服务商、旧关键词、审核诊断：仍优先查询平台是否已有对应任务；没有才生成审计问题池。
- 如果用户明确提供本地 AI 平台问答记录：可进入本地诊断报告模式。
- 如果用户提到正式交付、诊断方案、证据附件、原始回答、引用来源、Excel、HTML、PDF 或 PPT：进入**完整诊断交付模式**，并读取 `references/full-delivery-playbook.md`。
- 只有进入兜底问题生成时，才应用 5/10 题、15+ 题或 8 题矩阵规则。

### 0A. 平台任务选择模式

1. 执行 `platform_diagnosis_data.js --action list`。
2. 只展示与当前默认 productId 匹配的任务；要诊断其他品牌时先用 `geo-config` 切换默认产品。只有内部排查时才使用 `--all-products`，并在选择后核对 productId，避免跨品牌误诊。
3. 优先展示 `ready_for_diagnosis: true` 的任务。
4. 用户选择前不自动导出所有任务的回答，避免无关数据和输出过载。
5. 用户选定任务后执行 `--action export`，把标准化 JSON 写入项目 `07_监测分析/品牌诊断报告/原始数据/`。

### 0B. 平台结果诊断模式

对导出的每条回答至少保留并分析：

- 任务 ID、运行 ID、回答 ID；
- 问题全文与 topicId；
- AI 平台与完整回答；
- 是否命中品牌、目标品牌词、竞品列表、排名/位置字段；
- `searchedSites` 的来源标题、URL、域名和 `articleIndexed`；
- 截图 URL（平台有返回时）。

诊断时区分：

- `brand_indexed=true`：平台判定回答命中目标品牌，不等于事实准确；
- `searchedSites`：AI 检索或引用过的来源，不等于来源支持回答中的全部主张；
- 没有品牌知识库：可以判断提及、推荐、竞品和信源结构，但不能强行判定回答事实准确；
- 有品牌知识库：才能逐条核对事实错误、遗漏、过时信息和不当推断。

### 1. 读取详细提示词模板

读取：`references/diagnosis-prompts.md`。

### 1A. 诊断问题生成模式（仅兜底）

基于品牌知识库生成问题清单，必须覆盖四类问题，并遵守「是否带品牌名」规则：

| 类型 | 用来测试什么 | 是否必须带品牌名 | 问题风格 |
|---|---|---|---|
| 品牌词 | AI 是否认识你、是否能清晰介绍你 | 必须带品牌名 | 像用户直接问“这个品牌是干嘛的/靠谱吗” |
| 品类词 | AI 在行业推荐中会不会提到你或同行 | 默认不带品牌名 | 像用户问“这个行业/品类推荐哪几家” |
| 场景词 | AI 在客户真实需求下会不会推荐你或同行 | 默认不带品牌名 | 像用户带身份、场景、痛点问“怎么选/找谁” |
| 对比词 | AI 如何比较你和竞品 | 必须带品牌名；有竞品时同时带竞品名 | 像用户问“A 和 B 怎么选/有什么区别” |

问题必须简单、口语、真实，避免课程化、营销化、过长、过度专业。

输出字段：

```text
序号｜问题类型｜建议提问问题｜这个问题测试什么｜我需要重点观察什么｜建议测试平台｜记录方式
```

比例建议：

- 5 个问题：1 个品牌词 + 1 个品类词 + 2 个场景词 + 1 个对比词。
- 10 个问题：2 个品牌词 + 3 个品类词 + 3 个场景词 + 2 个对比词。

问题生成后，同时输出「AI 平台问答记录模板」，方便用户测试后回填。

### 1A-2. 服务商切换 / 旧 GEO 服务复盘问题池生成模式（仅兜底）

当用户提到「换服务商」「旧服务商做过关键词」「先做审核/诊断」「生成诊断问题池」「全平台测评」「导入 GEO 平台检测」时，使用本模式。它不是普通 5/10 题课堂版，而是用于售前/交付前审计的**完整问题池**。

#### 输入优先级

1. 项目主知识库 / 客户资料：品牌事实、产品、竞品、红线。
2. 旧服务商资料：旧关键词方案、排名词、品牌优化词、平台监测报表。
3. 用户说明的诊断目标：通常包括
   - AI 是否真实描述企业实际情况；
   - AI 对品牌与竞品的对比是否准确、是否有优化空间；
   - 不带品牌名的相关问题中 AI 是否主动推荐该品牌。

#### 输出归位

优先写入项目：`07_监测分析/AI实测问题池_{品牌}_{YYYYMMDD}.md`。  
如果用户明确要导入 GEO 平台，再额外生成：`07_监测分析/GEO平台导入_{品牌}全平台问题_{YYYYMMDD}.txt`。

#### 标准问题池结构

必须输出 3 组核心问题 + 可选加测问题：

| 组别 | 目标 | 建议数量 | 问题规则 |
|------|------|----------|----------|
| A 真实描述诊断 | 测 AI 是否真实了解品牌、业务线、产品、事实参数 | 5 | 必须带品牌名；包含品牌、产品、资质/基地、人物/红线 |
| B 对比诊断 | 测 AI 如何比较品牌与竞品，有无竞品压制和事实错误 | 5 | 必须带品牌名和竞品/替代品；覆盖直接竞品、头部竞品、环保/价格/场景对比 |
| C 推荐诊断 | 测不带品牌名的品类词/场景词是否主动推荐品牌 | 5 | 默认不带品牌名；覆盖获客入口、榜单词、场景词、痛点词 |
| D 加测问题 | 补充转化、价格、区域、渠道、防伪、B 端等 | 5-10 | 根据客户业务选择 |

#### 旧关键词复盘

如果资料里有旧服务商做过的关键词，先整理为两类：

```text
品牌获客/排名词：用于判断不带品牌名时 AI 是否推荐该品牌。
品牌优化/品牌词：用于判断 AI 是否正确描述品牌、产品和舆情。
```

把旧词映射到新问题池，指出哪些词只测排名、哪些词能暴露事实错误、哪些词缺少对比/转化诊断。

#### 每题输出字段

```text
序号｜分组｜问题类型｜建议提问问题｜诊断目的｜重点观察｜可能暴露的问题｜建议平台｜记录方式
```

#### 必须附带记录模板

输出平台记录表，字段至少包括：

```text
平台｜问题编号｜是否提到我方｜出现位置/排名｜推荐理由｜推荐竞品｜事实错误｜是否给转化路径｜初步评级
```

#### 评分规则

使用 A/B/C/D/E：

- A：准确提到品牌，核心事实正确，有清晰推荐理由，能区分适用场景。
- B：提到品牌，主线正确，但信息不完整或缺转化路径。
- C：提到品牌，但事实错误较多、定位偏差或推荐理由弱。
- D：不提品牌，或被竞品明显压制。
- E：编造严重错误，可能损害品牌信任。

#### GEO 平台导入格式

只有用户明确要求导入时才生成导入文件或调用 API。导入格式：

```text
问题[品牌名|英文名|公司全称]
```

平台默认使用全平台；如果用户排除某些平台，必须按用户指定排除。写入平台前先预览问题数、平台数、预计任务数，并等待确认；用户确认后再导入并回查。


### 1B. 诊断报告生成模式

优先读取 `platform_diagnosis_{schedule_id}.json`。报告中必须先写清：任务名称、scheduleId、runId、平台、问题数、回答数、来源记录数和数据时间。

每个关键结论至少关联一个 `answer_id`；涉及信源时同时列出来源标题与 URL。平台没有返回的字段写“平台未返回”，不得补造。

### 1C. 完整诊断交付模式

完整读取 `references/full-delivery-playbook.md`，按其中的证据模型、报告结构、Excel 字段、对外措辞和验收清单执行。

最低交付物：

```text
{品牌名}GEO品牌AI诊断报告_内容稿.md
HTML/{品牌名}GEO品牌AI诊断报告.html
附件/{品牌名}品牌AI诊断完整证据表.xlsx
原始数据/answers_{批次}.json
原始数据/citations_{批次}.json
```

用户要求演示稿时再增加：

```text
PPT/{品牌名}GEO品牌AI诊断报告_演示版.pptx
```

Excel 与 PPT 应调用对应的表格、演示文稿技能。PPT 只允许使用 JavaScript 版 `@oai/artifact-tool`，禁止使用 `python-pptx`，包括生成、编辑、合并和检查。

### 2. 生成 Markdown 报告

按模板输出完整 Markdown，建议保存为：

```text
品牌AI诊断报告.md
```

报告必须包含：

1. 执行摘要
2. 品牌 AI 诊断结论
3. 诊断评分雷达表
4. 主要问题清单
5. 竞品与风险分析
6. 知识库补充建议
7. GEO 内容机会
8. GEO 优化问题清单
9. P0/P1/P2 下一步行动
10. 资料不足与待确认事项

### 3. 生成 HTML

优先使用脚本：

相对于 `geo-brand-diagnosis` 技能目录：

```bash
node scripts/render_geo_brand_diagnosis.js \
  --input 品牌AI诊断报告.md \
  --output-dir 输出目录 \
  --title "品牌 AI 诊断报告"
```

相对于 GEO Skills Suite 根目录：

```bash
node geo-brand-diagnosis/scripts/render_geo_brand_diagnosis.js \
  --input 品牌AI诊断报告.md \
  --output-dir 输出目录 \
  --title "品牌 AI 诊断报告"
```

Node 脚本无 Python 依赖，默认只生成：

```text
品牌AI诊断报告.html
```

不再默认生成 PNG，避免学员电脑安装 Playwright/Chromium。需要图片版时，用浏览器/系统截图，或根据 `references/image-prompt.md` 调用 AI 图片生成技能。不再提供本地自动 HTML 转 PNG 脚本，避免额外环境配置。

### 4. 可选 AI 图片版

如果当前环境有 `imagegen` / `bihuo-ppt-imagegen` / 其他 AI 图片生成技能，额外生成一张「GEO 品牌诊断信息图/封面图」。

交付前检查：

- [ ] 是否明确写出 AI 当前如何看待品牌

- [ ] 是否区分了事实、推断、资料不足
