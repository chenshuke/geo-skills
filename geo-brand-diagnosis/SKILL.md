# GEO 品牌认知与产品推荐诊断

## 目标

使用同一个技能入口完成两种不同诊断，共用平台取数和证据核对能力，但不得混用指标、判断标准和报告结构。

### 模式 A：品牌认知诊断

回答：AI 是否认识品牌、说得是否准确、是否说出真实优势、是否存在错误或负面信息，以及应补什么知识和公开证据。

典型问题包含目标品牌名，例如：`必火AI是什么公司，主要做什么？`

### 模式 B：产品推荐诊断

回答：用户没有点名品牌时，AI 是否会想到、提到并推荐目标产品/品牌，推荐理由是否成立，竞品为何占位，以及应优化哪个问题、证据、内容和信源。

典型问题不包含目标品牌名，例如：`短视频创作推荐什么数字人平台？`

### 模式 C：混合诊断

任务同时包含两类问题时，先逐题分类，再分别统计和分析，最后汇总共同病根。不得用一个综合分数掩盖两类结果。

## 第一步：确定诊断模式

按以下优先级判断：

1. 用户明确说“品牌诊断/品牌认知诊断”时使用模式 A。
2. 用户明确说“产品推荐诊断/获客诊断/推荐率分析”时使用模式 B。
3. 用户未指定时，根据实际问题判断：包含品牌名的身份、业务、优势、证据、口碑、边界问题归入 A；不含品牌名的推荐、哪家好、怎么选、适合什么、性价比问题归入 B。
4. 同一任务两类问题都存在时使用模式 C。
5. 无法可靠分类时，展示任务名称和代表问题，让用户选择“品牌认知”或“产品推荐”；不要让用户查找或输入计划 ID。

## 交付模式

### 老板阅读版（默认）

默认只交付一个 HTML：

```text
品牌认知：07_监测分析/品牌诊断报告/HTML/{品牌名}GEO品牌AI诊断报告.html
产品推荐：07_监测分析/产品推荐诊断报告/HTML/{品牌名}GEO产品推荐诊断报告.html
混合诊断：07_监测分析/GEO综合诊断报告/HTML/{品牌名}GEO综合诊断报告.html
```

Markdown 和原始 JSON 可作为内部中间文件保留，不主动展示任务 ID、接口字段、完整回答和全部来源。

### 完整审计版（按需）

仅当用户明确要求原始回答、全部来源、Excel、PDF、PPT、技术编号或正式审计材料时，完整读取 `references/full-delivery-playbook.md`。

## 平台取数

优先读取已有 Scheduled Indexing 任务，不要求用户重新生成问题或粘贴回答。

调用 API 前遵守 `../geo-config/SKILL.md`。未配置 openKey、companyId 或 productId 时，先完成配置和选择。

列出最近任务：

```bash
node geo-brand-diagnosis/scripts/platform_diagnosis_data.js --action list --limit 30
```

任务选择流程固定为：

```text
技能读取最近任务
→ 展示任务名称、问题数、平台、时间和完成状态
→ 用户选择任务
→ 技能内部使用计划 ID
```

不得要求普通用户自己查找或输入计划 ID。只有一个明显匹配且已完成的任务时可以直接使用；有多个任务时必须让用户选择。未经确认不要创建新任务或触发 `run-now`。

导出任务：

```bash
node geo-brand-diagnosis/scripts/platform_diagnosis_data.js \
  --action export \
  --schedule-id <内部选中的任务ID> \
  --diagnosis-mode <brand|product|auto> \
  --json-out <报告目录>/原始数据/platform_diagnosis_<任务ID>.json
```

产品诊断需要分析同一问题的多次历史运行时，增加 `--all-runs`。只有单次课堂诊断时不要读取全部历史运行，以免混淆分母。

平台没有可用任务或用户明确要求新建测试问题时，读取 `references/diagnosis-prompts.md`。

## 共同证据规则

1. 原始 AI 回答是“AI 实际说了什么”的事实来源。
2. 品牌知识库和证据台账是“AI 说得对不对、推荐理由是否成立”的核对基准。
3. `searchedSites` 是 AI 检索或引用过的网页，不等于网页支持回答中的全部主张。
4. `brand_indexed=true` 只说明回答检测到目标词，不能直接等同于准确、推荐或引用我方内容。
5. 竞品、推荐态度和推荐强度必须阅读回答语义判断，不能只看目标词命中。
6. 数据缺失时写清限制，不把未取得回答算作未提及、未推荐或失败。

## 模式 A：品牌认知诊断规则

品牌问题已经包含品牌名，因此不要计算“品牌提及率”，也不要把回答出现品牌名写成主动推荐。

逐题判断五个层面：

| 层面 | 核心判断 |
|---|---|
| 身份准确 | 公司主体、品牌关系、核心业务是否说对 |
| 信息完整 | 产品服务、目标客户、使用场景是否说清 |
| 优势与证据 | 是否说出知识库中真实且有证据的优势 |
| 边界与风险 | 是否虚构、夸大、混淆、过时或出现负面信息 |
| 来源结构 | AI 从哪里形成这些认识，哪些来源需要补充或点对点覆盖 |

有知识库时逐点比对；没有知识库时只能判断回答一致性、来源和明显风险，并列出待补资料，不能强行判定事实准确。

品牌诊断至少输出：

- 5 个问题分别说对、遗漏、说错了什么；
- 最影响品牌信任的错误或负面信息；
- 现有知识库缺失和证据缺失；
- 当前信息来自哪些来源，哪些来源可控；
- 需要补充什么内容、发布到哪类平台、如何同题复测。

生成老板阅读版前完整读取 `references/reader-first-html-report.md`。

## 模式 B：产品推荐诊断规则

产品推荐问题默认不包含目标品牌名。逐条回答必须区分以下状态：

| 状态 | 判断标准 |
|---|---|
| 未出现 | 回答正文没有目标品牌，来源页出现也不算正文提及 |
| 仅被引用 | 正文未提品牌，但 searchedSites 命中我方已知内容 |
| 被提到 | 正文出现品牌，但没有进入解决方案或候选名单 |
| 进入候选 | 品牌属于可供选择的合理候选，但没有明确推荐态度 |
| 明确推荐 | AI 明确建议、推荐或将品牌列为适合该需求的选择 |
| 优先推荐 | 位于首选、重点推荐或高强度正向建议位置 |
| 负面或不适合 | AI 明确劝退、否定或判断不适合该场景 |

核心指标必须分别统计，分母写清：

```text
品牌提及率 = 正文出现目标品牌的有效回答数 / 有效回答总数
候选进入率 = 进入候选及以上的有效回答数 / 有效回答总数
明确推荐率 = 明确推荐或优先推荐的有效回答数 / 有效回答总数
优先推荐率 = 优先推荐的有效回答数 / 有效回答总数
我方引用率 = searchedSites 命中我方已确认内容 URL 的有效回答数 / 有来源的有效回答总数
```

我方引用率必须基于已发布内容 URL、官网域名或引用源资产库核对，不能仅因来源标题含品牌名就认定为我方内容。

除比例外，逐题记录：推荐场景、目标品牌位置、推荐理由、态度与强度、理由是否有证据、引用来源、竞品、竞品理由和下一步动作。

多次运行时：

- 同一个问题的多次回答分别统计，观察推荐稳定性；
- 不得把 5 个不同问题各问 1 次冒充同一问题连续测试；
- 只有一次回答时只能描述当前状态，不能下“稳定推荐/稳定不推荐”结论；
- 比较优化前后时必须保持同问题、同平台和相近测试条件。

生成老板阅读版前完整读取 `references/product-recommendation-html-report.md`。

## 找病根与给行动

两种模式都按以下链路分析：

```text
现象 → 原始回答与来源证据 → 病根 → 影响 → 优先动作 → 同题复测
```

产品推荐未上榜时重点排查：

- 问题与目标产品真实能力不匹配；
- 知识库没有对应场景、优势、案例或边界；
- 推荐理由缺少可核验证据；
- 内容没有直接回答该推荐问题；
- 内容已经存在，但没有进入 AI 常用或可能引用的信源；
- 竞品在该问题下拥有更完整的内容和第三方证明；
- AI 能检索到品牌，却没有足够理由把品牌放进候选名单。

每个主要病根标注“已证实 / 高度可能 / 待验证”。行动建议必须能对应一个病根，并写清复测问题和观察指标。

## 生成 HTML

先生成符合对应模式结构的 Markdown，再使用 Node.js：

```bash
node geo-brand-diagnosis/scripts/render_geo_brand_diagnosis.js \
  --input <报告.md> \
  --output-dir <对应HTML目录> \
  --title "<报告标题>"
```

Markdown frontmatter 应写明：`品牌`、`报告类型`、`诊断模式`、`测试范围`、`测试日期`。渲染器会根据诊断模式生成品牌认知或产品推荐封面。

## 默认验收

- [ ] 已明确使用品牌认知、产品推荐或混合诊断模式；
- [ ] 品牌问题没有错误计算品牌提及率；
- [ ] 产品问题区分提及、候选、明确推荐和优先推荐；
- [ ] 我方引用率基于已确认 URL 或域名，不按标题猜测；
- [ ] 单次测试没有被写成稳定结论，多次运行没有混淆分母；
- [ ] 每个关键判断能回到问题、AI 原回答和代表来源；
- [ ] 推荐理由和品牌优势已用知识库或证据台账核对；
- [ ] 竞品按问题和场景组织，不只是名字堆砌；
- [ ] 行动建议对应病根，并包含同题复测方法；
- [ ] HTML 第一屏 10 秒内能看懂当前最大问题；
- [ ] 默认没有生成 Excel、PPT、PDF 或冗余附件；
- [ ] 全流程不要求学员安装或运行 Python。
