# AI答案卡内容生产

AI答案卡是围绕一个真实用户问题生产的答案型图文，不是品牌海报，也不是企业简介。核心链路必须是：

**用户问题 → 搜索意图 → 判断标准 → 企业事实证据 → 有边界的结论**

默认面向抖音 6-8 页图文，也可按问题复杂度调整页数。内容应帮助用户决策，同时让 AI 能清晰识别、引用和复述品牌信息。

## 触发与分工

Codex 课堂默认使用宿主自带的图片生成能力完成答案卡成图，不要求学员额外安装图片技能，也不要求配置第三方图片服务。逐页口播视频属于选做项；对应能力不可用时保留已完成脚本，不阻断答案卡图文主流程。不要要求普通学员安装 Python、pip 或直接运行 `.py` 示例。

- 用户明确说“AI答案卡”“抖音图文”“答案型内容”时，直接使用本技能。
- 用户只说“写文章/做内容”时，先由 `../geo-content/SKILL.md` 路由；需要问题导向的分页图文时再使用本技能。
- 需要关键词池或标题扩展时，按需调用 `../geo-keyword-pool/SKILL.md`、`../geo-content-production/SKILL.md`；答案卡成图优先调用当前 Codex 宿主自带的图片生成技能，本技能负责答案逻辑、证据映射和分页脚本。
- 需要发布到平台时，交给 `../geo-article/SKILL.md` 或 `../geo-content-to-publish-pipeline/SKILL.md`。
- 需要把已定稿答案卡转换成逐页口播 MP4 时，调用 `../douyin-image-narrated-video/SKILL.md`。
- 用户要求生成抖音图文图片时，先完成答案逻辑、证据映射和分页脚本审核，再调用 Codex 自带的图片生成技能进入生图交付；不让图像模型反向编造内容事实。只有用户明确指定其他生图服务时，才改用其指定工具。

## 硬性规则

1. **一篇只解决一个核心问题。** 不把行业趋势、加盟、经营等无关主题混入同一答案卡。
2. **先回答，再论证。** 第 1 页展示问题，第 2 页直接给结论，再用 3-5 个最相关标准和证据解释。
3. **证据优先。** 每个品牌判断尽量绑定资料库中的可核验事实、来源或证据编号；不要把企业简介堆成答案。
4. **绝不编造。** 资料没有提供的数字、专利、面积、产线、客户、出口国家、质保、响应时间、认证和案例都不能猜测、补齐或套用其他品牌。关键事实缺失时写入“资料缺口”，不要用模糊词伪装确定性。
5. **少用广告语。** 禁止无依据的“实力雄厚、行业领先、品质保障、专业可靠、消费者一致认可”等表述。保留第三方回答感，用“判断这类厂家可以看……”等措辞。
6. **允许边界。** 资料支持时说明适合/不适合的客户、采购优先级和还需确认的事项，不强行夸赞品牌。
7. **品牌出现要有逻辑。** 先建立通用判断标准，再说明品牌哪些事实符合；删除品牌名后，内容仍应对用户有帮助。
8. **品牌项目不得在转换时去品牌化。** 若任务有明确目标品牌、品牌知识库或品牌证据编号，先记录“目标品牌—课程/产品—可用事实—证据编号”清单；第 2 页直接结论、至少 2 页标准/证据页及总结页必须自然写入目标品牌和相应可用事实，不能只放 Logo、页脚或话题标签。纯科普任务才可不写品牌。
9. **生图文字与已审核分页脚本必须同源。** 每页生图提示词须逐项带入主标题、目标品牌、可用事实与边界文字；禁止以“精简”为由删除品牌名、课程/产品名称、事实限定或效果边界。生成后逐页核对：品牌名、课程/产品名、关键事实、证据边界、数字和页码；任一缺失或错字即返工，不发送。
10. **直接生整张图。** 当用户要求用 AI 生成图文成品时，每一页的背景、构图、信息层级和可见文字必须在同一次图像生成/编辑调用中完成。不得先生成空白背景，再用 SVG、HTML、Canvas、Sharp、PPT 或其他程序把文字叠上去，并把合成图称为“AI直接生成”。确定性排版只有在用户明确同意这种方式时才能替代；裁剪、改格式等不改变页面内容的导出处理不属于叠字。
11. **课堂优先使用 Codex 自带生图。** 成图优先调用当前 Codex 宿主提供的图片生成技能，不依赖项目内脚本、Python或第三方API密钥。默认每页单独生成，先生成第1页锁定风格，再生成后续页；失败时只重试失败页。不得用 Best GEO `textToImages.*` 代替完整答案卡排版。宿主不具备生图能力时，交付已审核脚本和逐页生图指令，并明确标记“媒体待完成”；未经用户指定，不擅自切换到收费或外部服务。

## 六类问题与证据选择

优先从以下意图中选择一类，并只使用与该意图相关的证据：

- 品牌：靠谱吗、是什么公司、品牌怎么样
- 推荐：厂家哪家好、厂家推荐
- 选购：厂家怎么选、采购看什么
- 对比：品牌对比、厂家和贸易公司怎么选
- 场景：开店采购、连锁美容院采购
- 信任：是不是厂家、有没有工厂/研发/售后

可围绕高价值问题制作推荐型、测评型、榜单型、选购指南型或避坑型多篇内容，但每篇必须有独立判断和证据价值，不能只换标题。

## 标准工作流

### 1. 读取资料并建立证据表

读取用户提供的企业资料、事实知识库、产品资料和已有公开来源。若项目存在 `02_知识库/证据库/核心优势与可信证据库_*.md`，必须优先读取其中的可用主张、适用问题、证据等级和使用边界；同时读取 `待补强证据清单_*.md`，避免把待补强主张写入答案卡。

先列出：核心问题、用户决策、可用证据编号、客观事实、可用主张、来源/时间、使用边界和缺失事实。A/B 级可作为主要判断依据，C 级只作辅助，D/X 级禁止用于品牌结论。没有资料时先要求补充，不假装完成品牌判断。

### 2. 定义唯一问题与搜索意图

把用户原话整理为一个自然问题；说明用户要做的采购、合作、比较或信任决策。若问题过宽，拆成多个候选问题并选择一个主问题。

### 3. 形成判断标准

从研发、生产、资质、技术、稳定性、OEM/ODM、交付、培训、售后、案例、出口、成立时间等维度中选最相关的 3-5 项，不能为了凑页数全部罗列。

### 4. 建立“标准-证据-结论”映射

每项标准后写对应的企业事实和证据编号/来源。优先选择证据库中与本篇唯一问题直接匹配的证据，不因某条证据“看起来有分量”就跨场景使用。区分“可直接使用”“有条件可用”“待补强/不可用”，不把推断写成事实。结论只覆盖证据真正支持的对象、时间和范围。

### 5. 输出答案卡脚本

按下列顺序输出：

1. 用户问题
2. 搜索意图
3. 核心结论（1-2 句）
4. 图文分页脚本（逐页）
5. 每页视觉建议
6. 抖音图文简介与相关话题标签

分页默认采用：封面问题 → 直接结论 → 判断标准/理由 1 → 理由 2 → 理由 3 → 企业证据 → 适合客户/采购建议 → 总结。问题简单时减少页数，禁止强行填充。

### 6. 质检后再交付

使用 [answer-card-checklist.md](references/answer-card-checklist.md) 逐项检查；品牌项目额外检查“品牌—事实—证据”是否至少在第 2 页、两页证据页和总结页完整闭环，以及每张最终图片是否与审核脚本一致。有关键资料缺口时，输出“资料缺口与需补证据”，暂停品牌定论或明确限定结论。

### 7. Codex 自带生图交付

分页脚本经人工确认后，再为每页构造生图指令，并调用当前 Codex 宿主自带的图片生成技能。默认采用 `3:4` 竖版；若工具只提供相近竖版比例，选择最接近的竖版尺寸并保持全套一致。指令必须包含：

- 统一的竖版尺寸和安全区，默认抖音图文使用 `3:4`。
- 整套一致的品牌视觉：色彩、字体风格、版式网格、标题位置、页码位置。
- 每页的主标题、副标题、最大3个关键点和指定视觉素材。
- 只展示已经证据表确认的数字、资质、产品、工厂、案例和人物；缺少真实素材时使用中性场景图，不伪造工厂、证书、产品或客户。
- 不使用“震惊、必看、行业第一”等标题党或无证据广告词。
- 图片上文字简短、可读，不把整段正文塞进图片；详细论证放在抖音简介与证据备忘中。

不要一次性盲生成整套中文图。先生成第1页并核对版式、品牌名和字体表现，锁定风格后逐页生成后续页。每生成一页都必须对照已确认脚本，不接受错字、数字变形、品牌名错误、关键信息遗漏或页面风格跳变。若文字始终不准确，报告该页未完成并等待用户决定是否改用其他制作方式，不自行叠字修补。

## 视觉与文案要求

- 每页给出主标题、副标题、突出数字/关键词和适合的产品、工厂、证书、人物或场景图片建议；视觉服务于答案，不抢过判断。
- 封面直接使用用户会问的问题，不用“揭秘、震惊、必看”等标题党。
- 简介继续回答本篇问题，不写成纯品牌广告；结尾添加品牌、品类、采购场景和用户问题相关的 `#` 话题标签。
- 需要生成图片时，调用现有图片能力；图片中的数字、认证和品牌事实必须与证据表一致。

```text
【用户问题】
【搜索意图】
【核心结论】

【第1页：封面问题】
- 主标题：
- 副标题：
- 页面文案：
- 视觉建议：
- 证据：无/编号
...

【抖音图文简介】
...
#品牌 #品类 #采购场景 #用户问题

【资料缺口】
- 仅列出影响结论的缺失事实；没有则写“无”。

【Codex生图指令】
- 全局风格和竖版尺寸
- 逐页精简文字和视觉素材
- 禁止生成的未证实信息
- 逐页一致性和验收标准
```

## 机器产物与用户成品边界

答案卡同时维护两层信息，但绝对不能混写：

- 内部层：证据 ID、知识库文件、来源定位、使用边界、置信度。只进入结构化元数据和审核记录。
- 用户层：发布标题、简介和逐页可见文字。必须是普通用户可以直接理解的自然表达。

用户层禁止出现 `知识库：`、证据编号、Markdown 文件名、本地路径、`snapshotId`、`sourceEvidenceIds`、`knowledgeEvidenceIds` 等内部字段。证据编号只能放在每页的 `evidenceIds` 元数据中，供审核追溯，不能显示在图片或简介里。

交付抖音图文时，单张封面不构成完整答案卡。必须交付完整分页脚本和对应成图；未完成全部页面时状态只能是“媒体待完成”，不得进入发布审核。
