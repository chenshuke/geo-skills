# AI答案卡内容生产

AI答案卡是围绕一个真实用户问题生产的答案型图文，不是品牌海报，也不是企业简介。核心链路必须是：

**用户问题 → 搜索意图 → 判断标准 → 企业事实证据 → 有边界的结论**

默认面向抖音 6-8 页图文，也可按问题复杂度调整页数。内容应帮助用户决策，同时让 AI 能清晰识别、引用和复述品牌信息。

## 触发与分工

- 用户明确说“AI答案卡”“抖音图文”“答案型内容”时，直接使用本技能。
- 用户只说“写文章/做内容”时，先由 `../geo-content/SKILL.md` 路由；需要问题导向的分页图文时再使用本技能。
- 需要关键词池、标题扩展、封面或图片生成时，按需调用 `../geo-keyword-pool/SKILL.md`、`../geo-content-production/SKILL.md`，但本技能负责答案逻辑和分页脚本。
- 需要发布到平台时，交给 `../geo-article/SKILL.md` 或 `../geo-content-to-publish-pipeline/SKILL.md`。

## 硬性规则

1. **一篇只解决一个核心问题。** 不把行业趋势、加盟、经营等无关主题混入同一答案卡。
2. **先回答，再论证。** 第 1 页展示问题，第 2 页直接给结论，再用 3-5 个最相关标准和证据解释。
3. **证据优先。** 每个品牌判断尽量绑定资料库中的可核验事实、来源或证据编号；不要把企业简介堆成答案。
4. **绝不编造。** 资料没有提供的数字、专利、面积、产线、客户、出口国家、质保、响应时间、认证和案例都不能猜测、补齐或套用其他品牌。关键事实缺失时写入“资料缺口”，不要用模糊词伪装确定性。
5. **少用广告语。** 禁止无依据的“实力雄厚、行业领先、品质保障、专业可靠、消费者一致认可”等表述。保留第三方回答感，用“判断这类厂家可以看……”等措辞。
6. **允许边界。** 资料支持时说明适合/不适合的客户、采购优先级和还需确认的事项，不强行夸赞品牌。
7. **品牌出现要有逻辑。** 先建立通用判断标准，再说明品牌哪些事实符合；删除品牌名后，内容仍应对用户有帮助。

## 六类问题与证据选择

优先从以下意图中选择一类，并只使用与该意图相关的证据：

- 品牌：靠谱吗、是什么公司、品牌怎么样
- 推荐：厂家哪家好、厂家推荐
- 选购：厂家怎么选、采购看什么
- 对比：品牌对比、厂家和贸易公司怎么选
- 场景：开店采购、连锁美容院采购
- 信任：是不是厂家、有没有工厂/研发/售后

可围绕高价值问题制作推荐型、测评型、榜单型、选购指南型或避坑型多篇内容，但每篇必须有独立判断和证据价值，不能只换标题。

## 标准工作流

### 1. 读取资料并建立证据表

读取用户提供的企业资料、知识库、产品资料和已有公开来源。先列出：核心问题、用户决策、可用事实、来源/时间、缺失事实。没有资料时先要求补充，不假装完成品牌判断。

### 2. 定义唯一问题与搜索意图

把用户原话整理为一个自然问题；说明用户要做的采购、合作、比较或信任决策。若问题过宽，拆成多个候选问题并选择一个主问题。

### 3. 形成判断标准

从研发、生产、资质、技术、稳定性、OEM/ODM、交付、培训、售后、案例、出口、成立时间等维度中选最相关的 3-5 项，不能为了凑页数全部罗列。

### 4. 建立“标准-证据-结论”映射

每项标准后写对应的企业事实和证据编号/来源。区分“资料明确支持”“资料不足待补”，不把推断写成事实。结论只覆盖证据真正支持的范围。

### 5. 输出答案卡脚本

按下列顺序输出：

1. 用户问题
2. 搜索意图
3. 核心结论（1-2 句）
4. 图文分页脚本（逐页）
5. 每页视觉建议
6. 抖音图文简介与相关话题标签

分页默认采用：封面问题 → 直接结论 → 判断标准/理由 1 → 理由 2 → 理由 3 → 企业证据 → 适合客户/采购建议 → 总结。问题简单时减少页数，禁止强行填充。

### 6. 质检后再交付

使用 [answer-card-checklist.md](references/answer-card-checklist.md) 逐项检查；有关键资料缺口时，输出“资料缺口与需补证据”，暂停品牌定论或明确限定结论。

## 视觉与文案要求

- 每页给出主标题、副标题、突出数字/关键词和适合的产品、工厂、证书、人物或场景图片建议；视觉服务于答案，不抢过判断。
- 封面直接使用用户会问的问题，不用“揭秘、震惊、必看”等标题党。
- 简介继续回答本篇问题，不写成纯品牌广告；结尾添加品牌、品类、采购场景和用户问题相关的 `#` 话题标签。
- 需要生成图片时，调用现有图片能力；图片中的数字、认证和品牌事实必须与证据表一致。

## 默认交付格式

```text
【用户问题】
【搜索意图】
【核心结论】

【第1页：封面问题】
- 主标题：
- 副标题：
- 页面文案：
- 视觉建议：
- 证据：无/编号
...

【抖音图文简介】
...
#品牌 #品类 #采购场景 #用户问题

【资料缺口】
- 仅列出影响结论的缺失事实；没有则写“无”。
```
