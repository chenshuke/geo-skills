# 知识库来源与超链接标准

## 目标

让每条关键事实同时满足：人能看懂、点击能追溯、AI 能读取、项目复制后链接仍有效。

## 一、来源目录

```text
01_项目资料/                         原始文件，不改名也不覆盖
02_知识库/
├── 00_来源索引.md                   全部来源入口
└── 来源摘录/
    ├── SRC-001_企业介绍.md
    └── SRC-002_产品手册.md
```

给每份资料分配稳定来源编号。文件内容更新时沿用原编号；不同文件不能共用编号。

## 二、来源索引格式

```markdown
| 来源编号 | 资料名称 | 来源主体 | 日期 | 原始文件 | 可读摘录 | 主要内容 | 状态 |
|---|---|---|---|---|---|---|---|
| SRC-001 | 企业介绍 | XX公司 | 2026-08 | [查看原始文件](<../01_项目资料/企业介绍.pdf>) | [查看文字摘录](<来源摘录/SRC-001_企业介绍.md>) | 企业主体、团队、服务流程 | 可用 |
```

## 三、来源摘录格式

```markdown
# 来源摘录｜企业介绍

- 来源编号：SRC-001
- 来源主体：XX公司
- 原始文件：[点击查看](<../../01_项目资料/企业介绍.pdf>)
- 提取说明：由原文件整理为便于检索的 Markdown，事实仍以原件为准。

<a id="src-001-section-7"></a>
## 第7节｜售后服务流程

原文事实摘录……
```

若原文件没有正式章节，可按页面或内容主题建立锚点：

```html
<a id="src-002-page-8"></a>
<a id="src-003-topic-after-sales"></a>
```

## 四、知识库引用格式

优先把链接放在事实或来源文字上：

```markdown
公司提供交付培训和售后响应流程。来源：[《企业介绍》第7节：售后服务流程](<来源摘录/SRC-001_企业介绍.md#src-001-section-7>)。
```

证据表使用：

```markdown
| 证据编号 | 客观事实 | 来源 |
|---|---|---|
| EV-001 | 公司设有标准售后服务流程 | [SRC-001《企业介绍》第7节：售后服务流程](<../来源摘录/SRC-001_企业介绍.md#src-001-section-7>) |
```

注意：链接相对路径以“当前 Markdown 文件所在目录”为起点。知识库根目录和 `证据库/` 内的相对路径通常不同。

## 五、人类可读规则

- `§7` 改成“第7节”。
- `§7.2` 改成“第7.2节”。
- `¶12` 改成“第12段”。
- `p.8`、`P8` 改成“第8页”。
- 只有编号没有标题时写“《资料名》第7节”，有标题时写“《资料名》第7节：标题”。
- 不展示解析器内部 ID、对象地址、临时文件名或绝对路径。

## 六、网页与不可读取资料

- 网页直接使用公开 URL，链接文字写“网站名｜页面标题”。
- 扫描图片先 OCR，再链接到来源摘录；不确定文字标“待人工核对”。
- PDF 页码与文档印刷页码不一致时，写清“PDF第8页（文档页码第6页）”。
- 无法读取或无法定位时写“来源待定位”，不得生成不存在的章节锚点。

## 七、验收

1. 从知识库随机点击至少 5 条关键事实，均能打开对应摘录位置。
2. 从来源索引能打开原始文件和文字摘录。
3. 项目整体移动后，相对链接仍可使用。
4. 运行 `node scripts/validate_knowledge_links.js 02_知识库`，缺失文件与缺失锚点均为 0。
