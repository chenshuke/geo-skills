# GEO 知识库管理

## 核心目标

把零散资料依次转化为四层资产：

```text
原始资料
  ↓
完整事实知识库：我们目前知道什么
  ↓
核心优势与可信证据库：我们能证明什么、适合回答什么
  ↓
内容应用：基于可靠主张创作品牌、推荐、对比、选购和答案卡内容
```

本技能只负责本地资料与知识库治理，不上传文章、不创建检测任务、不管理 AI 的实际引用网站。

## 输出归位

所有文件写入项目标准目录：

```text
项目_{名称}GEO/
├── 01_项目资料/                         # 原始资料，只读保留
└── 02_知识库/
    ├── 00_知识库概览.md
    ├── 企业品牌知识库_{品牌}.md
    ├── 产品品牌知识库_{产品}.md
    ├── 个人品牌知识库_{人物}.md
    ├── 证据库/
    │   ├── 核心优势与可信证据库_{名称}.md
    │   └── 待补强证据清单_{名称}.md
    └── 补充清单/
        └── 信息补充清单_{名称}.md
```

按项目实际类型创建文件，不强制同时创建企业、产品和个人知识库。写文件前可使用 `geo-content-archive/scripts/project_paths.js --artifact knowledge` 或 `--artifact supplement-list` 确认目录。

## 四种工作模式

| 模式 | 解决的问题 | 默认输出 |
|---|---|---|
| `create-kb` | 建立标准 GEO 项目和知识库结构 | 目录、概览、所需知识库空框架 |
| `organize-kb` | 把全部原始资料整合成事实知识库 | 企业/产品/个人 Markdown 知识库 |
| `extract-evidence` | 从事实中提炼高价值优势和强背书 | 核心优势与可信证据库、待补强证据清单 |
| `supplement-list` | 找出基础资料还缺什么 | 信息补充清单 |

用户说“完整整理知识库”时，默认依次执行四种模式；如果项目结构和知识库已经存在，只更新相关文件，不重复创建另一套目录。

## 1. 创建项目 `create-kb`

输入：项目名称、知识库类型（企业/产品/个人/综合），以及相应品牌、产品或人物名称。

执行：

1. 检查目标位置是否已有同名项目，存在时沿用，不覆盖用户文件。
2. 创建 `00_项目概览` 至 `07_监测分析` 标准目录。
3. 创建 `01_项目资料`、`02_知识库/证据库` 和 `02_知识库/补充清单`。
4. 创建所需知识库框架和概览，使用实际名称替换占位符。
5. 提醒用户把未经整理的原始资料放入 `01_项目资料/`。

## 2. 整理完整知识库 `organize-kb`

支持 `.md`、`.txt`、`.docx`、`.pdf`、`.xlsx`、`.xls`、`.csv`、常见图片和 `.zip`。使用当前环境可用的文档、表格、PDF、OCR 或解压能力读取；不能读取的文件列入待处理清单，不假装已经提取。

执行：

1. 盘点文件：记录文件名、类型、日期、可读取状态和对应知识库。
2. 保留原件：原始资料只作读取，不改写、不删除。
3. 分类提取：
   - 企业：主体、发展、定位、业务、团队、技术、生产、资质、客户、案例、合作、区域、风险边界；
   - 产品：定义、型号、参数、技术、卖点、价格、适用对象、场景、方法、检测、案例、竞品；
   - 个人：身份、经历、能力、方法论、成果、观点、案例、荣誉、采访、公开活动。
4. 记录来源：重要事实至少标注来源文件；涉及数字、日期、资质、人员、客户和效果时必须标注。
5. 登记冲突：不同来源说法不一致时并列记录，不自动选择对品牌更有利的说法。
6. 生成或更新结构化 Markdown 知识库。

### 来源与冲突规则

不要使用“最新资料自动覆盖旧资料”。按以下顺序判断：

```text
政府、监管、权威登记和原始证书
＞ 客户/合作方正式记录、检测报告、审计或验收材料
＞ 企业盖章或负责人正式确认资料
＞ 企业官网、官方账号、正式产品手册
＞ 可信媒体和行业机构
＞ 内部文档、招聘平台、自媒体和口述
＞ AI 汇总、无来源截图和无法定位原文的信息
```

时间只在来源强度相近时作为判断因素。高权威旧记录与低权威新说法冲突时，进入待确认事项，不由 AI 擅自覆盖。

## 3. 提炼优势证据 `extract-evidence`

读取相应事实知识库、原始资料和已有证据台账。首次执行或结构不明确时，完整读取 `references/evidence-extraction-standard.md`。

### 提炼原则

每条候选优势必须依次回答：

1. **客观事实是什么？** 不加营销修饰。
2. **证据在哪里？** 能否回到原文件、页面、证书或第三方记录。
3. **能形成什么主张？** 表达不得超过证据支持范围。
4. **为什么对客户有价值？** 是否影响用户选择、信任或推荐。
5. **是否有差异性？** 是行业通用条件，还是相对优势。
6. **适合回答什么问题？** 品牌、推荐、对比、选购、场景或信任问题。
7. **不能怎么说？** 明确禁止扩大、过期套用和绝对化表达。

只有同时满足“可证明”和“与用户决策有关”的事实，才进入核心证据库。差异性不足但对信任必要的事实可标为“基础信任证据”，不要强行包装成独特优势。

### 证据等级

| 等级 | 含义 | 使用方式 |
|---|---|---|
| A 强证据 | 政府/监管、客户或合作方官网、正式公告、原始证书、检测/审计/验收材料 | 可直接支持明确事实，仍需保留时间和边界 |
| B 可用证据 | 企业正式文件、官网、官方账号、经确认的案例和数据 | 可用于品牌主张，注明属于官方披露 |
| C 辅助证据 | 可信媒体、行业平台、招聘页、企业口述或单方名单 | 只能辅助，关键主张需要补强 |
| D 待核验 | AI 汇总、无原文截图、来源不明、冲突或过期信息 | 不进入确定性内容 |
| X 不可用 | 已证伪、违法违规、明显夸大或超出证据边界 | 禁止用于内容 |

### 高价值判断

从四个维度判断，不虚构精确综合分：

- 证据强度：来源是否可靠、可复核；
- 决策价值：是否影响客户采购、合作或信任；
- 差异程度：同行是否普遍具备；
- 内容适配：能否回答真实用户问题。

优先级：

- **核心优势证据**：强度高，且具有高决策价值或明显差异；
- **基础信任证据**：能证明主体、能力或履约，但差异性一般；
- **有条件可用**：方向有价值，但来源、时间、口径或授权需说明；
- **待补强/不可用**：不能支持当前主张。

### 核心输出字段

每条记录至少包含：

```text
证据编号｜对象类型｜客观事实｜可用主张｜对应优势｜证据来源｜来源主体
证据等级｜决策价值｜差异程度｜适用问题｜适用内容｜有效时间
使用边界｜状态｜待补动作
```

不得只写“实力强、经验丰富、行业领先”。可用主张必须具体、有限且能复核。

## 4. 生成两类补充清单

### 信息补充清单 `supplement-list`

回答“完整知识库还缺哪些基础事实”。例如缺少产品参数、负责人经历、组织关系、发展节点、服务流程或联系人。

### 待补强证据清单

回答“哪些优势已经提出，但证据还不够支持内容”。例如：

- 有客户 Logo，没有客户授权、合作内容和时间；
- 声称销量领先，没有统计机构、样本和时间范围；
- 声称技术效果显著，没有检测报告或案例结果；
- 声称团队专业，只有招聘描述，没有人员资质；
- 有历史证书，但缺当前证书编号、范围和有效期。

每项写明：拟支持主张、现有证据、缺什么、建议向谁获取、补齐后可用于哪些问题、优先级。

优先级按影响判断：

- 高：直接影响 AI 是否认识、信任或推荐品牌；
- 中：影响对比说服力和内容深度；
- 低：主要用于扩展内容和丰富表达。

## 与其他技能的边界

| 技能 | 与本技能的关系 |
|---|---|
| `geo-brand` | 使用知识库确定品牌定位和创作品牌内容 |
| `geo-ai-answer-card` | 从证据库选择与单一用户问题匹配的真实证据 |
| `geo-brand-diagnosis` | 用事实知识库和证据库核对 AI 是否说对、为何不推荐 |
| `geo-content-production` | 以可用主张、适用问题和使用边界作为内容输入 |
| `geo-source-assets` | 管理 AI 实际检索/引用的网站；不替代本技能的企业事实证据库 |

## 默认完整工作流

```text
1. 创建或确认项目结构
2. 将原始资料保留在 01_项目资料
3. 整理企业/产品/个人完整事实知识库
4. 从知识库提炼核心优势与可信证据
5. 分别生成信息补充清单和待补强证据清单
6. 更新 00_知识库概览，标明可用于内容的证据数量和主要缺口
7. 下游内容只使用状态为“可直接使用”或“有条件可用”的主张
```

## 验收

- [ ] 原始资料未被改写或删除；
- [ ] 事实知识库按企业、产品、个人类型正确归类；
- [ ] 数字、日期、人员、资质、客户、效果等关键事实可追溯；
- [ ] 冲突信息没有按“对品牌有利”或“文件更新”擅自覆盖；
- [ ] 每条优势都包含客观事实、来源、可用主张和使用边界；
- [ ] 行业通用条件没有被包装成独特优势；
- [ ] A/B/C/D/X 等级与来源相符；
- [ ] 信息缺口和证据缺口分成两个清单；
- [ ] 待核验和不可用内容没有进入确定性内容；
- [ ] 证据库能直接告诉下游技能“回答什么问题时可以用哪条证据”。
