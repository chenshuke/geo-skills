> **CLI 2 平台操作优先规则（2026-10-17）**：本技能默认只整理本地文件，不调用平台接口；用户明确要求同步时再交给 `../geo-knowledge-sync/SKILL.md`。任何平台读写先读取 `../best-geo/references/cli-compatibility.md`，以当前 capability/schema 为准，并显式使用 `projectId`。

# GEO 知识库管理

## 核心目标

把零散资料依次转化为四层资产：

```text
原始资料
  ↓
完整事实知识库：我们目前知道什么
  ↓
核心优势与可信证据库：我们能证明什么、适合回答什么
  ↓
内容应用：基于可靠主张创作品牌、推荐、对比、选购和答案卡内容
```

本技能只负责本地资料与知识库治理，不上传文章、不创建检测任务、不管理 AI 的实际引用网站。需要把整理后的知识库上传到 GEO 平台，或从平台下载备份时，调用 `geo-knowledge-sync`。

## 输出归位

所有文件写入项目标准目录：

```text
项目_{名称}GEO/
├── 01_项目资料/                         # 原始资料，只读保留
└── 02_知识库/
    ├── 00_知识库概览.md
    ├── 00_来源索引.md
    ├── 企业品牌知识库_{品牌}.md
    ├── 产品品牌知识库_{产品}.md
    ├── 个人品牌知识库_{人物}.md
    ├── 来源摘录/
    │   └── SRC-001_{资料名}.md
    ├── 证据库/
    │   ├── 核心优势与可信证据库_{名称}.md
    │   ├── 待补强证据清单_{名称}.md
    │   ├── 证据候选与补强台账_{名称}.md
    │   └── 可回答问题机会图谱_{名称}.md
    └── 补充清单/
        └── 信息补充清单_{名称}.md
```

按项目实际类型创建文件，不强制同时创建企业、产品和个人知识库。写文件前可使用 `geo-content-archive/scripts/project_paths.js --artifact knowledge` 或 `--artifact supplement-list` 确认目录。

## 五种工作模式

| 模式 | 解决的问题 | 默认输出 |
|---|---|---|
| `create-kb` | 建立标准 GEO 项目和知识库结构 | 目录、概览、所需知识库空框架 |
| `organize-kb` | 把全部原始资料整合成事实知识库 | 企业/产品/个人 Markdown 知识库 |
| `extract-evidence` | 从事实中提炼高价值优势和强背书 | 核心优势与可信证据库、待补强证据清单 |
| `supplement-list` | 找出基础资料还缺什么 | 信息补充清单 |
| `assess-kb` | 按当前阶段检查知识库是否达到可用水平，并从证据反推可竞争的问题 | GEO知识库体检看板、可回答问题机会图谱、下一步补强清单 |

用户说“完整整理知识库”时，默认依次执行五种模式；如果项目结构和知识库已经存在，只更新相关文件，不重复创建另一套目录。没有用户问题池时，`assess-kb` 不计算“已确认问题池覆盖度”，但必须根据现有证据生成“可回答问题机会图谱”；“资料完整度”统一改称“知识结构覆盖度”，分母来自当前对象类型公开的10模块清单，必须在看板中列明。

## 1. 创建项目 `create-kb`

输入：项目名称、知识库类型（企业/产品/个人/综合），以及相应品牌、产品或人物名称。

执行：

1. 检查目标位置是否已有同名项目，存在时沿用，不覆盖用户文件。
2. 创建 `00_项目概览` 至 `07_监测分析` 标准目录。
3. 创建 `01_项目资料`、`02_知识库/来源摘录`、`02_知识库/证据库` 和 `02_知识库/补充清单`。
4. 创建所需知识库框架和概览，使用实际名称替换占位符。
5. 提醒用户把未经整理的原始资料放入 `01_项目资料/`。

## 2. 整理完整知识库 `organize-kb`

支持 `.md`、`.txt`、`.docx`、`.pdf`、`.xlsx`、`.xls`、`.csv`、常见图片和 `.zip`。使用当前环境可用的文档、表格、PDF、OCR 或解压能力读取；不能读取的文件列入待处理清单，不假装已经提取。

执行：

1. 盘点文件：给每份资料分配稳定编号 `SRC-001`、`SRC-002`，记录文件名、类型、日期、可读取状态和对应知识库，并写入 `00_来源索引.md`。
2. 保留原件：原始资料只作读取，不改写、不删除。
3. 分类提取：
   - 企业：主体、发展、定位、业务、团队、技术、生产、资质、客户、案例、合作、区域、风险边界；
   - 产品：定义、型号、参数、技术、卖点、价格、适用对象、场景、方法、检测、案例、竞品；
   - 个人：身份、经历、能力、方法论、成果、观点、案例、荣誉、采访、公开活动。
4. 建立来源摘录：把可读取资料整理成 Markdown 摘录，保留原章节标题，为每个章节写入稳定锚点，并同时链接原始文件。
5. 记录来源：重要事实至少使用可点击链接标注来源；涉及数字、日期、资质、人员、客户和效果时必须链接到具体章节、页面或表格位置。
6. 登记冲突：不同来源说法不一致时并列记录，不自动选择对品牌更有利的说法。
7. 生成或更新结构化 Markdown 知识库，并校验内部链接和锚点。
8. 原始资料刚导入时，先建立“证据候选与补强台账”，不要把尚未核验的资料直接判为可用证据。

### 人类可读的来源定位

知识库面向学员阅读，禁止在正文、表格和来源标签中输出难懂的内部符号或缩写：

| 禁止写法 | 必须改为 |
|---|---|
| `§7` | `第7节` |
| `§7.2` | `第7.2节` |
| `¶12` | `第12段` |
| `p.8`、`P8` | `第8页` |
| `#3`（表示条目时） | `第3项` |

来源标签要把“资料名 + 人类可读位置 + 内容标题”说完整。例如：

```markdown
[《企业介绍》第7节：售后服务流程](<来源摘录/SRC-001_企业介绍.md#src-001-section-7>)
```

如果原文确实把 `§` 作为正文内容或正式名称的一部分，可以在原文摘录中保留；但知识库导航和引用标签仍写成“第7节”。完整规则见 `references/source-linking-standard.md`。

### 文档超链接映射

- `00_来源索引.md` 是全部资料的入口，每份资料同时提供“原始文件”和“Markdown 摘录”链接。
- Word、PDF、PPT、Excel、图片等原件保持不变；另建 `来源摘录/SRC-xxx_资料名.md` 供用户点击阅读、供 AI 稳定解析。
- 来源摘录中的章节使用稳定 HTML 锚点，例如 `<a id="src-001-section-7"></a>`。不要只依赖中文标题自动生成的锚点。
- 知识库中的关键事实、证据表、案例、数字、资质和结论必须链接到最具体的来源位置，不能只写文件名或“企业资料”。
- 链接使用相对路径，禁止写当前电脑的绝对路径，保证整个项目复制到 Windows 或 Mac 后仍可使用。
- 网页来源直接链接公开 URL，并在链接文字中写明网站名和页面标题。
- 无法定位到具体位置时标为“来源待定位”，不得伪造章节或链接。

### 来源与冲突规则

不要使用“最新资料自动覆盖旧资料”。按以下顺序判断：

```text
政府、监管、权威登记和原始证书
＞ 客户/合作方正式记录、检测报告、审计或验收材料
＞ 企业盖章或负责人正式确认资料
＞ 企业官网、官方账号、正式产品手册
＞ 可信媒体和行业机构
＞ 内部文档、招聘平台、自媒体和口述
＞ AI 汇总、无来源截图和无法定位原文的信息
```

时间只在来源强度相近时作为判断因素。高权威旧记录与低权威新说法冲突时，进入待确认事项，不由 AI 擅自覆盖。

## 3. 提炼优势证据 `extract-evidence`

读取相应事实知识库、原始资料和已有证据台账。首次执行或结构不明确时，完整读取 `references/evidence-extraction-standard.md`。

### 提炼原则

每条候选优势必须依次回答：

1. **客观事实是什么？** 不加营销修饰。
2. **证据在哪里？** 能否回到原文件、页面、证书或第三方记录。
3. **能形成什么主张？** 表达不得超过证据支持范围。
4. **为什么对客户有价值？** 是否影响用户选择、信任或推荐。
5. **是否有差异性？** 是行业通用条件，还是相对优势。
6. **适合回答什么问题？** 品牌、推荐、对比、选购、场景或信任问题。
7. **不能怎么说？** 明确禁止扩大、过期套用和绝对化表达。

只有同时满足“可证明”和“与用户决策有关”的事实，才进入核心证据库。差异性不足但对信任必要的事实可标为“基础信任证据”，不要强行包装成独特优势。

### 证据成熟度等级

| 等级 | 含义 | 使用方式 |
|---|---|---|
| A 强证据 | 来源权威或相对独立，能直接证明主张，原文可定位，时间和范围明确 | 可直接支持明确事实，仍需保留时间和边界 |
| B 可用证据 | 企业正式文件、官网、官方账号、经确认的案例和数据，能够直接支持事实 | 可用于品牌主张，注明来源性质 |
| C 辅助证据 | 可信媒体、行业平台、招聘页、企业口述或单方名单，只能间接支持 | 只能辅助，关键主张需要补强 |
| D 待核验 | AI 汇总、无原文截图、来源不明、冲突、过期或无法定位 | 暂不进入确定性内容，但保留为补强候选 |
| X 不可用 | 已证伪、违法违规、明显夸大或超出证据范围 | 禁止用于内容，记录原因 |

等级不是资料文件的“永久标签”，而是“某条证据对某个主张的当前成熟度”。同一份官网资料中的不同事实可以有不同等级；多个弱来源互相转载，也不会自动升级为 A 级。

### 价值与成熟度分开记录

每条候选证据同时记录两个维度：

- **证据价值**：高 / 中 / 低，判断这条事实是否影响用户选择、信任或推荐，以及是否具有差异性。
- **证据成熟度**：A / B / C / D / X，判断这条事实当前是否有足够可靠、可追溯、范围匹配的支持。

高价值但 C/D 级的证据不能丢弃，应进入“优先补强”；低价值但 A 级的证据可以保留，但不应挤占核心内容资源。只有“高价值且 A/B 级”的证据，才适合直接承担核心推荐或对比结论。

### 高价值判断

从四个维度判断，不虚构精确综合分：

- 证据强度：来源是否可靠、可复核；
- 决策价值：是否影响客户采购、合作或信任；
- 差异程度：同行是否普遍具备；
- 内容适配：能否回答真实用户问题。

优先级：

- **核心优势证据**：强度高，且具有高决策价值或明显差异；
- **基础信任证据**：能证明主体、能力或履约，但差异性一般；
- **有条件可用**：方向有价值，但来源、时间、口径或授权需说明；
- **待补强/不可用**：不能支持当前主张。

### 核心输出字段

每条记录至少包含：

```text
证据编号｜对象类型｜客观事实｜可用主张｜对应优势｜证据来源｜来源主体
证据等级｜决策价值｜差异程度｜适用问题｜适用内容｜有效时间
使用边界｜状态｜待补动作
```

不得只写“实力强、经验丰富、行业领先”。可用主张必须具体、有限且能复核。

## 4. 生成两类补充清单

### 信息补充清单 `supplement-list`

回答“完整知识库还缺哪些基础事实”。例如缺少产品参数、负责人经历、组织关系、发展节点、服务流程或联系人。

### 待补强证据清单

回答“哪些优势已经提出，但证据还不够支持内容”。例如：

- 有客户 Logo，没有客户授权、合作内容和时间；
- 声称销量领先，没有统计机构、样本和时间范围；
- 声称技术效果显著，没有检测报告或案例结果；
- 声称团队专业，只有招聘描述，没有人员资质；
- 有历史证书，但缺当前证书编号、范围和有效期。

每项写明：拟支持主张、现有证据、缺什么、建议向谁获取、补齐后可用于哪些问题、优先级。

优先级按影响判断：

- 高：直接影响 AI 是否认识、信任或推荐品牌；
- 中：影响对比说服力和内容深度；
- 低：主要用于扩展内容和丰富表达。

## 5. GEO知识库体检 `assess-kb`

体检是阶段检查，不是给所有项目强行打一个总分。先判断项目处于哪个阶段，再决定哪些指标可以计算。首次执行或需要解释分子、分母时，读取 `references/kb-readiness-standard.md`。需要从知识库反推问题时，完整读取 `references/question-opportunity-standard.md`。

### 阶段判断

| 阶段 | 进入条件 | 主要输出 | 不计算的指标 |
|---|---|---|---|
| 资料导入期 | 已有原始文件、网址、图片或录音等资料，但尚未完成结构化 | 资料清单、可读取状态、待处理项 | 知识结构覆盖度、问题覆盖度 |
| 事实建档期 | 已有企业/产品/个人知识库，事实有来源链接 | 结构检查、冲突清单、来源链接检查 | 问题覆盖度（无问题池时） |
| 证据规划期 | 已把资料拆成候选事实和候选主张，但仍有 C/D 级证据 | 证据候选台账、价值—成熟度矩阵、补强优先级 | 不能把候选证据当作已可用证据 |
| 内容可生产期 | 目标问题池已确认，核心问题有 A/B 级证据 | 用户问题—证据覆盖表、可创作范围 | 未覆盖问题不得假设已解决 |
| 持续优化期 | 已发布内容并有监测或复测结果 | 内容—问题—证据—复测闭环 | 不把资料评分当成上榜结果 |

### 三类指标的计算规则

1. **资料处理状态**：只报告“已发现 / 已读取 / 待人工处理 / 读取失败”的数量，不把文件数量称为资料完整度。
2. **知识结构覆盖度**：完成事实建档后，按企业、产品或个人的公开10模块清单分别计算。分母固定为当前对象的10个模块；分子是至少已有一条相关事实的模块数。每个模块另标记 🟢“有可追溯事实”、🟡“已有线索但来源待补”、⚪“尚无资料”。综合项目分别显示企业和产品，不合并成一个含糊总分。
3. **可回答问题机会**：不需要预先提供问题池。AI从A/B级证据和高价值C/D级候选反推问题族，分别输出“现在可竞争”“补证后可竞争”“暂不建议竞争”。这是机会图谱，不计算覆盖率，也不把同义改写数量当成绩。
4. **已确认问题池覆盖度**：只有用户提供或确认了真实问题池后才计算，分母是问题池中的实际问题数，分子是每个问题至少有一条A/B级证据可支持核心回答的问题数。没有问题池时显示“未评估—尚未导入真实问题池”。

### 从证据反推问题

问题机会必须从“可用事实—可用主张—用户决策”推导，不能为了凑数量批量改写同义句。分为两条主线：

1. **品牌问题**：问题中出现品牌名，回答品牌是谁、做什么、适合谁、有什么能力、凭什么可信、与同类有什么差异、边界是什么。
2. **产品/服务推荐问题**：问题中不预设品牌名，回答某类产品、服务商或解决方案怎么选、推荐谁、什么场景适合什么。目标品牌只有在证据足以支持时才能进入答案。

两条主线再按搜索粒度展开：

- 大词：宽泛品类或服务推荐；
- 小词：细分品类、具体能力或具体服务；
- 场景词：人群、地区、预算、规模、用途和业务场景；
- 长尾词：带多个约束条件、接近最终决策的问题。

证据越强、范围越广，才越有资格竞争大词；证据范围越窄，越应该优先竞争小词、场景词和长尾词。只有企业自述、缺少案例或第三方证明时，优先回答品牌身份和有限能力问题，不强行进入无品牌推荐问题。

每个问题族至少记录：代表问题、问题类型、搜索粒度、用户真实决策、目标AI判断、可用证据、证据成熟度、品牌进入答案的理由、当前状态、补强动作。问题图谱写入 `证据库/可回答问题机会图谱_{名称}.md`。

### 推荐的可视化输出

```text
GEO知识库体检｜当前阶段：证据规划期

资料处理：已读取 18 份｜待人工处理 2 份
知识结构覆盖：企业 8/10（🟢 5｜🟡 3｜⚪ 2）
可回答问题机会：品牌问题 6个问题族｜推荐问题 4个问题族
当前适合：小词、场景词、长尾词
暂不建议：宽泛大词推荐
已确认问题池覆盖：未评估（尚未导入真实问题池）
证据候选：42 条｜记录完整 31 条
证据成熟度：A 4｜B 12｜C 18｜D 8｜X 0
高价值待补强：7 条

当前结论：资料已完成初步整理，可以继续做证据规划；暂不建议把 C/D 级候选直接写成确定性内容。
下一步优先级：先补 3 条高价值证据，再建立首批真实用户问题池。
```

### 体检报告必须回答

- 哪些资料已经被读到，哪些还没读到；
- 哪些证据已经可直接使用，哪些只是有价值但待补强；
- 哪些高价值主张因证据等级不足暂时不能写；
- 现有知识库已经有资格回答哪些品牌问题和推荐问题；
- 当前更适合竞争大词、小词、场景词还是长尾词；
- 当前指标的分子、分母、对象模板和计算口径；
- 用户下一步只需要做哪三件事。

体检报告写入 `02_知识库/00_GEO知识库体检看板.md`。候选证据与补强记录写入 `证据库/证据候选与补强台账_{名称}.md`，证据反推的问题写入 `证据库/可回答问题机会图谱_{名称}.md`。这些文件是可读的工作看板，不替代原始资料，也不把“可回答”误写成“已经上榜”。

## 与其他技能的边界

| 技能 | 与本技能的关系 |
|---|---|
| `geo-brand` | 使用知识库确定品牌定位和创作品牌内容 |
| `geo-ai-answer-card` | 从证据库选择与单一用户问题匹配的真实证据 |
| `geo-brand-diagnosis` | 用事实知识库和证据库核对 AI 是否说对、为何不推荐 |
| `geo-content-production` | 以可用主张、适用问题和使用边界作为内容输入 |
| `geo-source-assets` | 管理 AI 实际检索/引用的网站；不替代本技能的企业事实证据库 |

## 默认完整工作流

```text
1. 创建或确认项目结构
2. 将原始资料保留在 01_项目资料
3. 整理企业/产品/个人完整事实知识库
4. 从知识库提炼核心优势与可信证据
5. 建立证据候选与补强台账，分别记录证据价值和证据成熟度
6. 分别生成信息补充清单和待补强证据清单
7. 运行 `assess-kb`，按实际阶段输出体检看板和可回答问题机会图谱；没有真实问题池时只把“已确认问题池覆盖度”标为未评估
8. 更新 00_知识库概览，标明可用于内容的证据数量和主要缺口
9. 更新 00_来源索引，并确保关键事实可以点击回到来源摘录或原始文件
10. 运行 `node scripts/validate_knowledge_links.js <项目目录/02_知识库>` 检查本地链接与锚点
11. 下游内容只使用状态为“可直接使用”或“有条件可用”的主张
```

## 验收

- [ ] 原始资料未被改写或删除；
- [ ] 事实知识库按企业、产品、个人类型正确归类；
- [ ] 数字、日期、人员、资质、客户、效果等关键事实可追溯；
- [ ] 没有使用 `§7`、`¶12`、`p.8` 等机器式来源标签，已改为“第7节、第12段、第8页”等自然语言；
- [ ] `00_来源索引.md` 能跳转到原始文件和 Markdown 来源摘录；
- [ ] 知识库中的关键事实能点击到具体来源章节，而不是只写参考文件名；
- [ ] 所有内部链接使用相对路径，复制项目后仍然有效；
- [ ] 链接校验不存在缺失文件或缺失锚点；
- [ ] 冲突信息没有按“对品牌有利”或“文件更新”擅自覆盖；
- [ ] 每条优势都包含客观事实、来源、可用主张和使用边界；
- [ ] 行业通用条件没有被包装成独特优势；
- [ ] A/B/C/D/X 等级与来源相符；
- [ ] 证据价值与证据成熟度分开记录；高价值 C/D 级证据进入补强台账而不是被丢弃；
- [ ] 信息缺口和证据缺口分成两个清单；
- [ ] 体检看板的每个分子、分母、对象模板和计算口径都可解释；
- [ ] 没有真实问题池时，已确认问题池覆盖度显示“未评估”，但仍从证据生成可回答问题机会图谱；
- [ ] 问题机会以独立决策意图为单位，不用同义句数量制造虚假覆盖；
- [ ] 品牌问题与无品牌推荐问题分开；问题粒度与证据强度、范围相匹配；
- [ ] “可回答问题”没有被误写成“已经上榜问题”；
- [ ] 知识结构覆盖度使用对应对象的公开10模块清单，综合项目分开显示；
- [ ] 待核验和不可用内容没有进入确定性内容；
- [ ] 证据库能直接告诉下游技能“回答什么问题时可以用哪条证据”。
