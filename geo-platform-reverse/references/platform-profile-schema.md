# 平台画像文件格式规范

> 本文档定义 `geo-platform-reverse` 生成的平台画像文件的标准格式。
> 该格式同时服务于人类阅读（Obsidian 渲染）和机器解析（geo-evidence-chain 消费）。

---

## 1. 文件命名

```
平台画像_{platform}_{YYYYMMDD}.md
```

示例：`平台画像_deepseek_20260508.md`

- `{platform}`：平台标识符（小写，deepseek/doubao/yuanbao/qwen/yiyan/kimi/zhipu）
- `{YYYYMMDD}`：生成日期（可选，建议保留以支持版本管理）

---

## 2. YAML Front Matter 规范

### 必填字段

| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| `type` | string | 固定值 `geo-platform-profile` | `geo-platform-profile` |
| `platform` | string | 平台标识符（小写） | `deepseek` |
| `platform_name` | string | 平台中文名 | `DeepSeek` |
| `generated_by` | string | 生成工具 | `geo-platform-reverse` |
| `generated_at` | string | 生成日期（ISO格式） | `2026-05-08` |
| `data_source` | string | 数据来源类型 | `data-driven` / `experiment` / `merged` |
| `sample_size` | number | 分析样本数量 | `342` |
| `confidence` | string | 置信度 | `high` / `medium` / `low` |
| `version` | string | 画像格式版本 | `v1.0` |

### 可选字段

| 字段 | 类型 | 说明 | 示例 |
|------|------|------|------|
| `date_range` | string | 数据时间范围 | `"2026-03-01 ~ 2026-05-07"` |
| `industry` | string | 行业领域 | `壁挂炉` / `mixed`（跨行业） |
| `company_id` | number | 公司ID（0=跨公司） | `0` |

### 置信度判定规则

| 样本量 | 置信度 |
|--------|--------|
| ≥ 200 | `high` |
| 50 ~ 199 | `medium` |
| < 50 | `low` |

## 3. Markdown 正文章节规范

### 章节 1：引用性格总览

格式：单表格，一行概括核心画像。

| 属性 | 值 |
|------|-----|
| **性格标签** | {策略类型标签} |
| **平均引用来源数** | {X.X}个 |
| **indexed采纳率** | {XX}% |
| **来源类型多样性** | {X.X}种/问题 |
| **偏好来源Top3** | {类型1}、{类型2}、{类型3} |
| **不引用的来源类型** | {类型列表，无则为"无"} |
| **时效性偏好** | {强/中/弱}（{2026年占比}%） |
| **引用格式** | {主要格式} |

### 章节 2：来源类型分布

格式：标准表格。

```
| 来源类型 | 出现次数 | 占比 | indexed次数 | indexed率 | 偏好度 |
|---------|---------|------|-----------|----------|--------|
```

- **偏好度**：indexed率 / 总体indexed率，标注为 **高** / 中 / 低

### 章节 3：交叉验证模式

格式：指标表 + 策略判定。

```
| 指标 | 值 | 解读 |
|------|-----|------|
| 平均来源数 | | |
| indexed采纳率 | | |
| 类型多样性 | | |
| 域名多样性 | | |
| 同源重复率 | | |
```

策略类型：高交叉验证型 / 精选型 / 广撒网型 / 均衡型

### 章节 4：问题类型→引用模式

格式：按问题类型分行的对比表。

```
| 问题类型 | 结果数 | 平均来源数 | indexed率 | 偏好来源类型Top3 | 特殊行为 |
|---------|--------|-----------|----------|----------------|---------|
```

### 章节 5：时效性分析

格式：年份分布表 + 偏好判定。

```
| 来源年份 | 占比 | indexed率 |
|---------|------|----------|
```

### 章节 6：引用格式

格式：格式类型占比表。

```
| 格式类型 | 使用频率 | 示例 |
|---------|---------|------|
```

### 章节 7：权威信号

格式：权威层级 indexed 率对比表。

```
| 信号类型 | indexed率 | 与平均差异 |
|---------|----------|----------|
```

### 章节 8：Top 15 被引用域名

格式：域名排名表。

```
| 排名 | 域名 | 被引用次数 | indexed次数 | indexed率 |
|------|------|-----------|-----------|----------|
```

### 章节 9：平台特异性行为

格式：无序列表，每条为从数据中动态发现的独特标签。

### 章节 10：策略建议

格式：分两部分。

1. **对GEO发布的建议**：编号列表
2. **与 evidence-chain 的衔接说明**：一段文字说明如何导入

## 4. geo-evidence-chain 解析规则

当 `geo-evidence-chain` 通过 `--platform-profiles` 参数导入画像文件时，按以下规则解析：

### 4.1 从 YAML Front Matter 读取

- `platform` → 匹配分析目标平台
- `generated_at` → 判断画像是否过期（>90天发出警告）
- `confidence` → 影响策略矩阵的可信度权重
- `sample_size` → 低于50时降级处理

### 4.2 从 Markdown 正文读取

- **章节 2（来源类型分布）**：替代 evidence-chain Step 3 的硬编码来源偏好表
  - 读取每行的 `来源类型`、`占比`、`偏好度`
  - 用动态数据替代硬编码的百分比

- **章节 3（交叉验证模式）**：替代 evidence-chain Step 3 的硬编码性格标签
  - 读取"策略类型"判定
  - 读取 `平均来源数` 和 `indexed采纳率`

- **章节 4（问题类型映射）**：增强 evidence-chain 的缺口分析
  - 读取各问题类型的 indexed 率
  - 用于更精准的发布策略推荐

### 4.3 Fallback 逻辑

- 如果画像文件中某个章节缺失或格式异常，回退到 evidence-chain 的硬编码默认值
- 如果画像文件完全无法解析，发出警告并使用硬编码默认值
- 部分平台有画像、部分没有时，有的用动态数据，没有的用硬编码
