# GEO 引用来源品牌识别技能

> **技能名称**：geo-citation-brand-audit  
> **用途**：针对 AI 查收录结果中的引用来源链接，自动访问页面并判断其是否与目标品牌/产品相关  
> **定位**：浏览器优先、可解释、可迭代优化  
> **适用阶段**：MVP 验证期 / 规则沉淀期 / 批量化前的流程固化期

---

## 核心原则

1. **先跑通，再提速**：前期优先使用浏览器能力稳定获取内容，不急于一开始就全做成纯请求/正则。
2. **证据优先**：每条判断都必须给出可复核证据，不能只给“相关/不相关”。
3. **分层判定**：先做标题/域名/正文命中，再做语义判断。
4. **逐步沉淀**：每次遇到新站型、新噪音、新误判，都补规则，而不是推翻重来。
5. **人工可复核**：输出结果必须适合回看、抽查、复盘。

---

## 适用输入

本技能适用于以下输入之一：

### 输入形态 A：单条引用
- 目标品牌
- 目标产品（可选）
- 引用标题
- 引用 URL
- AI 回答原文（可选）

### 输入形态 B：一组 citations
```json
{
  "target": {
    "brand": "海顿",
    "product": "壁挂炉",
    "aliases": ["海顿壁挂炉", "Haydn"]
  },
  "citations": [
    {
      "title": "2026 年壁挂炉品牌怎么选",
      "url": "https://example.com/a"
    }
  ]
}
```

### 输入形态 C：来自查收录系统的原始结果
- query
- platform
- answer
- sources / citations[]

---

## 标准输出

每条链接至少输出以下字段：

```json
{
  "citation_url": "https://example.com/a",
  "page_title": "页面实际标题",
  "domain": "example.com",
  "fetch_method": "browser",
  "extract_status": "success",
  "is_relevant": true,
  "relevance_type": "brand_direct",
  "confidence": 0.91,
  "matched_terms": ["海顿", "海顿壁挂炉"],
  "evidence": [
    "标题包含品牌词‘海顿壁挂炉’",
    "正文首段介绍该品牌产品",
    "页面主体为产品介绍/选购内容"
  ],
  "page_summary": "页面核心内容摘要",
  "needs_manual_review": false
}
```

---

## 判定标签

统一使用以下标签：

- `brand_direct`：页面核心主题就是目标品牌/产品
- `brand_related`：页面主主题相关，且对目标品牌有实质介绍
- `generic_with_brand_mention`：泛行业内容，仅提到目标品牌
- `competitor_only`：主体是竞品或对标品牌
- `irrelevant`：与目标品牌/产品无关
- `unknown`：页面无法稳定抽取，待人工复核

## 执行流程（浏览器优先）

### 步骤 1：预处理输入
先整理：
- 目标品牌名
- 产品名
- 别名/英文名/缩写
- 需要审核的 URL 列表

并对 URL 做：
- 去重
- 域名归类
- 明显无效链接过滤（空链接、锚点、javascript 等）

### 步骤 2：浏览器打开页面
优先使用浏览器工具访问页面。

操作要点：
1. `browser_navigate(url)` 打开页面
2. 如果快照信息不够，使用：
   - `browser_snapshot(full=true)`
   - `browser_console()` 检查报错/重定向/空白页
3. 必要时滚动：
   - `browser_scroll(direction="down")`
4. 如果页面是强视觉型或文本树抓不到核心内容：
   - `browser_vision()` 辅助判断页面结构

#### 浏览器前置检查（新增）
如果浏览器工具一开始就报 Playwright/Chromium 缺失，不要直接判定为页面失败，先做环境排查：

1. 先用终端确认 Playwright 已安装，并执行：
   - `npx playwright install chromium`
2. 在 macOS 环境里，浏览器缓存有时会下载到 profile home 下，例如：
   - `~/Library/Caches/ms-playwright`
   但浏览器工具实际查找的是：
   - `/Users/.../Library/Caches/ms-playwright`
3. 如果出现这种路径不一致，可建立符号链接把真实缓存目录映射到浏览器工具期望的位置。
4. 只有在浏览器环境确认可用后，才继续把页面异常归类为 404、空白页、登录拦截、跳转异常等业务失败。

### 步骤 3：提取页面有效信息
优先提取：
- 页面标题
- H1/H2
- 首段正文
- 页面摘要/主要段落
- 品牌词和产品词命中情况

如果网页快照足够清晰，可直接基于快照抽取。
如果快照不完整，再结合页面可见文本做归纳。

### 步骤 4：规则初判
先做低成本规则判断：

#### 高分信号
- 标题含“品牌名 + 产品名”
- H1 或首段含品牌词
- 正文多段围绕目标品牌展开
- 官方域名/官方渠道页面

#### 中分信号
- 页面为榜单/评测/问答，其中单独一节介绍目标品牌
- 正文多次出现品牌词、产品词并有上下文关系

#### 低分信号
- 仅出现一次品牌词
- 仅在评论区、相关推荐、友情链接中出现

#### 直接判负信号
- 通篇不含品牌/产品相关词
- 页面核心内容是竞品
- 页面主题与行业无关

### 步骤 5：语义复核
对规则判定不够确定的页面，必须做语义复核，输出：
- 页面主题是什么
- 是否真正在介绍目标品牌/产品
- 是主相关还是顺带提及
- 判定证据是什么

### 步骤 6：形成结构化结果
每条 URL 必须输出：
- 页面标题
- 链接
- 域名
- 判定标签
- 置信度
- 证据
- 是否需要人工复核

## 浏览器阶段的最佳实践

### 1. 用浏览器做“站型摸底”
前期不要急着抽象。先观察常见引用来源属于哪几类：
- 新闻站
- 企业官网
- 百科/问答站
- 电商详情页
- 聚合榜单页
- PDF/文档落地页

把这些站型整理出来，后续规则才有沉淀价值。

### 2. 保留“为什么判定”的证据
每次输出至少给 2~3 条证据，否则后续无法纠偏。

### 3. 优先做“相关/不相关/待复核”三分法
MVP 阶段不要一开始追求很细的标签精度。
先稳定地区分：
- 明显相关
- 明显无关
- 不确定待复核

### 4. 对失败页单独标记
例如：
- 页面打不开
- 403
- 跳转异常
- 内容为空
- 仅登录可见

这些不要混入“不相关”。

## 从浏览器到规则引擎的迭代路径

### V1：纯浏览器判定
适合刚开始。
- 浏览器打开
- 读页面
- 提取证据
- 做人工可复核判断

### V2：浏览器 + 关键词规则
在 V1 基础上沉淀：
- 品牌词字典
- 产品词字典
- 标题命中规则
- 域名白名单
- 首段命中规则

### V3：浏览器兜底 + 正则/HTML 规则主跑
当某些站型稳定后，把它们转为：
- 指定 CSS 选择器
- 正则提取正文
- 域名定制规则

浏览器只处理：
- 新站型
- 抽取失败页
- 规则低置信度页

### V4：半自动批处理
把规则成熟的页面自动跑掉，只把：
- `unknown`
- `competitor_only`
- `generic_with_brand_mention`
这些边界页送人工复核。

## 常见误判

### 误判 1：榜单页提到品牌一次就判相关
修正：必须判断该品牌是否为正文主体之一，而不是只出现过。

### 误判 2：官网域名就一律判相关
修正：还要看具体页面是否讲目标产品，而不是招聘页、新闻页、联系页。

### 误判 3：聚合站 SEO 页面误判为高相关
修正：判断正文是否有实质信息，而不是只有关键词堆砌。

### 误判 4：竞品对比页误判为目标品牌页
修正：区分“主体是目标品牌”还是“只是被列在对比对象里”。

---

## 复盘与沉淀要求

每轮执行后，建议沉淀：
1. 新出现的站型
2. 新发现的品牌别名/误写
3. 高误判页面特征
4. 可抽象为规则的提取逻辑
5. 可加入白名单/黑名单的域名

如果某类页面连续出现 3 次以上，就应该考虑把它从“浏览器人工判定”升级为“规则自动判定”。

## 结论

这个技能的目标不是一次性做成完美自动化，而是：

**先用浏览器把引用来源识别流程跑通并沉淀证据，再逐步把高频站型和高频规则固化为低成本自动流程。**

这是最适合 GEO 业务前期验证和逐步精进的路线。
