# GEO 内容生产技能

> **通用兼容**：适用于 Claude Code、Codex 和兼容 Agent Skills 的工具；建议完整安装同级 `geo-*` 技能，运行诊断请使用 `../geo-runtime/SKILL.md`。

> 本模块涵盖内容生产全流程：**关键词规划 / 标题创作 / 图文转短视频文案 / 图片生成**
> 对应的审核/覆盖分析/优化模块见 `../geo-content-audit/SKILL.md`

**外部依赖**：`geo-image-generation` 使用 GEO 平台 openKey/referer，与其他 GEO 技能共用配置。

## 输出归位硬规则

内容生产产物必须直接写入项目标准目录：关键词方案放 `03_规划方案/关键词方案/`，标题方案放 `03_规划方案/标题方案/`，文章放 `04_内容创作/{日期}/articles/`，封面放 `04_内容创作/{日期}/covers/`，配图放 `04_内容创作/{日期}/images/`。写文件前必须用 `geo-content-archive/scripts/project_paths.js` 或等价规则确定路径。

## 小批量高质量创作硬规则（课堂/学员模式）

面向学员实操课或“20问上榜战役”时，内容创作必须小批量高质量完成：

- 不要一次性批量生成 10 篇、12 篇、20 篇“简约版/摘要版”文章正文。
- 优先拆成子代理或小批量任务：P0核心内容建议 1 个子代理写 1 篇；同主题/同证据内容可 1 个子代理写 2-3 篇；单个子代理最多不超过 5 篇。
- 每篇文章必须是可进入审核/上传/发布准备的完整 Markdown 正文，而不是提纲、摘要或几段短文。
- 文章必须写入 GEO 项目标准目录：`04_内容创作/{日期}/articles/`。
- 每篇文章必须至少生成1张封面图，写入 `04_内容创作/{日期}/covers/`；没有封面图不能进入上传发布。
- 正文配图按内容需要生成，写入 `04_内容创作/{日期}/images/`；重点文章建议至少1张流程图/步骤图/对比图。
- 课程工作台或模块文档只记录文章链接、摘要、证据和待补项，不承载长正文。
- 如果缺少项目目录，先通过 `geo-content-archive/scripts/project_paths.js` 或同等规则确认目录；无法确认时先询问用户，不要乱建目录。


### 对外可发布正文规则

课堂/学员模式下生成文章时，正文必须像正式对外发布的文章：

- 不要在正文中出现“直接回答：”“判断标准：”“现有证据：”“待补证据：”等内部标签；
- 不要在正文中出现“待补证据”“资料待补”“截图待补”“案例待补”等字样；
- 缺失证据要写入模块草稿区、内部待补清单或审核清单，不写进文章正文文件；
- 没有证据支撑的案例、数据、排名、价格、客户评价、媒体背书，不得写进正文；
- 证据不足时，正文采用稳妥表达，例如“可以重点关注”“建议从以下维度判断”“通常需要看这几类资料”，不要伪装成已验证事实；
- 文章文件只保存可对外发布正文；内部待补清单必须单独输出到模块草稿区或审核清单，不要附在文章正文文件里。


## 一、关键词规划

本模块包含三个子技能，用于系统化构建品牌的三级关键词/意图体系。生成关键词时必须同时完成**分层优先级筛选**：L1、L2、L3 各自标注 P0/P1/P2，并为最终 L1×L2×L3 组合输出组合优先级、筛选理由和后续验证建议。

### 1.1 geo-keyword-plan — GEO拓展词方案生成

**用途**：生成完整GEO拓展词方案（飞书文档版+HTML美观版），输出15个L2拓展词 + 600-900个L3长尾问题，并对 L2、L3 和最终问题组合进行 P0/P1/P2 优先级筛选。

**参数**：

| 参数 | 必填 | 说明 |
|------|------|------|
| `--type` | 是 | 品牌类型：个人/企业/产品/获客 |
| `--brand` | 是 | 品牌/产品名称 |
| `--company` | 否 | 企业名称 |
| `--keyword-type` | 否 | 产品词型策略：品牌+品类/纯品类/双轨 |
| `--file` | 否 | 知识库文件路径 |
| `--output` | 否 | 输出目录（默认 03_规划方案/） |
| `--format` | 否 | 输出格式：both/feishu/html |

**执行步骤**：

1. **确认品牌信息**：类型、名称、行业、产品名称、目标客户、核心转化目标
2. **生成L1品类入口**：列出用户可能使用的核心品类词簇，标注 L1-P0/P1/P2、业务相关性、筛选理由
3. **生成15个L2属性词**：在 L1 基础上加入人群、场景、地域、功能、卖点、价格、信任等属性，标注 L2-P0/P1/P2
4. **生成L3意图问题库**：每个L2下25-60个L3问题，采用推荐/价格/对比/靠谱/教程/避坑/案例/趋势等意图类型，标注 L3-P0/P1/P2
5. **生成组合优先级**：对 L1×L2×L3 组合计算最终优先级，输出 Top20/Top50 推荐问题、推荐内容类型、需要补充素材、适合平台
6. **输出筛选说明**：说明哪些由 AI 初筛，哪些需要人工业务判断，哪些建议用抖音/小红书/百度/行业平台等指数工具验证
7. **输出双版本文件**：飞书文档版(MD) + HTML美观版(含渐变色卡片式设计)
8. **可选转PNG**：调用html-to-png脚本

**15类分类体系（个人品牌示例）**：

- **P0必做**（5个）：身份认知、背景故事、基本信息、经营思想、经验分享
- **P1重点**（5个）：专业洞察、创业项目、深度内容、权威背书、曝光记录
- **P2补充**（5个）：思想传播、事迹展示、职业背景、商务合作、持续关注

> 企业品牌/产品品牌/获客各有对应的15/17类分类，结构与上述类似。

### 1.2 geo-keyword-builder — GEO三级问题生成器

**用途**：生成GEO查收录三级问题体系（L1品类词5个、L2属性词15个、L3意图问题50个），支持四大维度，输出Markdown并可直接导入查收录系统；每层均需标注 P0/P1/P2，并输出最终组合优先级。

**参数**：

| 参数 | 必填 | 说明 |
|------|------|------|
| `--brand` | 是 | 品牌名称 |
| `--dimension` | 否 | 维度：all/personal/enterprise/product/acquisition |
| `--founder` | 否 | 创始人姓名（personal维度需要） |
| `--product` | 否 | 产品名称（product维度需要） |
| `--acquisition-type` | 否 | 获客类型：通用搜索词/行业获客词 |
| `--level` | 否 | 层级：L1/L2/L3或组合（默认全部） |
| `--auto-import` | 否 | 自动导入查收录（默认false） |
| `--output-file` | 否 | 输出文件名 |

**四大维度**：

| 维度 | 说明 |
|------|------|
| `personal` | 个人品牌（创始人IP） |
| `enterprise` | 企业品牌（认知/实力/信誉） |
| `product` | 产品品牌（功能/效果/优势） |
| `acquisition` | 产品获客（通用搜索词，不带品牌） |

**执行步骤**：

1. 参数解析与验证（personal需founder，product需product）
2. 按维度生成 L1品类词(5个)+L2属性词(15个)+L3意图问题(50个)问题体系
3. 为 L1/L2/L3 分别标注 P0/P1/P2，并计算最终组合优先级
4. 格式化为标准Markdown（问题格式：`问题[{品牌词}]`），同时保留 L1/L2/L3/组合优先级字段
5. 文件保存 + 可选自动导入查收录系统（每批5个问题）

**输出格式**：`问题[{品牌词}]`，用于查收录系统自动检测。

### 1.3 build-intent-tree — 三级意图树构建

**用途**：构建品牌三级意图树的可视化结构（L1品类词 -> L2属性词 -> L3意图问题），输出树状图+层级关系表+优先级筛选表。该技能不只是“生成全量意图”，还要在生成时完成 AI 初筛：每个 L1/L2/L3 标注优先级，最终 L1×L2×L3 组合也标注 P0/P1/P2。

**参数**：

| 参数 | 必填 | 说明 |
|------|------|------|
| `--type` | 是 | 品牌类型：个人/企业/产品 |
| `--brand` | 是 | 品牌/产品名称 |
| `--company` | 否 | 企业名称 |
| `--industry` | 否 | 行业领域（默认自动推断） |
| `--output` | 否 | 输出目录（默认 03_规划方案/） |

**执行步骤**：

1. 确认品牌信息：品牌/产品、行业、目标客户、服务地域、转化目标、已有证据素材
2. 生成 L1 品类词簇：围绕品牌/产品/核心品类扩展用户可能搜索的品类入口，并标注 L1-P0/P1/P2
3. 生成 L2 属性词：在 L1 基础上叠加人群、场景、地域、功能、卖点、价格、信任等属性，并标注 L2-P0/P1/P2
4. 生成 L3 意图问题：在 L2 基础上叠加推荐、价格、对比、靠谱、教程、避坑、案例、趋势等用户意图，并标注 L3-P0/P1/P2
5. 生成组合优先级：对每个 L1×L2×L3 组合输出 `组合优先级`、`组合评分`、`推荐内容类型`、`需要补充素材`、`适合发布平台`
6. 生成可视化树状结构（ASCII树形图），树节点必须显示优先级，例如 `L2: 佛山工厂短视频获客 [P0]`
7. 生成层级关系表（CSV格式），字段至少包含：`L1品类词、L1优先级、L2属性词、L2优先级、L3意图问题、L3意图类型、L3优先级、组合优先级、组合评分、筛选理由、推荐内容类型、需补充素材、验证建议`
8. 输出四个文件：可视化版(MD)、详解版(MD)、层级表(CSV)、高价值问题Top表(MD/CSV)

**L2属性类型**：人群、场景、地域、功能、卖点、价格/预算、信任/口碑、痛点、服务方式、结果导向。

**L3意图类型**：推荐/哪家好、价格/性价比、对比/怎么选、靠谱/评价、教程/怎么做、避坑/风险、案例/效果、最新/趋势。

**优先级规则**：

| 层级 | P0 | P1 | P2 |
|---|---|---|---|
| L1品类词 | 核心业务入口，和转化强相关 | 相关业务入口，可扩展 | 泛品类/弱相关入口 |
| L2属性词 | 精准命中目标客户、成交场景或强痛点 | 有明确内容价值 | 偏泛、偏科普、弱转化 |
| L3意图问题 | 推荐、价格、对比、靠谱、怎么选、避坑等决策意图 | 教程、案例、效果等培育/信任意图 | 定义、科普、泛了解意图 |
| 组合优先级 | L1/L2/L3均为高价值，且有素材支撑 | 组合有价值但素材或需求待验证 | 可后续补充或长期培育 |

> 注意：技能输出的优先级是 AI 初筛结果，不等于最终答案。最终筛选还需要人工业务判断，并可结合抖音、小红书、百度、行业平台、电商平台等外部指数/热词数据验证。

## 二、标题创作

本模块包含两个子技能，用于基于 L1/L2/L3 意图树生成高召回、可点击、可审核的 GEO 标题。标题创作必须从“用户问题”出发，而不是只把关键词堆进标题。

核心链路：

```text
L1品类入口 + L2属性前缀 + L3用户意图
→ 判断用户问题类型
→ 匹配文章内容类型
→ 生成新闻式标题
→ 检查召回、点击、合规和证据支撑
```

---

### AI 召回视角下的标题原则

生成标题时必须记住：AI 不是只看标题是否好看，而是会把用户问题拆成多个关键词去匹配标题、摘要和正文。因此标题要尽量承担“可召回入口”的作用。

```text
用户问题
→ AI 拆成：时间词 + 人群/地域/场景 + 核心品类词 + 意图词 + 内容类型词
→ 全网匹配文章标题和正文
→ 召回候选内容
→ 综合生成答案
```

标题中尽量覆盖 6 类召回词：

| 召回词类型 | 作用 | 示例 |
|---|---|---|
| 时间词 | 提升时效性和最新感 | 2026年、最新、上半年、年度 |
| L1核心词 | 锁定品类入口 | GEO获客、AI数字人、短视频获客 |
| L2属性词 | 锁定人群/地域/场景/预算 | 中小企业、佛山、制造业、低预算 |
| L3意图词 | 匹配用户任务 | 推荐、价格、对比、避坑、靠谱吗、怎么选 |
| 内容类型词 | 匹配文章形态 | TOP5、榜单、测评、盘点、分析、报告、指南 |
| 专业限定词 | 提升正式感和可信度 | 服务商、解决方案、评价维度、筛选标准、落地路径 |

标题优先公式：

```text
专业正式标题 = 时间词 + L2属性词 + L1核心词 + 内容类型词 + L3意图/专业限定 + 信息增量
```

---

### 2.1 geo-title-generator — GEO标题生成专家

**用途**：基于一个或一组 P0/P1 用户问题生成新闻式 GEO 标题。输入优先使用意图树结果中的 `L1品类词、L2属性词、L3意图问题、组合优先级`，输出标题矩阵、标题评分、适合内容类型和合规检查。

**标题生成原则**：用户问题类型决定文章内容类型，文章内容类型决定标题类型。标题不是孤立创作，而是对 L3 用户问题的“新闻式回答入口”。AI 通常会把用户问题拆解成多个相关关键词，再去全网匹配文章标题和正文实现召回，所以标题必须服务“关键词拆解 → 标题匹配 → 内容召回”。标题不能浪费匹配词：要尽可能同时覆盖时间词、L1核心词、L2属性词、L3意图词、内容类型词和专业限定词。标题也不能只生成“怎么选/多少钱/靠谱吗”这类问题式标题；同一批标题必须覆盖榜单类、测评类、盘点类、洞察分析类、指南类、案例类、避坑类等多种样式，用「推荐、TOP、精选、测评、盘点、分析、报告、榜单、清单、指南」等可被 AI 搜索召回的内容类型词提升覆盖面，同时保持专业、正式、可信。

**标题生成公式**：

```text
标题 = 时间 + L2属性前缀 + L1核心关键词 + L3意图衍生词 + 内容类型词 + 信息增量
```

字段说明：

| 字段 | 说明 | 示例 |
|---|---|---|
| 时间 | 尽可能带上当前年份或明确时间，优先使用执行时当前年份；除非标题非常短或常青内容，否则不省略 | 2026年、最新、上半年、年度 |
| L2属性前缀 | 人群、场景、地域、功能、卖点、价格、信任、痛点等约束 | 佛山工厂、中小企业、性价比 |
| L1核心关键词 | 品类入口/核心业务词 | 短视频获客、GEO优化、数字人 |
| L3意图衍生词 | 推荐、价格、对比、靠谱吗、怎么选、避坑、案例、效果等 | 怎么做、哪家好、多少钱、靠谱吗 |
| 内容类型词 | 榜单、推荐、TOP、精选、测评、盘点、攻略、案例、价格、避坑、报告、指南、洞察、分析、清单等 | TOP5、精选榜单、深度测评、行业盘点、趋势分析 |
| 信息增量 | 数量、方法、维度、结论、适用对象、风险提醒 | 3类打法、5个误区、完整流程 |

**问题类型 → 内容类型 → 标题类型映射**：

| L3用户问题类型 | 推荐内容类型 | 可用标题样式/常用表达 |
|---|---|---|
| 推荐/哪家好 | 榜单、推荐、TOP、精选、测评 | `2026年[属性][核心词]推荐TOP5`、`[行业][核心词]精选榜单`、`[属性][核心词]服务商测评` |
| 价格/性价比 | 价格盘点、费用分析、性价比测评 | `2026年[属性][核心词]价格盘点`、`[核心词]费用构成分析`、`高性价比[核心词]方案测评` |
| 对比/怎么选 | 对比测评、横向盘点、选型指南 | `[A]和[B]对比测评`、`[属性][核心词]主流方案盘点`、`[核心词]选型指南` |
| 靠谱/评价 | 口碑盘点、可信度分析、案例拆解 | `[属性][核心词]口碑盘点`、`[核心词]靠不靠谱？看这几个判断标准`、`[行业]服务商可信度分析` |
| 教程/怎么做 | 操作指南、流程清单、实操攻略 | `[属性][核心词]实操指南`、`[核心词]落地流程清单`、`从0到1做[核心词]` |
| 避坑/风险 | 避坑清单、风险分析、误区盘点 | `[属性][核心词]避坑清单`、`[核心词]常见误区盘点`、`选择[核心词]前要注意的风险` |
| 案例/效果 | 案例复盘、效果分析、方法拆解 | `[属性][核心词]案例复盘`、`[核心词]效果分析`、`一个案例看懂[核心词]关键动作` |
| 最新/趋势 | 趋势报告、行业洞察、机会分析 | `2026年[行业][核心词]趋势报告`、`[核心词]行业洞察`、`[属性][核心词]机会分析` |

**标题形态库（必须混合使用）**：

生成一批标题时，不要全部做成疑问句。应根据关键词和内容承接能力，混合以下标题形态：

| 标题形态 | 适合场景 | 常用召回词 | 示例模板 |
|---|---|---|---|
| 榜单推荐型 | 用户问推荐/哪家好/服务商 | 推荐、榜单、TOP、精选 | `2026年[属性][核心词]推荐TOP5：适合[人群]的选择` |
| 横向测评型 | 多品牌/多方案比较 | 测评、评测、对比、横评 | `[核心词]服务商测评：从案例、交付和价格看差异` |
| 盘点清单型 | 行业选择多、信息分散 | 盘点、清单、汇总、合集 | `[行业][核心词]服务商盘点：这几类公司适合不同企业` |
| 洞察分析型 | 行业趋势、平台变化、底层逻辑 | 洞察、分析、趋势、报告 | `2026年[核心词]趋势分析：企业为什么要提前布局` |
| 选型指南型 | 用户要决策但不清楚标准 | 指南、标准、方法、流程 | `[属性][核心词]选型指南：5个关键标准和避坑点` |
| 避坑风控型 | 用户担心踩坑/被骗/效果差 | 避坑、风险、误区、注意事项 | `[核心词]避坑清单：企业合作前要看清的4个问题` |
| 案例复盘型 | 有案例、过程、结果或方法论 | 案例、复盘、拆解、实战 | `[属性][核心词]案例复盘：从问题到落地的关键动作` |
| 价格成本型 | 价格、预算、套餐、成本 | 价格、费用、成本、预算 | `[核心词]费用分析：不同预算适合哪类方案` |
| 问题回答型 | 用户问题非常明确 | 怎么选、多少钱、靠谱吗、怎么做 | `[属性][核心词]怎么选？企业筛选合作方的5个关键标准` |

**标题多样性硬规则**：

- 一次生成 5 个标题：至少使用 3 种不同标题形态。
- 一次生成 10 个标题：至少使用 5 种不同标题形态。
- 同一批标题中，以“怎么选/怎么买/多少钱/靠谱吗/怎么做”开头或结尾的标题不得超过 40%。
- 榜单/推荐类标题必须自然包含 `推荐`、`TOP`、`精选`、`榜单`、`盘点`、`测评` 等召回词之一。
- 洞察/分析类标题必须自然包含 `趋势`、`洞察`、`分析`、`报告`、`机会` 等召回词之一。
- 不要为了多样性牺牲准确性：标题中的 TOP、排名、价格、案例、数据必须有资料支撑；没有资料时用“盘点/精选/参考/判断标准”替代绝对排名。

**标题输出字段**：

| 字段 | 说明 |
|---|---|
| L1品类词 | 来自意图树的核心品类入口 |
| L2属性词 | 人群/场景/地域/预算/功能/卖点/痛点/信任等属性 |
| L3意图问题 | 用户真实问题或问题词 |
| 问题类型 | 推荐/价格/对比/靠谱/教程/避坑/案例/趋势等 |
| 内容类型 | 榜单/评测/对比/攻略/案例/价格/避坑/报告等 |
| 新闻式标题 | 最终可用标题 |
| 标题形态 | 榜单推荐型/横向测评型/盘点清单型/洞察分析型/选型指南型/避坑风控型等 |
| 召回关键词覆盖 | 时间词、L1核心词、L2属性词、L3意图词、内容类型词、专业限定词是否覆盖 |
| 召回评分 | 关键词覆盖、意图覆盖、语义清晰度、标题可点击性 |
| 合规检查 | 是否存在绝对化、夸大、虚假承诺或不可验证数据 |
| 适合形式 | 图文/视频/都适合 |
| 标题优先级 | P0/P1/P2，参考组合优先级和内容证据充分度 |

**标题质量评估**：

```text
召回评分 = L1核心词覆盖 x 2 + L2属性覆盖 x 1.5 + L3意图覆盖 x 2 + 同义词/相关词覆盖 x 1
点击评分 = 问题明确度 x 2 + 信息增量 x 1.5 + 内容类型清晰度 x 1 + 时间新鲜度 x 1
可信评分 = 可验证数据/案例/流程支撑 x 2 + 避免夸大 x 1 + 与知识库一致 x 2
综合评分 = 召回评分 + 点击评分 + 可信评分
```

**三档字数适配**：

| 档位 | 风格 | 字数 | 适合问题 |
|------|------|------|---------|
| 标准档 | 直接回答型 | 18-28字 | 价格、靠谱吗、怎么做、哪家好 |
| 深度档 | 分析解释型 | 24-38字 | 对比、选型、避坑、案例复盘 |
| 旗舰档 | 权威报道型 | 26-42字 | 报告、趋势、行业指南、白皮书 |

**新闻式标题模式**：

| 模式 | 公式 |
|------|------|
| 榜单推荐型 | `[年份]年[属性][核心词]推荐TOP5：适合[人群/场景]的选择` |
| 精选盘点型 | `[行业/地域][核心词]精选盘点：不同类型企业怎么选` |
| 横向测评型 | `[属性][核心词]服务商测评：从案例、交付和价格看差异` |
| 深度分析型 | `[年份][行业][核心词]深度分析：机会、变化和落地建议` |
| 趋势报告型 | `[年份][行业][核心词]趋势报告：企业为什么要提前布局` |
| 最新指南型 | `[年份]年[属性][核心词]指南：[意图问题]怎么解决？` |
| 问题回答型 | `[属性][核心词][意图词]？[判断维度/解决方法]` |
| 对比评测型 | `[A]和[B]对比测评：[年份][核心词]怎么判断更适合` |
| 价格拆解型 | `[年份][属性][核心词]费用分析：价格构成和避坑点` |
| 案例复盘型 | `[属性][核心词]案例复盘：一个项目看关键动作` |
| 风险提醒型 | `[属性][核心词]避坑清单：合作前先看这几个问题` |

**专业正式感要求**：

- 优先使用“服务商、解决方案、评价维度、筛选标准、落地路径、趋势报告、行业洞察、深度测评、精选盘点”等正式表达。
- 少用过于口语化或标题党表达，例如“别再乱选了”“看完就懂”“太坑了”。
- 可以保留用户会问的意图词，但要用专业结构承接，例如把“怎么选”升级为“筛选标准/评价维度/选型指南”。
- 标题要像一篇可被 AI 引用的专业文章，而不是短视频口播标题。

**注意事项**：
- 标题必须优先服务用户问题，不要只堆核心关键词。
- 不要批量生成同一种“问题式标题”。标题必须有形态变化：榜单、测评、盘点、洞察、分析、指南、案例、避坑、价格等交替使用。
- 标题尽可能包含当前年份或明确时间（按执行时当前年份，例如 2026），并覆盖 L2属性前缀、L1核心关键词、L3意图词和内容类型词。
- 数据、案例、排名、价格区间必须来自知识库或可验证来源；无法验证时用“影响因素/判断方法/参考维度”替代。
- 避免“最、第一、唯一、保证、100%”等绝对化或不可证明表述。
- `TOP5/TOP10` 可以用于“候选清单/盘点/测评”表达，但不能伪造权威排名；资料不足时写“推荐参考/精选盘点/测评清单”。
- 标题长度不机械限制在30字以内；图文标题可 18-42 字，报告/指南/洞察分析类可适度更长，但必须清晰可读、专业正式。

### 2.2 geo-aggregate-title — GEO聚合标题生成器

**用途**：将多个 L1/L2/L3 用户问题聚合为少量高召回新闻式标题，实现多问题对一篇内容的覆盖，降低创作成本。聚合时必须保留主问题和被覆盖问题，避免为了覆盖过多而导致标题泛化。

**参数**：

| 参数 | 必填 | 说明 |
|------|------|------|
| `--plan` | 否 | GEO方案文件路径，优先使用含 L1/L2/L3 和组合优先级的意图树文件 |
| `--keywords` | 否 | 关键词/问题列表（逗号分隔） |
| `--brand` | 是 | 品牌/产品名称 |
| `--type` | 是 | 品牌类型：个人/企业/产品 |
| `--strategy` | 否 | 聚合策略：意图聚合/场景聚合/人群聚合/对比聚合 |
| `--ratio` | 否 | 聚合比（默认3-5:1；P0问题不建议过度聚合） |
| `--output` | 否 | 输出目录（默认 03_规划方案/标题方案/） |

**核心原理 — AI召回双路径**：

| 路径 | 原理 | 优化策略 |
|------|------|---------|
| 关键词匹配（字面召回） | AI提取问题关键词匹配标题 | 标题覆盖 L1核心词、L2属性词、L3意图词、同义词变体 |
| 语义向量匹配（语义召回） | 问题和文章转为向量计算相似度 | 标题和正文共同覆盖问题场景、决策维度、证据链 |

**L1/L2/L3词根组合框架**：

| 维度 | 类型 | 作用 |
|------|------|------|
| A. L1品类词 | 产品词、服务词、品牌词、行业词 | 锁定基础流量入口 |
| B. L2属性词 | 人群、场景、地域、功能、卖点、价格、信任、痛点 | 筛选精准流量和成交场景 |
| C. L3意图词 | 推荐、价格、对比、靠谱、教程、避坑、案例、趋势 | 明确用户问题和内容任务 |

**四种聚合策略**：

| 策略 | 适用场景 | 公式 |
|------|---------|------|
| 意图聚合 | 同一 L1/L2 下多个相近 L3 意图 | `[年份]+[L2属性]+[L1核心词]+[主意图]+[内容类型]+[信息增量]`，内容类型可用推荐/测评/盘点/指南/清单 |
| 场景聚合 | 同一核心词的多个使用场景 | `[年份]+[场景组]+[L1核心词]+[精选/盘点/指南/案例]+[信息增量]` |
| 人群聚合 | 同一产品的不同目标人群 | `[年份]+[人群组]+[L1核心词]+[推荐/测评/避坑/案例]+[判断标准]` |
| 对比聚合 | 多个方案/品牌/产品被一起比较 | `[A/B/替代方案]+对比测评：+[年份]+[L1核心词]+[判断维度]` |
| 榜单聚合 | 多个推荐类问题可由一篇文章覆盖 | `[年份]+[属性]+[L1核心词]+推荐TOP/精选榜单/服务商盘点` |
| 洞察聚合 | 多个趋势、变化、机会类问题可由一篇文章覆盖 | `[年份]+[行业]+[L1核心词]+趋势分析/行业洞察/机会报告` |

**执行步骤**：

1. 读取输入问题，提取 L1品类词、L2属性词、L3意图词和组合优先级。
2. 先保留 P0 主问题，再判断哪些 P1/P2 问题可以被同一标题和正文自然覆盖。
3. 按意图、场景、人群或对比分组，确定每组的主问题、覆盖问题和不适合聚合的问题。
4. 按新闻式标题公式生成标题，确保标题含时间、核心词、属性前缀、意图词和信息增量。
5. 做标题形态去重：同一批聚合标题必须混合推荐榜单、横向测评、盘点清单、洞察分析、选型指南、避坑清单等形态，不能全部是“怎么选/多少钱/靠谱吗”。
6. 做召回验证：L1/L2/L3覆盖检查 + 内容类型召回词检查 + 语义覆盖评估 + 证据支撑检查 + 合规检查。
7. 输出聚合标题表、覆盖问题清单、未覆盖问题清单、召回分析和使用建议。

### 标题创作技能对比

| 技能 | 核心输出 | 特色 | 适用场景 |
|------|---------|------|---------|
| `geo-title-generator` | 单个/少量用户问题 -> 新闻式标题矩阵 | 问题类型→内容类型→标题类型，含L1/L2/L3覆盖和优先级 | 单篇标题创作、P0问题标题打磨 |

## 三、图文转短视频文案

本模块用于把已经生成并审核过的 GEO 图文内容，改写成 1-5 分钟短视频口播文案。短视频文案必须继承前面的 GEO 内容逻辑：从 L1/L2/L3 用户问题出发，用新闻式标题承接用户意图，再用口语化表达完成解释、证据和行动引导。

核心链路：

```text
P0用户问题 + 新闻式标题 + 审核后图文
→ 提取核心结论、判断标准、证据和FAQ
→ 改写成 1-5 分钟短视频口播
→ 输出标题、钩子、脚本、分镜、封面文字、发布文案
```

---

### 3.1 geo-short-video-script — GEO图文转短视频文案

**用途**：将一篇审核后的 GEO 图文，转成适合真人口播、数字人、视频号/抖音/小红书/B站等平台使用的短视频文案。默认生成 1-5 分钟版本，可按平台和讲解深度输出 1分钟、3分钟、5分钟三个版本。

**输入优先级**：

| 输入 | 必填 | 说明 |
|---|---|---|
| 审核后图文 | 是 | 必须优先使用已通过事实关/GEO关/合规关的图文稿 |
| L1品类词 | 建议 | 用于锁定主题和关键词召回 |
| L2属性词 | 建议 | 用于承接人群、场景、地域、预算、痛点 |
| L3意图问题 | 是 | 用户真实问题，决定短视频开头和主体结构 |
| 新闻式标题 | 建议 | 作为视频标题或封面文案的基础 |
| 证据素材 | 建议 | 案例、数据、截图、客户反馈、流程、资质；没有则标注待补充 |
| 平台 | 否 | 抖音/视频号/小红书/B站/官网/数字人，影响语气和长度 |
| 时长 | 否 | 1分钟/3分钟/5分钟，默认生成 1-5 分钟可选版本 |

**短视频文案结构**：

| 结构 | 作用 | 要求 |
|---|---|---|
| 前5秒钩子 | 让用户知道“这条和我有关” | 直接说出 L3 用户问题或痛点，不要寒暄 |
| 场景代入 | 锁定目标人群和场景 | 对应 L2 属性，例如人群、地域、预算、痛点 |
| 核心结论 | 先给答案 | 用一句话回答用户问题，避免铺垫过长 |
| 3-5个观点 | 展开正文 | 来自图文中的判断标准、步骤、对比、避坑、FAQ |
| 证据/案例 | 提升可信度 | 只能使用知识库或图文已有证据，不能编造 |
| 总结行动 | 引导下一步 | 整理清单、对照检查、私信咨询、预约诊断、保存转发 |

**时长控制**：

| 版本 | 字数参考 | 适合场景 | 结构建议 |
|---|---:|---|---|
| 1分钟版 | 250-350字 | 抖音/视频号/小红书短内容 | 1个钩子 + 3个观点 + 1个行动引导 |
| 3分钟版 | 700-1000字 | 深度口播/数字人讲解 | 1个钩子 + 4个观点 + 1个案例/对比 + 行动引导 |
| 5分钟版 | 1200-1600字 | B站/官网/课程切片/深度解释 | 1个钩子 + 5个观点 + 表格口播化 + FAQ + 行动引导 |

**问题类型 → 视频表达方式**：

| L3问题类型 | 视频内容类型 | 表达重点 |
|---|---|---|
| 推荐/哪家好 | 选型建议/榜单解释 | 讲清选择标准，不直接虚假排名 |
| 价格/性价比 | 费用拆解/预算建议 | 讲费用构成、影响因素和避坑 |
| 对比/怎么选 | 对比评测 | 用“适合谁/不适合谁”讲清差异 |
| 靠谱/评价 | 信任解释/案例拆解 | 用流程、案例、评价、资质证明，不夸大 |
| 教程/怎么做 | 步骤教学 | 按第一步、第二步、第三步讲清楚 |
| 避坑/风险 | 风险提醒 | 先提醒常见误区，再给判断方法 |
| 案例/效果 | 案例复盘 | 讲背景、动作、结果、可复制点 |
| 最新/趋势 | 趋势解读 | 讲变化、机会、建议，避免空泛预测 |

**输出字段**：

| 字段 | 说明 |
|---|---|
| 视频标题 | 可用于发布标题，建议含核心词/问题词/场景词 |
| 封面文字 | 8-16字，突出问题或结果，不夸大 |
| 前5秒钩子 | 直接击中 L3 用户问题 |
| 口播脚本 | 1-5分钟正文，口语化、分段清楚 |
| 分镜建议 | 适合真人/数字人/产品画面/截图/表格/案例图 |
| 字幕重点 | 便于剪辑时突出关键词和金句 |
| 发布文案 | 平台发布说明，含关键词标签 |
| 证据缺口 | 哪些案例/数据/截图需要课后补充 |
| 合规提醒 | 不可直接发布或需要改写的高风险表达 |

**写作规则**：
- 必须基于审核后的图文改写，不要脱离原文重写成泛泛短视频鸡汤。
- 必须保留 L1核心词、L2属性场景、L3用户意图，确保短视频仍能反向支撑 GEO 召回。
- 语言要口语化，像老板/顾问在解释问题，不像论文和广告软文。
- 不编造案例、数据、排名、客户评价、价格承诺；没有证据时写“这里可以补充真实案例/数据”。
- 避免“最强、第一、唯一、保证、100%有效”等绝对化表达。
- 结尾行动要自然，不要强硬销售；优先引导用户整理问题清单、对照检查、预约诊断或查看完整图文。

**推荐提示词**：

```text
请调用 GEO 图文转短视频文案能力，把下面这篇已经审核优化过的GEO图文，改写成 1-5 分钟短视频口播文案。

要求：
1. 先识别 L1品类词、L2属性词、L3用户意图和问题类型。
2. 短视频要继承原图文的逻辑：用户问题 → 核心结论 → 判断标准/步骤/对比/避坑 → 证据 → 行动引导。
3. 默认输出 1分钟版、3分钟版、5分钟版三个可选版本。
4. 每个版本都要有：视频标题、封面文字、前5秒钩子、口播脚本、分镜建议、字幕重点、发布文案、关键词标签。
5. 不能编造案例、数据、价格、排名或客户评价；缺少证据请标注“待补充证据”。
6. 语言口语化，适合真人口播或数字人，不要像文章朗读。

L1品类词：{填写或让AI识别}
L2属性词：{填写或让AI识别}
L3用户问题：{填写P0问题}
新闻式标题：{填写最终标题}
目标平台：{抖音/视频号/小红书/B站/数字人，可选}

审核后图文：
{粘贴文章}
```

## 四、图片生成

本模块包含两个子技能，用于GEO文章配图和封面生成。

### 4.1 geo-image-generation — GEO 平台文生图

**用途**：基于 GEO 平台 API `POST /v1/text-to-img` 创建文生图任务，用于 GEO 文章封面、配图、产品展示图和素材库图片。该入口已替代旧外部图片直连接口。

**脚本路径**：`geo-content-production/scripts/generate_image.js`（相对于 GEO Skills Suite 根目录；若从本技能目录解析，则为 `scripts/generate_image.js`）

**底层接口**：

| 步骤 | 接口 | 说明 |
|---|---|---|
| 创建任务 | `POST /v1/text-to-img` | 返回任务 `id` 和初始 `status` |
| 查询结果 | `GET /v1/text-to-img?page=1&limit=20&companyId=...&productId=...` | 轮询到 `status=3` 后读取 `resourceUrls` |
| OSS 转存 | `POST /v1/oss/pre` + OSS 表单上传 | 默认先下载 `resourceUrls` 到本地临时文件，再上传到 GEO OSS，并逐个验证新 OSS URL |

**认证与配置**：与其他 GEO 平台技能一致，统一从 `~/.geo-skills/credentials/geo-config.json` 读取：

```json
{
  "geo": {
    "baseUrl": "<内部接口地址>",
    "openKey": "...",
    "referer": "https://geo.bihuoai.com/"
  },
  "defaults": {
    "companyId": 36,
    "productId": 409
  }
}
```

请求头统一使用：

```bash
Authorization: Bearer ${geo.openKey}
Referer: ${geo.referer}
Content-Type: application/json; charset=utf-8
```

**默认参数**：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `model` | `v2` | 默认使用效果更好的 v2，约 2 倍积分；可显式传 `--model v1` |
| `resolution` | `1k` | 当前平台前端默认值 |
| `num` | `1` | 生成张数 |
| `aspectRatio` | `16:9` | 适合文章封面/横版配图；可选 `1:1`、`9:16` 等 |
| `oss-mode` | `local` | 默认本地转存：下载 provider 图片 → `/v1/oss/pre` 获取签名 → OSS 表单上传 → HTTP 验证；可选 `auto`/`translate`/`none` |
| `wait` | 开启 | 创建任务后轮询直到完成或超时 |
| `interval-ms` | `5000` | 初始轮询间隔，脚本会逐步退避，兼顾速度和接口压力 |
| `max-interval-ms` | `15000` | 最大轮询间隔 |

**支持的画幅**：`16:9`、`9:16`、`1:1`、`4:3`、`3:4`、`3:2`、`2:3`、`21:9`。

**返回结果格式**：

创建任务时只返回任务信息：

```json
{
  "statusCode": 0,
  "message": "success",
  "data": {
    "id": 100,
    "status": 2
  }
}
```

轮询完成后，图片 URL 在 `resourceUrls` 字段；脚本默认通过本地转存链路输出 `ossUrls`：

```json
{
  "id": 100,
  "status": 3,
  "resourceUrls": ["https://p4-fdl.klingai.com/...png?..."],
  "ossUrls": ["https://bihuogeo.oss-cn-shanghai.aliyuncs.com/img/..."]
}
```

**命令示例**：

```bash
# 不消耗积分地检查默认 payload（默认 model=v2）
node geo-content-production/scripts/generate_image.js \
  --prompt "检查配置" \
  --dry-run

# 默认 model=v2，生成横版文章配图，等待完成并输出 OSS URL
node geo-content-production/scripts/generate_image.js \
  --prompt "必火AI科技感封面图，蓝色渐变背景，商业插画风格，无文字" \
  --aspect-ratio 16:9 \
  --json-out outputs/geo-image-result.json

# 下载第一张图片到本地文件
node geo-content-production/scripts/generate_image.js \
  --prompt "GEO优化服务流程信息图，科技感，无文字" \
  --output outputs/cover.png

# 在 GEO 项目中生成配图：自动写入 04_内容创作/{日期}/images/
node geo-content-production/scripts/generate_image.js \
  --prompt "GEO优化服务流程信息图，科技感，无文字" \
  --project-dir "项目_品牌GEO"

# 低成本测试：显式使用 v1，不等待完成
node geo-content-production/scripts/generate_image.js \
  --prompt "测试图" \
  --model v1 \
  --no-wait
```

**图片定位与内容策略**（核心原则）：

生成图片前必须回答：**为谁生成？放在哪？图片内容是什么？**

1. **为谁生成**：识别 GEO 客户品牌（从项目目录/知识库/文章中出现频次最高的正面品牌）。
2. **放在哪**：围绕客户品牌布局（首图、品牌段前/后、对比段、推荐表上方、总结段前）。
3. **图片内容**：从文章实际内容提取，prompt = `[客户品牌产品] + [具体技术/特征] + [具体数据/成就] + [风格描述]`。

**OSS 转存规则（重要）**：
- 默认使用 `--oss-mode local`：先把 `resourceUrls` 下载到本地临时文件，再用 `/v1/oss/pre` 获取上传签名，随后上传到 GEO OSS。
- 上传后必须逐个验证新 OSS URL，确认返回 HTTP 200/206 后再写入 `ossUrls`。
- 不要默认依赖 `/v1/oss/translate-url` 直接镜像 Kling 长签名图片 URL；这类 URL 可能过长且带复杂签名，接口可能不报错但返回 `null`。
- 如需兼容旧链路，可传 `--oss-mode auto`：先尝试 `translate-url`，失败、返回空或验证失败时自动回退本地上传。
- `--oss-mode translate` 仅用于低级调试，不作为封面/正文图文默认方案。

**关键规则**：
- 客户品牌出现位置附近必须有图片.
- 不要在竞品段落放图，避免为竞品引流。
- GEO 文章最终优先使用 `ossUrls` 中的 GEO OSS 绝对链接：`![](https://bihuogeo.oss-cn-shanghai.aliyuncs.com/...)`。
- 不再要求单独的图片 API Key；不要再配置或调用旧外部图片直连接口。

**状态约定**：
- `status=2`：已提交/处理中。
- `status=3`：生成成功，可读取 `resourceUrls`。
- 非处理中且非成功时，读取 `failReason` 排查。

### 4.2 generate-cover — GEO 文章封面生成

**用途**：为 GEO 文章生成封面图片。默认走 GEO 平台 `POST /v1/text-to-img`，不再使用本地 SVG/模板 fallback。

**推荐脚本路径（无 Python）**：`geo-content-production/scripts/generate_cover.js`

**核心原则**：
- 封面必须是可直接用于公众号、网页、GEO 文章和飞书文档的图片 URL 或 PNG/JPG 文件。
- 不输出 SVG 作为默认结果，因为 SVG 在发布链路中兼容性不足。
- 默认模型为 `v2`，默认画幅为 `16:9`。
- 生成完成后优先使用脚本返回的 `ossUrls`，也可以通过 `--output` 下载本地图片。

**底层流程**：

```text
title/subtitle/keywords/brand
→ 组装封面 prompt
→ 调用 geo-content-production/scripts/generate_image.js
→ POST /v1/text-to-img 创建任务
→ 轮询 status=3
→ 读取 resourceUrls
→ 默认下载到本地临时文件
→ `/v1/oss/pre` 获取签名并上传到 GEO OSS
→ 验证新 OSS URL 后输出 ossUrls
```

**命令行用法**：

```bash
# 生成封面并返回 OSS URL（默认 model=v2）
node geo-content-production/scripts/generate_cover.js \
  --title "2026年GEO优化服务商推荐TOP5" \
  --brand "必火AI" \
  --keywords "GEO优化,AI搜索,服务商推荐" \
  --json-out covers/cover_01_result.json

# 同时下载第一张封面到本地 PNG
node geo-content-production/scripts/generate_cover.js \
  --title "2026年壁挂炉推荐TOP10" \
  --brand "客户品牌名" \
  --output covers/cover_01.png

# 在 GEO 项目中生成封面：自动写入 04_内容创作/{日期}/covers/
node geo-content-production/scripts/generate_cover.js \
  --title "2026年GEO优化服务商推荐TOP5" \
  --brand "必火AI" \
  --project-dir "项目_必火AIGEO"

# 不消耗积分检查 prompt/payload
node geo-content-production/scripts/generate_cover.js \
  --title "2026年GEO优化服务商推荐TOP5" \
  --brand "必火AI" \
  --dry-run
```

**参数**：

| 参数 | 必填 | 说明 |
|------|------|------|
| `--title` | 是 | 文章标题；也可直接传 `--prompt` 覆盖自动组装 |
| `--subtitle` | 否 | 副标题/核心卖点 |
| `--keywords` | 否 | 关键词，逗号分隔 |
| `--brand` | 否 | 客户品牌/产品名，建议填写 |
| `--style` | 否 | commercial/tech/clean/product，默认 commercial |
| `--aspect-ratio` | 否 | 默认 16:9 |
| `--model` | 否 | 默认 v2，可传 v1 降低消耗 |
| `--output` | 否 | 下载第一张结果图到本地文件 |
| `--project-dir` | 否 | GEO 项目根目录；未传 `--output` 时，封面自动写入 `04_内容创作/{日期}/covers/` |
| `--json-out` | 否 | 保存完整 JSON 结果 |
| `--dry-run` | 否 | 只检查 payload，不创建任务 |

**封面 prompt 规范**：
- 必须围绕客户品牌和文章主题生成。
- 避免竞品品牌 logo、二维码、水印和乱码文字。
- 标题文字不强依赖 AI 直接绘制；如需文字，建议后期在发布平台或设计工具中叠加。
- 榜单/推荐/测评类封面要突出“专业、可信、干净”，不要做夸张标题党视觉。

**批量封面建议**：
- 使用短文件名，例如 `cover_01.png`、`cover_02.png`。
- 批量时建议保存 `json-out`，用其中的 `ossUrls` 映射文章标题。
- 如果需要严格的一一映射，可由上层工作流生成 `cover_mapping.json`。

**执行步骤**：

1. 从标题/关键词/品牌提取封面主题。
2. 组装高质量封面 prompt。
3. 调用 GEO 平台文生图，默认 `model=v2`、`aspectRatio=16:9`。
4. 轮询完成后读取 `resourceUrls`，默认通过“本地下载 + `/v1/oss/pre` 上传 + URL 验证”生成 `ossUrls`。
5. 文章中优先使用 `ossUrls`：`![](https://bihuogeo.oss-cn-shanghai.aliyuncs.com/...)`。
