# GEO 证据链分析

> **技能名称**：geo-evidence-chain
> **用途**：分析 AI 平台引用来源的分布规律，评估证据链完整性，生成发布策略矩阵
> **版本**：v1.1
> **更新日期**：2026-05-08
> **归属入口**：`geo-workflow-hub` > 4.5 内容审核与优化

---

## 核心理念

AI 是"千人千面"的。不同用户问不同 AI 平台同一个问题，AI 引用的信息来源完全不同。每个 AI 平台有自己独特的"证据链补全逻辑"——它需要什么类型的来源、多少种来源、什么权威级别的来源，才会"有信心"推荐一个品牌。

本技能从收录检测结果中提取 AI 实际引用的来源数据，分析各平台的引用偏好和证据链补全规律，反推出精准的发布策略，形成 GEO 项目闭环。

### 闭环全景

```
关键词规划 → 内容创作 → 内容发布 → 收录监测
    ↓
证据链分析（本技能）
    ↓
发布策略调整 → 内容优化 → 重新发布 → 收录监测 → ...
```

---

## 触发场景

在以下场景调用本技能：

- 收录监测完成后，需要分析 AI 引用了哪些来源
- 想了解各 AI 平台的引用偏好差异
- 需要确定下一步内容应该发布到哪些平台
- 需要评估当前证据链的完整度和薄弱环节
- 需要生成精准的发布策略矩阵指导下一步行动

---

## 六步分析框架

### 第一步：数据采集

从 GEO 平台拉取所有收录检测结果：

**API**：`GET /v1/ai-indexing/custom`

**提取字段**：
- `topic`：查询的问题
- `platform`：AI 平台（deepseek/doubao/yuanbao/qwen/yiyan）
- `content`：AI 的完整回答
- `searchedSite[]`：引用的信息来源列表
  - `url`：来源链接
  - `title`：文章标题
  - `platform`：来源域名
  - `indexed`：是否被 AI 实际采纳

### 第二步：来源分类

通过域名模式匹配，将所有引用 URL 分类为 8 种来源类型：

| 来源类型 | 典型域名 | 权重 | 说明 |
|---------|---------|------|------|
| **专业汽车平台** | pcauto, yiche, autohome, dongchedi, 58che | 0.30 | 汽车垂直领域权威来源 |
| **权威媒体/新闻** | sohu, qq, 163, ifeng, people, xinhua | 0.25 | 主流媒体背书 |
| **论坛/社区** | club.autohome, tieba, zhihu | 0.15 | 用户真实讨论声音 |
| **自媒体/公众号** | mp.weixin.qq.com | 0.10 | 深度内容（仅元宝引用） |
| **评测/导购** | smzdm, chinapp, maigoo | 0.10 | 消费决策参考 |
| **百科/知识库** | baike.baidu | 0.08 | 基础认知构建 |
| **内容聚合/百家号** | baijiahao, toutiao, jd, taobao | 0.07 | 流量型聚合平台 |
| **品牌官网** | 从 `--brand-domains` 参数读取 | 0.05 | 品牌自有阵地 |

**分类规则**（按优先级）：
1. URL 模式匹配（如 `mp.weixin.qq.com`）
2. 精确域名匹配（如 `pcauto.com.cn`）
3. 父域名匹配（如 `club.autohome.com.cn` → `autohome.com.cn`）
4. 兜底归类为"其他/未知"

### 第三步：平台证据画像

**数据源选择**：

- 如果提供了 `--platform-profiles` 参数：
  1. 读取指定的平台画像文件（支持单个文件路径、逗号分隔多文件、或目录路径）
  2. 从 YAML front matter 提取元数据（`platform`、`generated_at`、`sample_size`、`confidence`）
  3. 检查画像时效性：若 `generated_at` 距今超过 90 天，发出警告"⚠️ {平台}画像已过期（生成于{date}），建议重新运行 `geo-platform-reverse`"
  4. 从 Markdown 正文的"来源类型分布"章节读取各来源类型的占比和偏好度
  5. 从"交叉验证模式"章节读取策略类型和关键指标
  6. 使用动态数据替代下方硬编码表
  7. 若某个平台的画像文件缺失或解析失败，回退到下方硬编码默认值并标注
- 如果未提供：使用下方基于实证数据的硬编码表（v1.0 默认）

---

**硬编码默认表**（当未提供 `--platform-profiles` 时使用）：

为每个 AI 平台建立"引用性格画像"，基于实证数据分析：

| 平台 | 引用性格 | 偏好来源类型 | 独有特征 |
|------|---------|-------------|---------|
| **文心一言** | 权威偏好型 | 专业汽车平台(50%) + 权威媒体(29%) | 不引用公众号、不引用品牌官网 |
| **元宝** | 腾讯生态型 | 其他(50%) + 自媒体/公众号(18%) | **唯一引用微信公众号的平台** |
| **千问** | 用户声音+专家型 | 专业汽车(37%) + 论坛/社区(25%) | 不引用公众号、不引用品牌官网 |
| **豆包** | 专家+社区型 | 专业汽车(39%) + 论坛/社区(23%) | 不引用公众号 |
| **DeepSeek** | 最多元型 | 其他(41%) | 来源最分散、最不可预测 |

### 第四步：证据链完整性评分

对每个 `(问题, 平台)` 对计算四维评分：

```
EvidenceScore = 多样性(30%) + 权威性(30%) + 收录率(25%) + 品牌存在感(15%)
```

| 维度 | 权重 | A(优秀) | B(良好) | C(不足) | D(薄弱) |
|------|------|---------|---------|---------|---------|
| 多样性 | 30% | ≥4种来源类型 | 3种 | 2种 | 0-1种 |
| 权威性 | 30% | 高权重来源≥60% | 40-60% | 20-40% | <20% |
| 收录率 | 25% | ≥20% | 10-20% | 1-10% | 0% |
| 品牌存在感 | 15% | ≥60%来源提及品牌 | 40-60% | 20-40% | <20% |

**综合评级**：A(80-100) / B(60-79) / C(40-59) / D(0-39)

### 第五步：缺口识别

对 C/D 评级的 `(问题, 平台)` 对识别具体缺口：

| 缺口类型 | 检测规则 | 紧迫度 |
|---------|---------|--------|
| **平台偏好类型缺失** | 该平台最偏好的来源类型=0 | ⚠️ 最高 |
| **收录率为零** | indexed=true 数=0 | ⚠️ 最高 |
| **权威来源缺失** | 无权威媒体/专业平台来源 | 高 |
| **社区声音缺失** | 无论坛/社区来源 | 中 |
| **品牌官网缺失** | 无品牌自有域名来源 | 中 |
| **百科基础缺失** | 无百科/知识库来源 | 低 |

### 第六步：发布策略矩阵

基于缺口分析和各平台引用偏好，生成精准的"内容→渠道→平台"映射：

**核心映射表**（基于实证数据）：

| 目标 AI 平台 | 应发布到哪些渠道 | 内容类型建议 |
|-------------|---------------|-------------|
| 文心一言 | pcauto、sohu、qq、163 | 专业评测、品牌介绍、新闻稿 |
| 元宝 | 微信公众号、头条号 | 公众号深度文、头条号文章 |
| 千问 | club.autohome、tieba、pcauto | 论坛帖子、专业评测、用户讨论 |
| 豆包 | pcauto、club.autohome、autohome | 专业评测、社区讨论、导购 |
| DeepSeek | sohu、smzdm、zhihu | 深度分析、导购评测、知识分享 |

## 使用方法

### 方式1：完整分析（推荐）

```
/skill geo-evidence-chain --company="多耐,DN" --keyword-map="03_GEO方案/多耐减振器GEO关键词映射表.md"
```

### 方式2：指定平台分析

```
/skill geo-evidence-chain --company="多耐,DN" --platform="yiyan"
```

### 方式3：快速模式（仅摘要+策略矩阵）

```
/skill geo-evidence-chain --company="多耐,DN" --quick
```

### 方式4：指定输出目录

```
/skill geo-evidence-chain --company="多耐,DN" --output="06_策略/"
```

## 参数说明

| 参数 | 必填 | 默认值 | 说明 |
|------|------|--------|------|
| `--company` | 是 | - | 目标品牌名，逗号分隔别名（如 `多耐,DN`） |
| `--company-id` | 否 | 36 | 公司 ID |
| `--platform` | 否 | 全部 | 筛选特定平台（deepseek/doubao/yuanbao/qwen/yiyan） |
| `--topic` | 否 | 全部 | 筛选问题关键词（模糊匹配） |
| `--keyword-map` | 否 | - | 关键词映射表路径（含核心词→拓展词→问题层级） |
| `--output` | 否 | `06_策略/` | 报告输出目录 |
| `--brand-domains` | 否 | - | 品牌自有域名列表（逗号分隔，如 `dnshocks.com,dnshocks.cn`） |
| `--platform-profiles` | 否 | - | 平台画像文件路径或目录（由 `geo-platform-reverse` 生成）。传入后第三步使用动态画像替代硬编码表。支持逗号分隔多文件或目录路径（目录下自动匹配 `平台画像_*.md`） |
| `--quick` | 否 | false | 快速模式：仅输出执行摘要和发布策略矩阵 |

## 执行步骤

当调用此技能时，按以下步骤执行：

### 1. 读取配置与参数

从 `geo-config.json` 读取 `openKey` 和 `baseUrl`。解析用户提供的参数。

### 2. 数据采集

分页调用 `GET /v1/ai-indexing/custom`，拉取所有收录结果。每页 200 条，请求间加 1 秒延迟避免限流。

### 3. 来源分类

对每条结果的 `searchedSite[]` 中的每个 URL：
1. 提取域名
2. 匹配来源类型
3. 标记 indexed 状态和品牌提及情况

### 4. 平台画像

按平台分组，计算：
- 来源类型分布（数量 + 占比）
- 引用性格描述
- Top 域名列表
- 收录率

### 5. 证据链评分

按 `(topic, platform)` 分组，计算四维评分和综合评级。

### 6. 缺口识别

对所有 C/D 评级的问题-平台对，识别具体缺口类型。

### 7. 策略生成

基于缺口 + 平台偏好，生成发布策略矩阵。

### 8. 报告输出

生成 Markdown 报告，保存到指定目录。

## 与其他技能的衔接

### 上游（数据输入）

| 技能 | 关系 |
|------|------|
| `geo-indexing-result` | 本技能调用同一 API `/v1/ai-indexing/custom` 获取数据 |
| `geo-platform-reverse` | 通过 `--platform-profiles` 参数导入动态平台画像，替代硬编码表 |
| `geo-indexing-check` | 证据链分析的前提：先跑完收录检测才有数据 |
| `geo-keyword-plan` | 通过 `--keyword-map` 参数复用关键词层级结构 |

### 下游（策略执行）

| 技能 | 关系 |
|------|------|
| `optimize-content` | 证据链缺口 → 生成补充内容 |
| `geo-article-create` | 全新文章创建 |
| `geo-create-media-articles` | 媒体类内容创建 |
| `check-coverage` | 发布后验证覆盖度改善 |

### 推荐工作流

```
1. /geo-workflow-hub evidence-chain --company="品牌" --quick
   → 快速了解当前证据链状况和发布策略

2. 根据策略矩阵，决定发布什么内容、发到哪里

3. 创建内容 → 发布到目标平台

4. 等待收录监测完成

5. /geo-workflow-hub evidence-chain --company="品牌"
   → 重新分析，对比改善情况
```

## 注意事项

1. **数据依赖**：本技能依赖收录检测结果，需先运行 `geo-indexing-check` 生成数据
2. **数据量要求**：建议至少 100 条以上结果才有统计意义
3. **动态变化**：AI 平台的引用偏好可能随时间变化，建议定期重新分析
4. **品牌别名**：务必在 `--company` 中包含所有品牌别名（如"多耐,DN,DUONAI"）
5. **渠道实操**：发布策略矩阵是指导性的，实际发布还需考虑各渠道的入驻门槛和审核机制
