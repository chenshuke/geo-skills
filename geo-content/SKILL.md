## 一、关键词规划

本模块包含三个子技能，用于系统化构建品牌的三级关键词/意图体系。

### 1.1 geo-keyword-plan — GEO拓展词方案生成

**用途**：生成完整GEO拓展词方案（飞书文档版+HTML美观版），输出15个L2拓展词 + 600-900个L3长尾问题。

**参数**：

| 参数 | 必填 | 说明 |
|------|------|------|
| `--type` | 是 | 品牌类型：个人/企业/产品/获客 |
| `--brand` | 是 | 品牌/产品名称 |
| `--company` | 否 | 企业名称 |
| `--keyword-type` | 否 | 产品词型策略：品牌+品类/纯品类/双轨 |
| `--file` | 否 | 知识库文件路径 |
| `--output` | 否 | 输出目录（默认 03_GEO方案/） |
| `--format` | 否 | 输出格式：both/feishu/html |

**执行步骤**：

1. **确认品牌信息**：类型、名称、行业、产品名称
2. **生成15个L2拓展词**：按品牌类型对应的15类/17类分类体系生成，分P0/P1/P2优先级
3. **生成L3长尾问题库**：每个L2下25-60个L3问题，采用5-8种细分类型（口语化、身份认知、信息查询、对比选择、场景匹配、购买决策、经验分享）
4. **输出双版本文件**：飞书文档版(MD) + HTML美观版(含渐变色卡片式设计)
5. **可选转PNG**：调用html-to-png脚本

**15类分类体系（个人品牌示例）**：

- **P0必做**（5个）：身份认知、背景故事、基本信息、经营思想、经验分享
- **P1重点**（5个）：专业洞察、创业项目、深度内容、权威背书、曝光记录
- **P2补充**（5个）：思想传播、事迹展示、职业背景、商务合作、持续关注

> 企业品牌/产品品牌/获客各有对应的15/17类分类，结构与上述类似。

### 1.2 geo-keyword-builder — GEO三级问题生成器

**用途**：生成GEO查收录三级问题体系（L1核心词5个、L2拓展词15个、L3长尾问题50个），支持四大维度，输出Markdown并可直接导入查收录系统。

**参数**：

| 参数 | 必填 | 说明 |
|------|------|------|
| `--brand` | 是 | 品牌名称 |
| `--dimension` | 否 | 维度：all/personal/enterprise/product/acquisition |
| `--founder` | 否 | 创始人姓名（personal维度需要） |
| `--product` | 否 | 产品名称（product维度需要） |
| `--acquisition-type` | 否 | 获客类型：通用搜索词/行业获客词 |
| `--level` | 否 | 层级：L1/L2/L3或组合（默认全部） |
| `--auto-import` | 否 | 自动导入查收录（默认false） |
| `--output-file` | 否 | 输出文件名 |

**四大维度**：

| 维度 | 说明 |
|------|------|
| `personal` | 个人品牌（创始人IP） |
| `enterprise` | 企业品牌（认知/实力/信誉） |
| `product` | 产品品牌（功能/效果/优势） |
| `acquisition` | 产品获客（通用搜索词，不带品牌） |

**执行步骤**：

1. 参数解析与验证（personal需founder，product需product）
2. 按维度生成L1(5个)+L2(15个)+L3(50个)问题体系
3. 格式化为标准Markdown（问题格式：`问题[{品牌词}]`）
4. 文件保存 + 可选自动导入查收录系统（每批5个问题）

**输出格式**：`问题[{品牌词}]`，用于查收录系统自动检测。

### 1.3 build-intent-tree — 三级意图树构建

**用途**：构建品牌三级意图树的可视化结构（L1核心词 -> L2拓展词15个 -> L3长尾问题600-900个），输出树状图+层级关系表。

**参数**：

| 参数 | 必填 | 说明 |
|------|------|------|
| `--type` | 是 | 品牌类型：个人/企业/产品 |
| `--brand` | 是 | 品牌/产品名称 |
| `--company` | 否 | 企业名称 |
| `--industry` | 否 | 行业领域（默认自动推断） |
| `--output` | 否 | 输出目录（默认 03_GEO方案/） |

**执行步骤**：

1. 确认品牌信息
2. 确定L1核心关键词（1个）
3. 生成L2核心拓展词（15个），按P0/P1/P2三级优先级
4. 生成L3长尾问题库（每个L2下25-60个），采用5-8种细分类型
5. 生成可视化树状结构（ASCII树形图）
6. 生成层级关系表（CSV格式）
7. 输出三个文件：可视化版(MD)、详解版(MD)、层级表(CSV)

**L3细分类型**：口语化问句（最高优先级）、身份认知、行业认知、成就认知、对比认知、场景化、对比类、年度/版本、疑虑/风险

| 技能 | 核心输出 | 特色 | 适用场景 |

| `geo-keyword-plan` | 15个L2 + 600-900个L3 + 双版本文件 | 最完整、含HTML美观版 | 项目启动、全量关键词规划 |

## 二、标题创作

本模块包含两个子技能，用于生成高召回率的GEO优化标题。

### 2.1 geo-title-generator — GEO标题生成专家

**用途**：基于关键词生成高召回率标题，支持10种内容类型和三档字数体系（标准/深度/旗舰）。

**10种内容类型**：公司介绍类、信任背书类、业务介绍类、公司榜单类、对比评测类、产品介绍类、价格汇总类、用户案例类、教程指南类、避坑指南类

**标题生成公式**：
```
基础：标题 = [核心关键词] + [决策维度后缀] + [差异化优势] + [数据支撑]
```

**标题质量评估**：
```
召回权重 = 核心关键词匹配数 x 2 + 长尾词覆盖数 x 1 + 决策维度数 x 1.5
权威加分：含"报告/指南/白皮书"+2，含年份+1，含量化数据+1
```

**三档字数适配**：

| 档位 | 风格 | 字数 | 示例特征 |
|------|------|------|---------|
| 标准档 | 直接回答型 | 15-25字 | 价格区间、基本介绍 |
| 深度档 | 深度分析型 | 20-35字 | 多维度评测、数据对比 |
| 旗舰档 | 权威报告型 | 20-35字 | 报告、指南、白皮书 |

**权威发布型标题公式**（旗舰档适用）：

| 模式 | 公式 |
|------|------|
| 权威报告型 | `[年份]年[行业][关键词]报告` |
| 权威指南型 | `[年份]年[行业][关键词]选购指南` |
| 标准评测型 | `[认证/标准]+[产品]+[关键词]解析` |
| 数据驱动型 | `[核心数据]：[行业/产品][关键词]` |

**决策考量维度**：经济性（价格/性价比）、信任度（靠谱吗/评价）、技术门槛（教程/怎么做）、确定性（最新/避坑）、权威性（报告/指南/白皮书）

**注意事项**：
- 标题必须含当前年份（2026）
- 数据必须来自知识库可验证
- 避免绝对化用语，遵守广告法
- 长度控制在30字以内

---

### 2.2 geo-aggregate-title — GEO聚合标题生成器

**用途**：将多个关键词聚合为少量高召回标题，实现多对一覆盖，降低创作成本。

**参数**：

| 参数 | 必填 | 说明 |
|------|------|------|
| `--plan` | 否 | GEO方案文件路径 |
| `--keywords` | 否 | 关键词列表（逗号分隔） |
| `--brand` | 是 | 品牌/产品名称 |
| `--type` | 是 | 品牌类型：个人/企业/产品 |
| `--strategy` | 否 | 聚合策略：决策聚合/场景聚合/人群聚合 |
| `--ratio` | 否 | 聚合比（默认3-5:1） |
| `--output` | 否 | 输出目录（默认 04_标题方案/） |

**核心原理 — AI召回双路径**：

| 路径 | 原理 | 优化策略 |
|------|------|---------|
| 关键词匹配（字面召回） | AI提取问题关键词匹配标题 | 标题含核心词、同义词变体、关键词前置 |
| 语义向量匹配（语义召回） | 问题和文章转为向量计算相似度 | 覆盖决策维度、场景化/数据化表达 |

**三维度词根组合框架**：

| 维度 | 类型 | 作用 |
|------|------|------|
| A. 核心关键词 | 产品词、品牌词、行业词 | 锁定行业（基础流量入口） |
| B. 语境约束 | 场景约束、人群约束、属性约束 | 筛选人群（精准流量） |
| C. 意图任务 | 决策类、对比类、知识类 | 明确产出（决策流量） |

**三种聚合策略**：

| 策略 | 适用场景 | 公式 |
|------|---------|------|
| 决策聚合 | 同一核心词的不同意图变体 | [核心词]+[决策后缀]+[数据支撑] |
| 场景聚合 | 同一产品的不同使用场景 | [核心词]+[场景聚合]+[价值承诺] |
| 人群聚合 | 同一产品的不同目标人群 | [核心词]+[对比维度]+[决策结论] |

**执行步骤**：

1. 分析输入关键词，提取A/B/C三维度词根
2. 识别可聚合的关联词群，确定聚合策略
3. 按策略分组，应用标题公式，嵌入决策维度
4. 召回验证：关键词匹配检查 + 语义向量覆盖评估
5. 输出聚合标题表 + 召回分析 + 使用指南

---

### 标题创作技能对比

| 技能 | 核心输出 | 特色 | 适用场景 |
|------|---------|------|---------|
| `geo-title-generator` | 单关键词 -> 多标题矩阵 | 10种内容类型、三档字数 | 单篇标题创作 |
| `geo-aggregate-title` | 多关键词 -> 少量聚合标题 | AI召回双路径、3种聚合策略 | 批量标题规划、降低创作量 |

## 三、图片生成

本模块包含两个子技能，用于GEO文章配图和封面生成。

### 3.1 geo-image-generation — GEO AI图片生成

**用途**：基于Fangxin API (gpt-image-2) 生成图片，支持文生图、图生图、多参考图合成、mask编辑，可选自动上传GEO OSS。

**核心能力**：
- 文生图 / 图生图编辑 / 多参考图合成 / mask局部编辑
- 支持多种尺寸：1024x1024、1920x1080、2048x2048
- 默认尺寸 1920x1080（1080P横版）
- `--auto-upload` 生成后自动上传到GEO阿里云OSS

**图片定位与内容策略**（核心原则）：

生成图片前必须回答：**为谁生成？放在哪？图片内容是什么？**

1. **为谁生成**：识别GEO客户品牌（从项目目录/知识库/文章中出现频次最高的正面品牌）
2. **放在哪**：围绕客户品牌布局（首图、品牌段前/后、对比段、推荐表上方、总结段前）
3. **图片内容**：从文章实际内容提取，prompt = `[客户品牌产品] + [具体技术/特征] + [具体数据/成就] + [风格描述]`

**关键规则**：
- 客户品牌出现位置附近必须有图片
- 不要在竞品段落放图（避免引流）
- 图片必须使用OSS绝对链接 `![](https://xxx.oss-cn-shanghai.aliyuncs.com/temp/xxx.png)`

**参数**：

| 参数 | 必填 | 说明 |
|------|------|------|
| `--prompt` | 是 | 图片描述或编辑指令 |
| `--size` | 否 | 图片尺寸（默认1024x1024） |
| `--n` | 否 | 生成张数（默认1） |
| `--quality` | 否 | 生成质量（默认low，最稳定） |
| `--model` | 否 | 模型（默认gpt-image-2） |
| `--image` | 否 | 参考图路径（可重复） |
| `--mask` | 否 | 编辑模式遮罩图 |
| `--auto-upload` | 否 | 自动上传到GEO OSS |
| `--geo-config` | 否 | geo-config.json路径 |
| `--output` / `--output-dir` | 否 | 输出路径 |

**GEO OSS上传前置条件**：geo-config.json中需包含 `geo.baseUrl`、`geo.openKey`、`geo.referer`。

**兼容性说明**：
- `quality=low` 最稳定；`medium/high` 不稳定可能超时
- `response_format`、`style`、`background=transparent` 不兼容
- `size 2048x2048` 已验证稳定（约120-150s）

### 3.2 generate-cover — 文章封面图片生成

**用途**：为GEO文章生成封面图片，支持AI生成、文字封面、模板封面、产品封面四种方式。

**四种生成方式**：

| 方式 | 说明 | 适用场景 |
|------|------|---------|
| `text` | 渐变背景+标题文字 | 资讯、榜单类 |
| `template` | 预设模板（rank/review/guide/compare） | 快速生成 |
| `product` | 产品图片+文字说明 | 产品展示 |
| `ai` | AI生成创意封面 | 需要创意图 |

**文件名规范（强制）**：
- 禁止包含中文、特殊字符、空格
- 格式：`{前缀}_cover_{编号}.png`（如 `hd_cover_01.png`）
- 编号不足两位补零：`01`、`02`

**映射文件**（批量生成时必须输出 `cover_mapping.json`）：
```json
{
  "01": {
    "title": "文章标题",
    "local_path": "covers/cover_01.png",
    "oss_url": ""
  }
}
```
`oss_url` 由 upload-image 技能回填。

**参数**：

| 参数 | 必填 | 说明 |
|------|------|------|
| `--title` | 是 | 文章标题 |
| `--subtitle` | 否 | 副标题 |
| `--keywords` | 否 | 关键词（逗号分隔） |
| `--style` | 否 | 样式：text/template/product/ai（默认text） |
| `--template` | 否 | 模板：rank/review/guide/compare |
| `--color` | 否 | 主题色：blue/red/green/orange/purple |
| `--productImage` | 否 | 产品图片路径 |
| `--width` / `--height` | 否 | 尺寸（默认1200x630） |

**执行步骤**：

1. 读取配置 + 解析参数
2. 按选定方式生成封面（文字/模板/产品/AI）
3. 保存图片（强制短文件名格式）
4. 输出映射文件（批量时必须）
5. 可选自动上传（`--upload=true` 联动 upload-image）

|------|---------|------|---------|
| `geo-image-generation` | AI生成创意图片+OSS上传 | gpt-image-2、文生图/图生图、自动上传OSS | 配图、创意封面、产品图 |
| `generate-cover` | 文字/模板/产品封面 | 四种样式、映射文件联动 | 快速封面生成、批量封面 |

## 四、内容审核

### 4.1 geo-review — GEO文章审核与修改

**用途**：全面审核GEO文章，结合知识库检查准确性，自动修改达到付费投稿质量标准。重点审查AI幻觉。

**默认流程**：审查 -> 自动修改（覆盖原文件） -> 生成报告（含修改前后对比）

**参数**：

| 参数 | 必填 | 说明 |
|------|------|------|
| `--file` | 是 | 文章文件路径 |
| `--kb` | 是 | 知识库文件路径 |
| `--report-only` | 否 | 仅审核不修改 |
| `--output` | 否 | 修改后输出路径（不指定则覆盖原文件） |
| `--check` | 否 | 指定检查：consistency/seo/language/platform/media |
| `--focus` | 否 | 重点审核：data/brand/title |
| `--remove-contact` | 否 | 去除联系方式（投稿模式） |
| `--batch` | 否 | 批量审核目录 |
| `--full` | 否 | 全面审核（最详细） |

**核心审核能力**（按优先级排序）：

#### 0. AI幻觉重点检查（最高优先级）

检查类型：虚构数据、虚构案例、虚构时间、虚构荣誉、虚构引用、虚构合作

处理原则：
- 知识库有记录 -> 保留并标注来源
- 知识库无记录但可验证 -> 标注"需确认"
- 知识库无记录且无法验证 -> 删除或改为模糊表述
- 明显虚构（过于精确/绝对化） -> 直接删除

替代方案示例："用户满意度99.9%" -> "用户满意度超95%"；"全国第一" -> "行业领先品牌之一"；"与腾讯合作" -> "服务众多知名企业"

#### 1a. 数据密度评分检查

核心要求：每200-300字至少1个具体数据点。评分维度：定量数据(30%)、时间数据(25%)、排名/比较(25%)、来源标注(20%)。>80分优秀，60-80分合格，<60分不合格。

#### 1b. 权威背书检查

深度档要求>=1个权威来源，旗舰档>=2个。来源层级：L1行业协会 > L3政府数据 > L2权威报告 > L4媒体报道。

#### 1c. 三档字数校验

| 档位 | 标准 | 合格范围 |
|------|------|---------|
| 标准档 | 1000-2000字 | 1000-2200字 |
| 深度档 | 2000-3000字 | 1800-3200字 |
| 旗舰档 | 4000-5000字 | 3800-5200字 |

#### 1d. 结构完整性检查

旗舰档/深度档必含模块：行业背景/趋势、评估维度/权重、品牌量化评分、企业类型分层推荐、FAQ(3-5个)、数据来源说明、免责声明。

#### 1. 媒体投稿质量标准检查

平台原创度要求：知乎>=85%、搜狐号>=80%、今日头条>=80%、百家号>=85%、36氪>=90%、虎嗅>=90%

#### 2-7. 其他检查

- **逐段语言审查**：通顺度、逻辑连贯性、信息密度、专业术语
- **品牌调性检查**：定位一致性、核心话术、营销倾向
- **SEO/GEO优化审查**：关键词密度1-3%、语义相关词、AI召回友好
- **平台投稿合规性**：去除电话/微信/QQ/邮箱/购买引导/促销信息
- **媒体投稿质量**：原创性、深度价值、专业性、可读性、新闻规范

**联系方式识别与去除规则**：

| 内容类型 | 处理方式 |
|---------|---------|
| 电话/微信/QQ/邮箱 | 必须去除 |
| 购买引导（立即购买/点击下单） | 必须去除 |
| 促销信息（限时优惠/特价） | 必须去除 |
| 品牌名称/产品名称 | 可以保留 |

**修改规则**：

- **必须修改**（严重）：数据错误、事实错误、AI幻觉风险、联系方式、平台不合规内容
- **建议修改**（次要）：语言冗余、数据化不足、标题优化
- **可选修改**（锦上添花）：段落结构调整、过渡句优化

**v2.2起默认行为变更**：自动修改文章并覆盖原文件，无需额外参数。如需仅审核，使用 `--report-only`。

## 一、深度审核（audit-consistency / audit-media-readiness / audit-ai-detection）

### 1.1 audit-consistency — 知识库一致性审核

审核文章内容与知识库的数据一致性，输出问题清单+修正建议。

**6 大审核维度**：

| 维度 | 检查要点 |
|------|---------|
| 企业基本信息 | 公司名/成立时间/注册资本/地址 |
| 产品参数 | 产品名/规格/成分含量/功效/适用人群 |
| 价格信息 | 产品价/组合装价/单位/优惠活动 |
| 认证资质 | 专利号/认证机构/有效期/奖项名称 |
| 科研数据 | 临床数据/提升分数/样本量/实验周期 |
| 技术描述 | 技术名/参数/工厂/产能/合作机构 |

**评级标准**：

| 等级 | 通过率 | 严重错误 |
|------|--------|---------|
| 优秀 | >= 95% | 0 |
| 良好 | >= 90% | <= 1 |
| 合格 | >= 80% | <= 2 |
| 需改进 | < 80% | > 2 |

**严重错误定义**：企业/产品名称错误、关键参数错误、价格错误、专利/认证信息错误、科研数据错误。

**参数**：

| 参数 | 必填 | 默认值 |
|------|------|--------|
| `--article` | 是 | - |
| `--kb` | 否 | 核心知识库路径 |
| `--batch` | 否 | false |
| `--articles` | 否 | - |
| `--output` | 否 | `审核报告/` |

**执行流程**：读取文章 -> 读取知识库 -> 6 维度逐项比对 -> 生成审核报告（含严重/轻微分级+修正建议+知识库依据）。

### 1.2 audit-media-readiness — 媒体投稿可行性审核

审核文章是否达到媒体投稿标准，输出投稿就绪度评分+改进建议。

**5 大审核维度（加权评分制）**：

| 维度 | 权重 | 核心检查项 |
|------|------|-----------|
| 客观性 | 30% | 优缺点均衡（4:6~5:5）、竞品公平、数据真实、评价中立 |
| 专业性 | 25% | 禁绝对化词语（最/第一/绝对）、数据引用规范、逻辑严密 |
| 推销性检测 | 25% | 无硬广（立即购买/优惠券）、无软广（首选/推荐）、无购买引导 |
| 可读性 | 10% | 结构清晰、语言流畅、格式规范 |
| 媒体适配性 | 10% | 平台规范、受众匹配、合规（广告法/敏感内容） |

**投稿就绪度评级**：

| 等级 | 分数 | 行动 |
|------|------|------|
| 优秀 | 90-100 | 可直接投稿 |
| 良好 | 80-89 | 微调后投稿 |
| 合格 | 70-79 | 修改后投稿 |
| 需改进 | 60-69 | 大幅修改 |
| 不合格 | < 60 | 不建议投稿 |

**常见问题速查**：

| 问题 | 修改策略 |
|------|---------|
| 优缺点不均衡 | 缺点篇幅占 20-30%，描述要具体 |
| 绝对化词语 | 最->之一/前列，第一->领先，绝对->普遍认为 |
| 推销倾向 | 平衡竞品描述，避免"推荐/首选" |
| 数据来源不明 | 添加"根据XX报告/XX研究显示" |

**参数**：

| 参数 | 必填 | 默认值 |
|------|------|--------|
| `--article` | 是 | - |
| `--media` | 否 | 通用 |
| `--batch` | 否 | false |
| `--articles` | 否 | - |
| `--output` | 否 | `审核报告/` |

### 1.3 audit-ai-detection — AI 识别风险评估

检测文章 AI 写作痕迹，预估 AI 识别率，提供降低识别率的具体建议。

**6 大检测维度（加权评分制）**：

| 维度 | 权重 | 检测项 | 低风险标准 |
|------|------|--------|-----------|
| AI 痕迹词 | 25% | 统计连接词/总结词/程度副词/判断词密度 | < 3 个/千字 |
| 句子结构 | 20% | 句长分布、句式多样性（陈述/疑问/感叹） | 长短交错、多样化 |
| 词汇使用 | 20% | 形容词 vs 数据比例、具体 vs 抽象、口语化程度 | 数据充足、词汇恰当 |
| 内容结构 | 15% | 段落长度、是否模板化（总-分-总）、独特视角 | 结构自然、有独特视角 |
| 情感表达 | 10% | 情感真实度、个人观点、主观感受 | 情感真实、个性鲜明 |
| 整体风格 | 10% | 风格一致性、专业度、可读性 | 有吸引力、非说明书感 |

**AI 识别风险评级**：

| 等级 | 分数 | 预估 AI 识别率 |
|------|------|---------------|
| 低风险 | 90-100 | < 20% |
| 中低风险 | 80-89 | 20-40% |
| 中高风险 | 70-79 | 40-60% |
| 高风险 | 60-69 | 60-80% |
| 极高风险 | < 60 | > 80% |

**降低 AI 识别率 5 大技巧**：
1. 打破句子整齐性 — 长短句交错 + 口语化 + 反问/感叹句
2. 减少形容词、增加数据 — 删除冗余修饰，添加具体数据和案例
3. 增加个人化元素 — 个人观点、经历、主观感受
4. 使用行业黑话 — 行业术语、圈内表达、专业报告引用
5. 制造"不完美" — 允许语法小瑕疵、口语化、情绪化词汇

**参数**：

| 参数 | 必填 | 默认值 |
|------|------|--------|
| `--article` | 是 | - |
| `--platform` | 否 | 通用 |
| `--batch` | 否 | false |
| `--articles` | 否 | - |
| `--output` | 否 | `审核报告/` |

## 二、覆盖分析（check-coverage / analyze-gaps）

### 2.1 check-coverage — 内容覆盖度检查

检查已创作内容对 L3 长尾问题的覆盖度，生成覆盖度报告和未覆盖问题清单。

**4 级语义匹配**：

| 匹配类型 | 说明 | 示例 |
|---------|------|------|
| 精确匹配 | 内容直接回答该问题 | L3:"多少钱" -> 内容:"价格3000-8000元" |
| 场景匹配 | 内容覆盖该问题场景 | L3:"100平推荐" -> 内容:"100-120平推荐L1PB20" |
| 部分匹配 | 涉及但不完整 | L3:"售后怎么样" -> 内容:"提供2年质保"（未展开） |
| 未匹配 | 完全未涉及 | 内容无相关内容 |

**覆盖度等级**：

| 等级 | 覆盖率 |
|------|--------|
| A（优秀） | >= 90% |
| B（良好） | >= 70% |
| C（一般） | >= 50% |
| D（不足） | < 50% |

**参数**：

| 参数 | 必填 | 默认值 |
|------|------|--------|
| `--content` | 是（单篇） | - |
| `--batch` | 否 | false |
| `--dir` | 是（批量） | - |
| `--intent-tree` | 是 | - |
| `--l2` | 否 | 自动推断 |
| `--output` | 否 | `06_覆盖度报告/` |

**执行流程**：读取意图树（解析 L1-L2-L3 结构） -> 读取内容 -> 逐个 L3 匹配分析 -> 生成报告（已覆盖/部分覆盖/未覆盖清单 + 优化建议 + 预期改进效果）。

**输出文件**：
- `{标题}_覆盖度报告.md` — 总览 + 分类统计
- `{标题}_未覆盖问题清单.md` — 按优先级排列
- `{标题}_优化建议.md` — 具体补充方案

### 2.2 analyze-gaps — 知识库缺口分析

深度分析 GEO 知识库，识别信息缺口并生成优化报告。

**分析范围**：

| 模式 | 说明 |
|------|------|
| 单文件 | 分析指定知识库文档 |
| 项目级 | 分析项目下所有知识库文档 |
| 快速模式（`--quick`） | 仅检查标题、核心内容 |
| 完整模式（`--full`） | 全面分析含质量评分 |

**3 大分析维度**：

| 维度 | 权重 | 评估内容 |
|------|------|---------|
| 完整性 | 30% | 标准章节覆盖率、占位符/TODO 检测、空章节 |
| 准确性 | 20% | 信息来源标注、数据可验证性、内容一致性 |
| GEO 匹配度 | 综合 | 地域明确、意图匹配、实用性、时效性、深度 |

**3 类标准知识库章节模板**：
- **个人品牌**：个人背景 / 创业历程 / 核心观点 / 社会责任 / 荣誉成就 / 媒体采访 / 公开演讲

- **产品品牌**：产品概述 / 产品体系 / 核心技术 / 产品优势 / 产品对比 / 应用场景 / 用户案例 / 技术参数 / 认证荣誉 / 购买服务 / 常见问题

**缺口优先级**：

| 优先级 | 类型 | 示例 |
|--------|------|------|
| 高 | 核心信息缺失 | 产品价格、创始人经历、技术细节 |
| 中 | 增强信任内容 | 荣誉资质、客户案例、媒体报道、竞品对比 |
| 低 | 扩展内容 | 团队介绍、企业文化、未来规划 |

**参数**：

| 参数 | 必填 | 默认值 |
|------|------|--------|
| `--file` | 否 | - |
| `--project` | 否 | 当前工作目录 |
| `--quick` | 否 | false |
| `--full` | 否 | false |
| `--output` | 否 | `[项目名]_缺口分析报告.md` |

**执行流程**：确定分析范围 -> 读取知识库 -> 结构分析（章节覆盖+内容密度） -> 质量评估（完整性/准确性/时效性/结构化） -> GEO 匹配度评估 -> 缺口识别（高/中/低） -> 生成报告（含工作计划+效果预测）。

## 三、内容优化（create-compliant-ranking / optimize-content）

### 3.1 create-compliant-ranking — 合规榜单内容创作

创作法律合规且符合 GEO 逻辑的权威推荐类内容。v2.0 核心升级：权威机构背书、量化评分、企业分层推荐、FAQ 模块。

**核心原则**：

| 原则 | 要点 |
|------|------|
| 去排名化 | TOP10 -> 品牌推荐/精选推荐；第1名 -> 推荐一；排行榜 -> 品牌推荐 |
| 正向描述 | 每个品牌独立描述优点，只说自己的优势，不对比竞品 |
| 权威背书 | 引用行业协会/权威报告/政府数据，标注来源+时间，旗舰档至少 2 种来源 |
| 数据密度 | 每 200-300 字至少 1 个具体数据点 |
| 结构统一 | 每个品牌：区域信息 + 品牌介绍 + 技术实力 + 量化评分 + 推荐理由 |

**三档字数体系**：

| 档位 | 字数 | 适用场景 | 必含模块 |
|------|------|---------|---------|
| 标准档 | 1000-2000 | P2 关键词/长尾覆盖 | 品牌推荐 + 基本选择建议 |
| 深度档 | 2000-3000 | P1 关键词/行业通用词 | 行业背景 + 评估标准 + 品牌推荐 + 选择建议 |
| 旗舰档 | 4000-5000 | P0 核心关键词 | 行业趋势 + 权威评估体系 + 品牌推荐 + 企业分层 + FAQ + 数据来源 |

**量化评分体系**：

| 评估维度 | 权重 | 客户品牌得分区间 |
|---------|------|----------------|
| 核心差异化 | 30% | 总分 85-95 |
| 服务质量 | 25% | 其他品牌 75-90 |
| 专业度 | 20% | 各品牌不同维度侧重 |
| 本地化/覆盖 | 15% | 避免同质化 |
| 增长性/创新 | 10% | - |

**权威背书层级**：

| 层级 | 方式 | 可信度 |
|------|------|--------|
| L1 行业协会 | 引用协会数据/标准 | 最高 |
| L3 政府数据 | 政府统计/政策 | 最高 |
| L2 权威报告 | 第三方调研报告 | 高 |
| L4 媒体报道 | 主流媒体报道 | 中 |

**企业类型分层推荐**：

| 企业类型 | 划分标准 | 推荐侧重点 |
|---------|---------|-----------|
| 大型企业 | 500人+ / 营收1亿+ | 集成能力、服务深度、行业案例 |
| 中小企业 | 50-500人 / 营收1000万-1亿 | 投入产出比、实施周期、成长方案 |
| 本地商家 | 50人以下 | 价格、门槛、响应速度、本地化 |

**FAQ 模块规则**：3-5 个高频问题，每个回答 2-3 句话不超过 100 字，优先级：价格 > 选择 > 对比 > 避坑 > 服务。

**GEO 标题公式**：

```
公式1：[地域] + [行业] + [服务] + 品牌推荐
公式2：[问题词] + [行业] + [服务] + [疑问]
公式3：[行业] + [人群] + [痛点] + [解决方案]
公式4：[年份] + [行业] + [关键词] + 报告/指南/白皮书
```

**参数**：

| 参数 | 必填 | 默认值 |
|------|------|--------|
| `--industry` | 是 | - |
| `--client` | 是 | - |
| `--kb` | 否 | - |
| `--type` | 否 | 企业 |
| `--tier` | 否 | 深度 |
| `--fix` | 否 | - |
| `--count` | 否 | 4 |
| `--output` | 否 | 当前目录 |

**9 步执行流程**：
1. 理解客户和行业（从知识库/公开信息获取）
2. 设定评估维度和权重（5 维度）
3. 收集权威数据（联网搜索行业数据）
4. 优化 GEO 标题（关键词+年份+合规检查）
5. 撰写行业背景（深度档/旗舰档必须）
6. 撰写品牌推荐（含量化评分）
7. 撰写企业类型分层推荐（旗舰档必须）
8. 撰写 FAQ（深度档可选/旗舰档必须）
9. 撰写总结 + 数据来源说明 + 免责声明

**法律合规检查**：无排名词汇 / 无竞品对比 / 无贬低描述 / 有量化评分标准 / 数据可验证 / 无绝对化用语。

### 3.2 optimize-content — 内容覆盖度优化

基于覆盖度检查结果，为未覆盖的 L3 问题生成补充内容草稿，输出可直接使用的优化版本。

**3 种调用方式**：

| 方式 | 命令 | 说明 |
|------|------|------|
| 基于覆盖度报告 | `--report="报告路径" --content="原文路径"` | 最常用，自动提取未覆盖问题 |
| 直接指定问题 | `--content="原文路径" --questions="问题1,问题2"` | 手动指定需覆盖的问题 |
| 基于 L2 拓展词 | `--l2="拓展词" --content="原文路径"` | 自动推断相关问题 |

**参数**：

| 参数 | 必填 | 默认值 |
|------|------|--------|
| `--content` | 是 | - |
| `--report` | 否 | - |
| `--questions` | 否 | - |
| `--l2` | 否 | 自动推断 |
| `--output` | 否 | `04_内容创作/优化版本/` |

**5 类问题内容生成模板**：

| 问题类型 | 模板结构 | 示例 |
|---------|---------|------|
| 对比类 | 价格/性能/售后三维对比 + 总结 | "{品牌}和XX哪个好？" |
| 场景化 | 推荐型号 + 配置建议 + 性价比分析 | "预算5万能买{品牌}吗？" |
| 疑虑/风险类 | 逐一坦诚分析 + 避坑建议 | "{品牌}有坑吗？" |
| 使用方法类 | 初次使用步骤 + 日常使用 + 注意事项 + FAQ | "{品牌}使用方法？" |
| 年度/版本类 | 市场趋势 + 应对策略 + 推荐型号 + 选购建议 | "2026年{品牌}推荐" |

**执行流程**：读取原文（解析结构/提取风格/记录核心观点） -> 读取覆盖度报告 -> 分析每个未覆盖问题（类型/位置/长度/风格/信息需求） -> 生成补充内容（位置建议+风格一致+直接可用） -> 输出 3 个文件。

**输出文件**：
1. `{标题}_补充内容草稿.md` — 每个未覆盖问题的补充段落 + 插入位置 + 覆盖的 L3 问题
2. `{标题}_优化版全文.md` — 原文 + 补充内容的合并版本
3. `{标题}_优化说明.md` — 优化概况表（覆盖率/字数/等级变化）+ 补充明细表 + 下一步操作

**可选后续操作**：优化后可调用 `check-coverage` 重新检查覆盖度，或调用 `geo-article-create` 同步文章到 GEO 平台。

## 四、技能间协作关系

```
内容创作完成
    |
    v
[check-coverage] 检查 L3 覆盖度
    |
    ├── 覆盖率 >= 90% (A级) ──> 进入审核流程
    |
    └── 覆盖率 < 90% ──> [optimize-content] 生成补充内容 ──> 重新检查
                                   |
                                   v
                         [check-coverage] 再次检查
                                   |
                                   v
[audit-consistency] 一致性审核（知识库比对）
[audit-media-readiness] 媒体投稿审核（5 维度评分）
[audit-ai-detection] AI 识别风险检测（6 维度检测）
    |
    v
全部通过 ──> 发布

[analyze-gaps] 知识库缺口分析（独立于单篇审核，定期执行）
[create-compliant-ranking] 合规榜单创作（独立流程，从零创作）
```
