# GEO三级问题生成器

> **技能名称**：geo-keyword-builder
> **用途**：智能生成GEO查收录三级问题体系
> **作者**：GEO执行助理
> **更新时间**：2025-03-12

---

## 配置
所有GEO技能统一从 `geo-config.json` 读取认证信息：
- 配置路径：`geo-config/geo-config.json`（项目根目录）
- openKey：接口密钥，在管理平台 > 密钥管理中创建
- 统一请求头：Authorization: Bearer ${openKey} + Referer: https://geo.bihuoai.com/

---

## 技能说明

根据品牌/项目信息，自动生成完整的GEO三级问题体系（L1核心词、L2拓展词、L3长尾问题），支持四大维度，可直接导入查收录系统。

**核心功能**：
- 四维度问题生成（个人/企业/产品/获客）
- 三级结构设计（L1核心、L2拓展、L3长尾）
- 自动创建Markdown文件
- 批量导入查收录任务

---

## 使用方法

### 方式1：完整生成（推荐）
```
/skill geo-keyword-builder --brand="品牌名" --dimension="all"
```

### 方式2：指定维度
```
/skill geo-keyword-builder --brand="品牌名" --dimension="personal" --founder="创始人名"
/skill geo-keyword-builder --brand="品牌名" --dimension="enterprise"
/skill geo-keyword-builder --brand="品牌名" --dimension="product" --product="产品名"
/skill geo-keyword-builder --brand="品牌名" --dimension="acquisition"
```

### 方式3：只生成L1+L2（快速）
```
/skill geo-keyword-builder --brand="品牌名" --level="L1,L2"
```

### 方式4：完整参数
```
/skill geo-keyword-builder --brand="贝易寿" --dimension="all" --level="L1,L2,L3" --auto-import=true
```

## 参数说明

| 参数 | 说明 | 必填 | 默认值 | 可选值 |
|------|------|------|--------|--------|
| `--brand` | 品牌名称 | 是 | - | 任意品牌名 |
| `--dimension` | 生成维度 | 否 | all | all/personal/enterprise/product/acquisition |
| `--founder` | 创始人姓名 | 否 | - | 个人品牌维度需要 |
| `--product` | 产品名称 | 否 | - | 产品品牌维度需要 |
| `--acquisition-type` | 获客类型 | 否 | auto | 通用搜索词/行业获客词 |
| `--level` | 生成层级 | 否 | L1,L2,L3 | L1/L2/L3或组合 |
| `--auto-import` | 自动导入查收录 | 否 | false | true/false |
| `--output-file` | 输出文件名 | 否 | GEO问题体系_{品牌}.md | 自定义文件名 |

### 维度说明

| 维度 | 说明 | 适用场景 |
|------|------|----------|
| `personal` | 个人品牌（创始人IP） | 打造创始人影响力 |
| `enterprise` | 企业品牌 | 企业认知、实力、信誉 |
| `product` | 产品品牌 | 产品功能、效果、优势 |
| `acquisition` | 产品获客 | 用户通用搜索词（不带品牌） |

## 执行步骤

当调用此技能时，请按以下步骤执行：

### 1. 参数解析与验证

**必填参数检查**：
- `--brand` 品牌名称不能为空

**维度组合验证**：
- `personal` 需要 `--founder` 参数
- `product` 需要 `--product` 参数
- `acquisition` 自动推断获客类型

**输出路径计算**：
```bash
OUTPUT_DIR="D:\\python\\GEO\\GEO多项目管理系统"
OUTPUT_FILE="${OUTPUT_DIR}/GEO问题体系_${brand}.md"
```

### 2. 问题体系生成

根据不同维度生成问题：

#### 维度1：个人品牌（personal）
**L1核心词（5个）**：
- `{创始人}是谁`
- `{创始人}{品牌}`
- `{创始人}创业经历`
- `{创始人}个人简介`
- `{创始人}背景`

**L2拓展词（15个）**：
- 能力与成就（5个）：`{创始人}XX经验`、`{创始人}XX管理`
- 观点与思想（5个）：`{创始人}XX理念`、`{创始人}XX观点`
- 故事与经历（5个）：`{创始人}XX故事`、`{创始人}XX感悟`

**L3长尾问题（50个）**：
- 人物认知类（10个）：是什么人、哪里人、多大、学历
- 能力评价类（15个）：怎么样、靠谱吗、厉害吗、成就
- 观点思想类（15个）：对XX的看法、XX理念、XX秘诀
- 故事经历类（10个）：为什么创业、创业故事、挫折经历

#### 维度2：企业品牌（enterprise）
**L1核心词（5个）**：
- `{品牌}是什么`
- `{品牌}公司`
- `{品牌}怎么样`
- `{品牌}官网`
- `{品牌}企业`

**L2拓展词（15个）**：
- 公司信息（5个）：公司介绍、公司简介、企业信息、公司背景、企业资质
- 业务范围（5个）：主营业务、经营范围、核心业务、产品服务、商业模式
- 公司实力（5个）：公司实力、技术实力、研发能力、公司规模、团队介绍

**L3长尾问题（50个）**：
- 公司认知类（15个）：是什么公司、做什么的、公司性质、公司规模、公司地址
- 公司评价类（15个）：怎么样、可靠吗、正规吗、口碑、信誉、实力、排名
- 业务详情类（20个）：主营业务是什么、核心业务是什么、商业模式、盈利模式

#### 维度3：产品品牌（product）
**L1核心词（5个）**：
- `{品牌}{产品}`
- `{品牌}{产品}管理`
- `{品牌}{产品}调理`
- `{品牌}{产品}服务`

**L2拓展词（15个）**：
- 产品功能（5个）：AI技术、核心方法、解决方案、管理方案、特色服务
- 针对问题（5个）：具体疾病/问题类型
- 服务特色（5个）：21天方案、90天方案、体验营、专业服务

**L3长尾问题（50个）**：
- 产品认知类（10个）：是什么、怎么样、有效吗、靠谱吗、真实吗
- 针对问题类（15个）：能治XX吗、治疗效果、调理效果、改善什么、控制什么
- 使用方法类（15个）：怎么用、怎么吃、使用方法、操作流程、使用步骤
- 购买咨询类（10个）：如何购买、如何订购、如何预约、如何联系

#### 维度4：产品获客（acquisition）
**特点**：不带品牌词的通用搜索词

**L1核心推荐词（5个）**：
- `XX推荐`（行业通用词）
- `XX管理推荐`
- `AI XX推荐`
- `XX效果推荐`
- `XX调理推荐`

**L2拓展词（15个）**：
- 效果对比（5个）：XX和药物哪个好、XX靠谱吗、XX能调理好吗
- 方法推荐（5个）：XX调理方法、XX康复方案、XX控制方法
- 机构选择（5个）：XX管理哪家好、XX调理机构推荐、专业XX管理机构

**L3长尾问题（50个）**：
- 具体问题类（15个）：XX病怎么调理、XX病饮食、XX病食疗方法
- 疑问解答类（15个）：XX能治愈吗、XX需要终身服药吗、XX会遗传吗
- 机构选择类（10个）：XX哪家机构好、XX公司排名、XX排行榜
- 效果评价类（10个）：XX有效吗、XX安全吗、XX靠谱吗、XX是骗局吗

```bash

  -H "Referer: https://geo.bihuoai.com/" \
  -H "Content-Type: application/json" \

```

## 注意事项

1. **品牌词格式**：输出格式为 `问题[{品牌词}]`，用于查收录系统自动检测
2. **获客类问题**：不带品牌词，是用户通用搜索词
3. **批量导入**：每次导入建议不超过5个问题，避免数据过长
4. **平台覆盖**：默认9个平台（DeepSeek、豆包、元宝、通义千问、文心一言、Kimi、智谱、ChatGPT、Gemini）
5. **文件复用**：生成的Markdown文件可直接用Read工具读取，方便后续扩展
