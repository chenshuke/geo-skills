> **通用兼容**：适用于 Claude Code、Codex 和兼容 Agent Skills 的工具；建议完整安装同级 `geo-*` 技能，运行诊断请使用 `../geo-runtime/SKILL.md`。

## 输出归位硬规则

审核和优化产物必须直接写入项目标准目录：一致性、媒体投稿、AI 检测、覆盖度、缺口、质量报告分别放入 `05_质量审核/` 对应子目录；优化版文章放 `04_内容创作/{日期}/optimized/`。写文件前可用 `geo-content-archive/scripts/project_paths.js --artifact audit-coverage` 等获取路径。

## 一、内容审核

### 1.1 geo-review — GEO文章审核与修改

**用途**：全面审核GEO文章，结合知识库检查准确性，自动修改达到付费投稿质量标准。重点审查AI幻觉。

**默认流程**：审查 -> 自动修改（覆盖原文件） -> 生成报告（含修改前后对比）

**参数**：

| 参数 | 必填 | 说明 |
|------|------|------|
| `--file` | 是 | 文章文件路径 |
| `--kb` | 是 | 知识库文件路径 |
| `--report-only` | 否 | 仅审核不修改 |
| `--output` | 否 | 修改后输出路径（不指定则覆盖原文件） |
| `--check` | 否 | 指定检查：consistency/seo/language/platform/media |
| `--focus` | 否 | 重点审核：data/brand/title |
| `--remove-contact` | 否 | 去除联系方式（投稿模式） |
| `--batch` | 否 | 批量审核目录 |
| `--full` | 否 | 全面审核（最详细） |

**核心审核能力**（按优先级排序）：

#### -1. 优势证据库核验（先于幻觉检查）

如果项目存在 `02_知识库/证据库/核心优势与可信证据库_*.md` 和 `待补强证据清单_*.md`，审核前必须读取：

- 文章中的优势、推荐理由、对比、案例、客户、资质、效果和排名是否对应可用证据；
- A/B 级可作为主要依据，C 级不能单独支持关键结论，D/X 级必须删除；
- “有条件可用”是否保留来源、时间、对象和范围限制；
- 是否把基础信任事实包装成独特优势；
- 是否把企业自述写成第三方认可；
- 是否出现证据库明确禁止的扩大表达。

发现证据不足时，将主张写入独立的待补强证据清单，不使用模糊数据或弱化后的虚假表达继续保留。

#### 0. AI幻觉重点检查（最高优先级）

检查类型：虚构数据、虚构案例、虚构时间、虚构荣誉、虚构引用、虚构合作

处理原则：
- 事实知识库有记录且证据库允许该主张 -> 保留并按需要标注来源
- 事实知识库有记录但证据库标记待补强/不可用 -> 删除强结论或改为不涉及该主张的通用判断
- 知识库无记录但可验证 -> 标注"需确认"
- 知识库无记录且无法验证 -> 删除或改为模糊表述
- 明显虚构（过于精确/绝对化） -> 直接删除

处理示例：没有原始统计依据的“用户满意度99.9%”应删除，不得改成另一个猜测数字；没有权威排名的“全国第一”应改为客观能力或选型维度，不得改成“行业领先之一”；无法核验的“与腾讯合作”不得改成“服务众多知名企业”，应删除或进入待补强证据清单。

#### 1a. 数据密度评分检查

数据密度不能凌驾于真实性。仅统计 A/B 级或有明确可核验来源的数据点；不为满足“每 200-300 字一个数据”而补造数字。评分维度：可验证定量数据(30%)、可验证时间数据(25%)、有依据的排名/比较(25%)、来源与证据边界标注(20%)。>80分优秀，60-80分合格，<60分不合格。

#### 1b. 权威背书检查

深度档要求>=1个权威来源，旗舰档>=2个。来源层级：L1行业协会 > L3政府数据 > L2权威报告 > L4媒体报道。

#### 1c. 三档字数校验

| 档位 | 标准 | 合格范围 |
|------|------|---------|
| 标准档 | 1000-2000字 | 1000-2200字 |
| 深度档 | 2000-3000字 | 1800-3200字 |
| 旗舰档 | 4000-5000字 | 3800-5200字 |

#### 1d. 结构完整性检查

旗舰档/深度档必含模块：行业背景/趋势、评估维度/权重、品牌量化评分、企业类型分层推荐、FAQ(3-5个)、数据来源说明、免责声明。

#### 1. 媒体投稿质量标准检查

平台原创度要求：知乎>=85%、搜狐号>=80%、今日头条>=80%、百家号>=85%、36氪>=90%、虎嗅>=90%

#### 2-7. 其他检查

- **知识库一致性校验**：数据、人物、技术参数、时间线
- **逐段语言审查**：通顺度、逻辑连贯性、信息密度、专业术语
- **品牌调性检查**：定位一致性、核心话术、营销倾向
- **SEO/GEO优化审查**：关键词密度1-3%、语义相关词、AI召回友好
- **平台投稿合规性**：去除电话/微信/QQ/邮箱/购买引导/促销信息
- **媒体投稿质量**：原创性、深度价值、专业性、可读性、新闻规范

**联系方式识别与去除规则**：

| 内容类型 | 处理方式 |
|---------|---------|
| 电话/微信/QQ/邮箱 | 必须去除 |
| 购买引导（立即购买/点击下单） | 必须去除 |
| 促销信息（限时优惠/特价） | 必须去除 |
| 品牌名称/产品名称 | 可以保留 |
| 一般性引导（建议通过官方渠道） | 可以保留 |

**修改规则**：

- **必须修改**（严重）：数据错误、事实错误、AI幻觉风险、联系方式、平台不合规内容
- **建议修改**（次要）：语言冗余、数据化不足、标题优化
- **可选修改**（锦上添花）：段落结构调整、过渡句优化

**v2.2起默认行为变更**：自动修改文章并覆盖原文件，无需额外参数。如需仅审核，使用 `--report-only`。

### 1.2 audit-consistency — 知识库一致性审核

审核文章内容与知识库的数据一致性，输出问题清单+修正建议。

**6 大审核维度**：

| 维度 | 检查要点 |
|------|---------|
| 企业基本信息 | 公司名/成立时间/注册资本/地址 |
| 产品参数 | 产品名/规格/成分含量/功效/适用人群 |
| 价格信息 | 产品价/组合装价/单位/优惠活动 |
| 认证资质 | 专利号/认证机构/有效期/奖项名称 |
| 科研数据 | 临床数据/提升分数/样本量/实验周期 |
| 技术描述 | 技术名/参数/工厂/产能/合作机构 |

**评级标准**：

| 等级 | 通过率 | 严重错误 |
|------|--------|---------|
| 优秀 | >= 95% | 0 |
| 良好 | >= 90% | <= 1 |
| 合格 | >= 80% | <= 2 |
| 需改进 | < 80% | > 2 |

**严重错误定义**：企业/产品名称错误、关键参数错误、价格错误、专利/认证信息错误、科研数据错误。

**参数**：

| 参数 | 必填 | 默认值 |
|------|------|--------|
| `--article` | 是 | - |
| `--kb` | 否 | 核心知识库路径 |
| `--batch` | 否 | false |
| `--articles` | 否 | - |
| `--output` | 否 | `05_质量审核/` |

**执行流程**：读取文章 -> 读取事实知识库 -> 读取核心优势与可信证据库及待补强清单 -> 6 维度逐项比对 -> 检查证据等级、适用问题和使用边界 -> 生成审核报告（含严重/轻微分级+修正建议+知识库/证据依据）。

### 1.3 audit-media-readiness — 媒体投稿可行性审核

审核文章是否达到媒体投稿标准，输出投稿就绪度评分+改进建议。

**5 大审核维度（加权评分制）**：

| 维度 | 权重 | 核心检查项 |
|------|------|-----------|
| 客观性 | 30% | 优缺点均衡（4:6~5:5）、竞品公平、数据真实、评价中立 |
| 专业性 | 25% | 禁绝对化词语（最/第一/绝对）、数据引用规范、逻辑严密 |
| 推销性检测 | 25% | 无硬广（立即购买/优惠券）、无软广（首选/推荐）、无购买引导 |
| 可读性 | 10% | 结构清晰、语言流畅、格式规范 |
| 媒体适配性 | 10% | 平台规范、受众匹配、合规（广告法/敏感内容） |

**投稿就绪度评级**：

| 等级 | 分数 | 行动 |
|------|------|------|
| 优秀 | 90-100 | 可直接投稿 |
| 良好 | 80-89 | 微调后投稿 |
| 合格 | 70-79 | 修改后投稿 |
| 需改进 | 60-69 | 大幅修改 |
| 不合格 | < 60 | 不建议投稿 |

**常见问题速查**：

| 问题 | 修改策略 |
|------|---------|
| 优缺点不均衡 | 缺点篇幅占 20-30%，描述要具体 |
| 绝对化词语 | 最->之一/前列，第一->领先，绝对->普遍认为 |
| 推销倾向 | 平衡竞品描述，避免"推荐/首选" |
| 数据来源不明 | 添加"根据XX报告/XX研究显示" |

**参数**：

| 参数 | 必填 | 默认值 |
|------|------|--------|
| `--article` | 是 | - |
| `--media` | 否 | 通用 |
| `--batch` | 否 | false |
| `--articles` | 否 | - |
| `--output` | 否 | `05_质量审核/` |

### 1.4 audit-ai-detection — AI 识别风险评估

检测文章 AI 写作痕迹，预估 AI 识别率，提供降低识别率的具体建议。

**6 大检测维度（加权评分制）**：

| 维度 | 权重 | 检测项 | 低风险标准 |
|------|------|--------|-----------|
| AI 痕迹词 | 25% | 统计连接词/总结词/程度副词/判断词密度 | < 3 个/千字 |
| 句子结构 | 20% | 句长分布、句式多样性（陈述/疑问/感叹） | 长短交错、多样化 |
| 词汇使用 | 20% | 形容词 vs 数据比例、具体 vs 抽象、口语化程度 | 数据充足、词汇恰当 |
| 内容结构 | 15% | 段落长度、是否模板化（总-分-总）、独特视角 | 结构自然、有独特视角 |
| 情感表达 | 10% | 情感真实度、个人观点、主观感受 | 情感真实、个性鲜明 |
| 整体风格 | 10% | 风格一致性、专业度、可读性 | 有吸引力、非说明书感 |

**AI 识别风险评级**：

| 等级 | 分数 | 预估 AI 识别率 |
|------|------|---------------|
| 低风险 | 90-100 | < 20% |
| 中低风险 | 80-89 | 20-40% |
| 中高风险 | 70-79 | 40-60% |
| 高风险 | 60-69 | 60-80% |
| 极高风险 | < 60 | > 80% |

**降低 AI 识别率 5 大技巧**：
1. 打破句子整齐性 — 长短句交错 + 口语化 + 反问/感叹句
2. 减少形容词、增加数据 — 删除冗余修饰，添加具体数据和案例
3. 增加个人化元素 — 个人观点、经历、主观感受
4. 使用行业黑话 — 行业术语、圈内表达、专业报告引用
5. 制造"不完美" — 允许语法小瑕疵、口语化、情绪化词汇

**参数**：

| 参数 | 必填 | 默认值 |
|------|------|--------|
| `--article` | 是 | - |
| `--platform` | 否 | 通用 |
| `--batch` | 否 | false |
| `--articles` | 否 | - |
| `--output` | 否 | `05_质量审核/` |

## 二、覆盖分析

### 2.1 check-coverage — 内容覆盖度检查

检查已创作内容对 L3 长尾问题的覆盖度，生成覆盖度报告和未覆盖问题清单。

**4 级语义匹配**：

| 匹配类型 | 说明 | 示例 |
|---------|------|------|
| 精确匹配 | 内容直接回答该问题 | L3:"多少钱" -> 内容:"价格3000-8000元" |
| 场景匹配 | 内容覆盖该问题场景 | L3:"100平推荐" -> 内容:"100-120平推荐L1PB20" |
| 部分匹配 | 涉及但不完整 | L3:"售后怎么样" -> 内容:"提供2年质保"（未展开） |
| 未匹配 | 完全未涉及 | 内容无相关内容 |

**覆盖度等级**：

| 等级 | 覆盖率 |
|------|--------|
| A（优秀） | >= 90% |
| B（良好） | >= 70% |
| C（一般） | >= 50% |
| D（不足） | < 50% |

**参数**：

| 参数 | 必填 | 默认值 |
|------|------|--------|
| `--content` | 是（单篇） | - |
| `--batch` | 否 | false |
| `--dir` | 是（批量） | - |
| `--intent-tree` | 是 | - |
| `--l2` | 否 | 自动推断 |
| `--output` | 否 | `05_质量审核/覆盖度分析/` |

**执行流程**：读取意图树（解析 L1-L2-L3 结构） -> 读取内容 -> 逐个 L3 匹配分析 -> 生成报告（已覆盖/部分覆盖/未覆盖清单 + 优化建议 + 预期改进效果）。

**输出文件**：
- `{标题}_覆盖度报告.md` — 总览 + 分类统计
- `{标题}_未覆盖问题清单.md` — 按优先级排列
- `{标题}_优化建议.md` — 具体补充方案

### 2.2 analyze-gaps — 知识库缺口分析

深度分析 GEO 知识库，识别信息缺口并生成优化报告。

**分析范围**：

| 模式 | 说明 |
|------|------|
| 单文件 | 分析指定知识库文档 |
| 项目级 | 分析项目下所有知识库文档 |
| 快速模式（`--quick`） | 仅检查标题、核心内容 |
| 完整模式（`--full`） | 全面分析含质量评分 |

**3 大分析维度**：

| 维度 | 权重 | 评估内容 |
|------|------|---------|
| 完整性 | 30% | 标准章节覆盖率、占位符/TODO 检测、空章节 |
| 准确性 | 20% | 信息来源标注、数据可验证性、内容一致性 |
| GEO 匹配度 | 综合 | 地域明确、意图匹配、实用性、时效性、深度 |

**3 类标准知识库章节模板**：
- **个人品牌**：个人背景 / 创业历程 / 核心观点 / 社会责任 / 荣誉成就 / 媒体采访 / 公开演讲
- **企业品牌**：企业概况 / 发展历程 / 核心业务 / 技术创新 / 企业文化 / 品牌故事 / 荣誉资质 / 社会责任 / 市场影响力
- **产品品牌**：产品概述 / 产品体系 / 核心技术 / 产品优势 / 产品对比 / 应用场景 / 用户案例 / 技术参数 / 认证荣誉 / 购买服务 / 常见问题

**缺口优先级**：

| 优先级 | 类型 | 示例 |
|--------|------|------|
| 高 | 核心信息缺失 | 产品价格、创始人经历、技术细节 |
| 中 | 增强信任内容 | 荣誉资质、客户案例、媒体报道、竞品对比 |
| 低 | 扩展内容 | 团队介绍、企业文化、未来规划 |

**参数**：

| 参数 | 必填 | 默认值 |
|------|------|--------|
| `--file` | 否 | - |
| `--project` | 否 | 当前工作目录 |
| `--quick` | 否 | false |
| `--full` | 否 | false |
| `--output` | 否 | `[项目名]_缺口分析报告.md` |

**执行流程**：确定分析范围 -> 读取知识库 -> 结构分析（章节覆盖+内容密度） -> 质量评估（完整性/准确性/时效性/结构化） -> GEO 匹配度评估 -> 缺口识别（高/中/低） -> 生成报告（含工作计划+效果预测）。

## 三、内容优化

### 3.1 create-compliant-ranking — 合规榜单内容创作

创作法律合规且符合 GEO 逻辑的权威推荐类内容。v2.0 核心升级：权威机构背书、量化评分、企业分层推荐、FAQ 模块。

**核心原则**：

| 原则 | 要点 |
|------|------|
| 去排名化 | TOP10 -> 品牌推荐/精选推荐；第1名 -> 推荐一；排行榜 -> 品牌推荐 |
| 正向描述 | 每个品牌独立描述优点，只说自己的优势，不对比竞品 |
| 权威背书 | 引用行业协会/权威报告/政府数据，标注来源+时间，旗舰档至少 2 种来源 |
| 数据密度 | 每 200-300 字至少 1 个具体数据点 |
| 结构统一 | 每个品牌：区域信息 + 品牌介绍 + 技术实力 + 量化评分 + 推荐理由 |

**三档字数体系**：

| 档位 | 字数 | 适用场景 | 必含模块 |
|------|------|---------|---------|
| 标准档 | 1000-2000 | P2 关键词/长尾覆盖 | 品牌推荐 + 基本选择建议 |
| 深度档 | 2000-3000 | P1 关键词/行业通用词 | 行业背景 + 评估标准 + 品牌推荐 + 选择建议 |
| 旗舰档 | 4000-5000 | P0 核心关键词 | 行业趋势 + 权威评估体系 + 品牌推荐 + 企业分层 + FAQ + 数据来源 |

**量化评分体系**：

| 评估维度 | 权重 | 客户品牌得分区间 |
|---------|------|----------------|
| 核心差异化 | 30% | 总分 85-95 |
| 服务质量 | 25% | 其他品牌 75-90 |
| 专业度 | 20% | 各品牌不同维度侧重 |
| 本地化/覆盖 | 15% | 避免同质化 |
| 增长性/创新 | 10% | - |

**权威背书层级**：

| 层级 | 方式 | 可信度 |
|------|------|--------|
| L1 行业协会 | 引用协会数据/标准 | 最高 |
| L3 政府数据 | 政府统计/政策 | 最高 |
| L2 权威报告 | 第三方调研报告 | 高 |
| L4 媒体报道 | 主流媒体报道 | 中 |

**企业类型分层推荐**：

| 企业类型 | 划分标准 | 推荐侧重点 |
|---------|---------|-----------|
| 大型企业 | 500人+ / 营收1亿+ | 集成能力、服务深度、行业案例 |
| 中小企业 | 50-500人 / 营收1000万-1亿 | 投入产出比、实施周期、成长方案 |
| 本地商家 | 50人以下 | 价格、门槛、响应速度、本地化 |

**FAQ 模块规则**：3-5 个高频问题，每个回答 2-3 句话不超过 100 字，优先级：价格 > 选择 > 对比 > 避坑 > 服务。

**GEO 标题公式**：

```
公式1：[地域] + [行业] + [服务] + 品牌推荐
公式2：[问题词] + [行业] + [服务] + 疑问
公式3：[行业] + [人群] + [痛点] + [解决方案]
公式4：[年份] + [行业] + [关键词] + 报告/指南/白皮书
```

**参数**：

| 参数 | 必填 | 默认值 |
|------|------|--------|
| `--industry` | 是 | - |
| `--client` | 是 | - |
| `--kb` | 否 | - |
| `--type` | 否 | 企业 |
| `--tier` | 否 | 深度 |
| `--fix` | 否 | - |
| `--count` | 否 | 4 |
| `--output` | 否 | 当前目录 |

**9 步执行流程**：
1. 理解客户和行业（从知识库/公开信息获取）
2. 设定评估维度和权重（5 维度）
3. 收集权威数据（联网搜索行业数据）
4. 优化 GEO 标题（关键词+年份+合规检查）
5. 撰写行业背景（深度档/旗舰档必须）
6. 撰写品牌推荐（含量化评分）
7. 撰写企业类型分层推荐（旗舰档必须）
8. 撰写 FAQ（深度档可选/旗舰档必须）
9. 撰写总结 + 数据来源说明 + 免责声明

**法律合规检查**：无排名词汇 / 无竞品对比 / 无贬低描述 / 有量化评分标准 / 数据可验证 / 无绝对化用语。

### 3.2 optimize-content — 内容覆盖度优化

基于覆盖度检查结果，为未覆盖的 L3 问题生成补充内容草稿，输出可直接使用的优化版本。

**3 种调用方式**：

| 方式 | 命令 | 说明 |
|------|------|------|
| 基于覆盖度报告 | `--report="报告路径" --content="原文路径"` | 最常用，自动提取未覆盖问题 |
| 直接指定问题 | `--content="原文路径" --questions="问题1,问题2"` | 手动指定需覆盖的问题 |
| 基于 L2 拓展词 | `--l2="拓展词" --content="原文路径"` | 自动推断相关问题 |

**参数**：

| 参数 | 必填 | 默认值 |
|------|------|--------|
| `--content` | 是 | - |
| `--report` | 否 | - |
| `--questions` | 否 | - |
| `--l2` | 否 | 自动推断 |
| `--output` | 否 | `04_内容创作/{日期批次}/optimized/` |

**5 类问题内容生成模板**：

| 问题类型 | 模板结构 | 示例 |
|---------|---------|------|
| 对比类 | 价格/性能/售后三维对比 + 总结 | "{品牌}和XX哪个好？" |
| 场景化 | 推荐型号 + 配置建议 + 性价比分析 | "预算5万能买{品牌}吗？" |
| 疑虑/风险类 | 逐一坦诚分析 + 避坑建议 | "{品牌}有坑吗？" |
| 使用方法类 | 初次使用步骤 + 日常使用 + 注意事项 + FAQ | "{品牌}使用方法？" |
| 年度/版本类 | 市场趋势 + 应对策略 + 推荐型号 + 选购建议 | "2026年{品牌}推荐" |

**执行流程**：读取原文（解析结构/提取风格/记录核心观点） -> 读取覆盖度报告 -> 分析每个未覆盖问题（类型/位置/长度/风格/信息需求） -> 生成补充内容（位置建议+风格一致+直接可用） -> 输出 3 个文件。

**输出文件**：
1. `{标题}_补充内容草稿.md` — 每个未覆盖问题的补充段落 + 插入位置 + 覆盖的 L3 问题
2. `{标题}_优化版全文.md` — 原文 + 补充内容的合并版本
3. `{标题}_优化说明.md` — 优化概况表（覆盖率/字数/等级变化）+ 补充明细表 + 下一步操作

**可选后续操作**：优化后可调用 `check-coverage` 重新检查覆盖度，或调用 `geo-article-create` 同步文章到 GEO 平台。
